## 第1章 计算机网络体系结构

### 1.1 自查清单

- [ ] 计算机网络定义与组成（硬件/软件/协议）；网络的分类（按范围：WAN/MAN/LAN/PAN；按使用者；按交换技术：电路/报文/分组交换）
- [ ] **电路交换**（建立连接→通话→释放，独占资源、实时性强、线路利用率低）vs **报文交换**（存储转发整个报文）vs **分组交换**（拆分为分组、存储转发、时延小利用率高）——能给场景选交换方式、会算三种方式的时延
- [ ] 性能指标会算：速率与带宽、**四种时延**（发送时延 $= \dfrac{\text{分组长度}}{\text{带宽}}$、传播时延 $= \dfrac{\text{信道长度}}{\text{传播速率}}$、处理、排队）、时延带宽积（$= \text{传播时延} \times \text{带宽}$，"以比特为单位的链路长度"）、RTT、利用率、丢包率
- [ ] 分层结构的好处（各层独立/灵活/易实现维护/促进标准化）；**协议三要素：语法、语义、同步（时序）**
- [ ] OSI 七层与 TCP/IP 四层、**教学五层**模型的对应；**五层模型每层的功能、传输单位（PDU）、典型协议/设备**：物理层（比特、集线器/中继器）、链路层（帧、交换机/网桥）、网络层（分组/IP、路由器）、传输层（报文段，TCP/UDP）、应用层（报文）
- [ ] 各层典型协议归类：应用层 HTTP/FTP/SMTP/DNS/DHCP；传输层 TCP/UDP；网络层 IP/ICMP/ARP（教材口径 ARP 归网络层）；链路层 Ethernet/PPP
- [ ] 通信方式：单工/半双工/全双工；同步传输 vs 异步传输

- [ ] **OSI 七层各层功能与对应 PDU / 设备（强化）**：物理层（比特；中继器/集线器）→ 链路层（帧；网桥/交换机）→ 网络层（分组/数据报；路由器）→ 传输层（报文段；网关）→ 会话层（会话管理与同步）→ 表示层（格式转换、加密、压缩）→ 应用层（报文）；会话层与表示层在五层模型并入应用层

### 1.2 易错点 · 高频陷阱

- 发送时延与传播时延别混：**发送时延与带宽、分组长度有关；传播时延只与距离、介质有关**，与带宽无关。
- "带宽 1Mb/s"不是 1MB/s（字节 ×8）；存储单位 GB 与传输单位 Gb 区分。
- 电路交换在**数据量大、实时性强、连续传送**时占优；突发式数据适合分组交换。
- OSI 没有被市场接受（复杂、先于实现），TCP/IP 赢在实现先行——简答题要点。
- 会话层、表示层功能（会话管理/同步；数据压缩加密格式转换）——五层模型里归入应用层。
- 时延带宽积单位是 bit；"第一个比特到达接收方时链路上已塞满多少比特"就是这个积。

### 1.3 自测问答

**Q1. 100MB 文件经 1Gb/s 链路（忽略处理排队时延，传播时延 10ms）用分组交换（分组 1000B）发送，求最后一个小分组的到达时间（从第一个比特发出算起）。**

<details><summary>▶ 展开答案</summary>

总比特 $= 100 \times 2^{20} \times 8 \approx 8.39 \times 10^8$ bit；发送时延 $\approx 0.839\text{s}$。第一个分组发送完即可出发（1000B → 8μs），传播 10ms 后到达；后续分组流水到达。
到达时间 $\approx$ 第一个分组的发送+传播 + 剩余数据的发送时延 $= 8\mu\text{s} + 10\text{ms} + (0.839\text{s} - 8\mu\text{s}) \approx \textbf{0.849s}$。
（本质：分组交换总时间 $\approx$ 总发送时延 + 一个传播时延。）
</details>

**Q2. 链路带宽 10Mb/s，往返传播时延 20ms。发送方连续发送，问第一个比特到达对端时链路上最多可容纳多少数据（时延带宽积口径）？**

<details><summary>▶ 展开答案</summary>

单程传播 10ms × 10Mb/s：$10\text{ms} \times 10\text{Mb/s} = 10^5\text{bit} \approx \textbf{12.5KB}$（"链路容纳"按单程传播时延计算；若按往返 20ms 口径则为 25KB）。
</details>

## 第2章 物理层

### 2.1 自查清单

- [ ] 物理层任务：确定与传输媒体接口的特性（机械/电气/功能/规程）；**传数据不传差错控制**（链路层才管）
- [ ] 基本概念：码元（携带 1 个或多个比特）、波特率（码元/秒）与比特率（bit/s）；$\text{比特率} = \text{波特率} \times \log_2 V$（$V$ 为码元离散状态数）
- [ ] **奈奎斯特定理：$C = 2W\log_2 V$（无噪声）**；**香农定理：$C = W\log_2(1 + S/N)$（有噪声，$S/N$ 为信噪比线性值）**；$dB = 10\lg(S/N)$——两种题型都会算，能判断"带宽或电平数翻倍哪个更有效"
- [ ] 编码：不归零（NRZ，无自同步）、归零（RZ）、**曼彻斯特**（每比特中间跳变，数据率是码率一半；以太网 10Mb/s 对应 20M 波特）、**差分曼彻斯特**（看起始有无跳变）、4B/5B
- [ ] 调制：ASK/FSK/PSK/QAM（幅相联合，QAM-16 每码元 $\log_2 16 = 4$ bit）——会给波特率算比特率
- [ ] 传输媒体：导向（双绞线/同轴/光纤——多模 vs 单模）与非导向（无线电波/微波/红外）；各介质的典型场景
- [ ] 物理层设备：**中继器**（再生信号，5-4-3 规则）与**集线器 Hub**（多口中继器；物理层；共享带宽、一个冲突域、半双工广播）

- [ ] **物理层接口的四特性**：**机械特性**（接口形状、引线数目、引脚数量与排列）、**电气特性**（电压范围、阻抗匹配、传输速率与距离限制）、**功能特性**（某条线上某一电平表示何种意义、各信号线的用途）、**规程特性/过程特性**（各线路的工作规程与时序，即事件出现顺序）——会给一例判"属于哪种特性"
- [ ] **数据报与虚电路（分组交换的两种方式，也是网络层向传输层提供的两种服务）**：**数据报**（无连接，每个分组**独立选路**、路由器逐跳决策，携带完整目的地址，可能乱序/丢失/重复，差错控制交给传输层；健壮灵活，突发性数据首选）vs **虚电路**（面向连接，先建立虚电路再传数据、所有分组**沿同一路径**、分组只需携带**虚电路号**、按序到达，差错控制由网络层负责；节点失效影响大、有建立/释放开销，适合长时间大量的持续通信）；**两者都属于分组交换**（传输单位都是分组，区别在是否建连，与电路交换的"独占线路"不同）；因特网采用数据报服务

### 2.2 易错点 · 高频陷阱

- 奈氏公式**没有噪声项**、限制的是波特率上限；香农公式**与 V 无关**、给出的是极限比特率——两者结论"提高电平数"与"提高信噪比"各管一头。
- 曼彻斯特编码波特率是数据率的两倍（每比特两个信号变化）；以太网 100Mb/s 用 4B/5B+NRZI 才不需要 200M 波特。
- dB 换算：30dB → $S/N = 10^{30/10} = 1000$；3dB ≈ 2 倍；公式 $C = W\log_2(1+S/N)$ 先把 dB 转线性再代。
- 集线器**不隔离冲突域**也不能全双工；"Hub 上的主机同时通信仍冲突"。
- 数据报/虚电路的适用场景别写反：**长时间大量持续通信、要求按序 → 虚电路；突发、短事务、要求健壮 → 数据报**。
- 光纤多模用发光二极管、便宜、短距；单模用激光、贵、长距——方向别反。
- 数据报与虚电路都属**分组交换**（"虚电路 = 电路交换"错）；区别的核心是**是否建立连接、分组是否携带虚电路号**：虚电路只带虚电路号且按序到达，数据报带完整目的地址且可能乱序。
- 教材口径：**数据报/虚电路是网络层向传输层提供的两种服务**（不由物理层/链路层决定）；"虚电路是无连接服务"是典型错项。

### 2.3 自测问答

**Q1. 信道带宽 3kHz，信噪比 30dB，用 QAM-16 调制。奈氏极限和香农极限各是多少？实际最大速率取多少？**

<details><summary>▶ 展开答案</summary>

奈氏：$2 \times 3000 \times \log_2 16 = 24000 = \textbf{24kb/s}$；$S/N = 10^{30/10} = 1000$，香农：$3000 \times \log_2(1001) \approx \textbf{29.9kb/s}$。
实际取两者较小值 = **24kb/s**。
</details>

**Q2. 若在上题中把带宽加倍到 6kHz，极限速率变为多少？与"电平数加倍到 32"相比哪个提升大？**

<details><summary>▶ 展开答案</summary>

带宽加倍：$2 \times 6000 \times 4 = 48\text{kb/s}$；电平加倍（$V=32$）：$2 \times 3000 \times 5 = 30\text{kb/s}$。**带宽加倍提升更大**（×2 vs ×5/4）——这就是"扩展带宽优于增加电平"的经典结论。
</details>

**Q3. 数据报服务与虚电路服务各有什么特点？为什么因特网采用数据报服务？**

<details><summary>▶ 展开答案</summary>

虚电路：**面向连接**，通信前建立虚电路，分组**只携带虚电路号**、沿同一路径**按序到达**，差错控制由**网络层**负责，服务质量的保证较好；代价是建立/释放开销，**节点失效会使虚电路中断**，可靠性依赖网络。
数据报：**无连接**，每个分组**独立选路**、携带完整目的地址，可能乱序/丢失，差错控制由**传输层**（TCP）负责。
因特网选数据报，是因为它灵活健壮、能自动适应网络故障、无需建立连接的开销，适合计算机之间的突发性通信；**两者都属于分组交换**（不是电路交换）。
</details>

## 第3章 数据链路层

### 3.1 自查清单

- [ ] 链路层功能：组帧、差错控制、流量控制、传输管理；（无连接/有确认等服务等概念）
- [ ] **四种组帧**：字符计数法（首字节计长度，出错连锁）、字节填充（SOH/EOT + 转义字符 ESC）、**比特填充（HDLC：5 个连续 1 后插 0）**、物理编码违例（以太网）
- [ ] 差错控制：检错（奇偶校验、**CRC 循环冗余校验**——模 2 除法会手算 FCS）与纠错（**海明码：$2^r \ge m + r + 1$**，能纠 1 位错）；CRC 只检错不纠错
- [ ] 流量控制与可靠传输（停止-等待、GBN、SR）：**停止-等待：信道利用率 $U = \dfrac{T_D}{T_D + RTT + T_A}$**，会算长肥管道的利用率
- [ ] **GBN：发送窗口 $\le 2^n - 1$**；出错后重传全部已发送未确认帧；累计确认；接收窗口=1
- [ ] **SR：发送窗口 = 接收窗口 $\le 2^{n-1}$**；逐帧确认、选择重传；缓存乱序帧
- [ ] 介质访问控制：信道划分（FDM/TDM/**STDM 统计时分**/WDM/**CDM 码分多址——正交码片内积为 0，会算 A+(B⊕C) 的合并信号分离**）、随机接入（纯 ALOHA 与**时隙 ALOHA（效率翻倍）**、1-坚持/非坚持/p-坚持 CSMA）、**CSMA/CD**（重点）
- [ ] CSMA/CD 全流程：边发边听、**争用期 $2\tau$ 内无冲突即成功**；**最短帧长 $= 2\tau \times \text{数据率}$**（10Mb/s、$\tau = 25.6\mu\text{s}$ → 512bit=64B）；小于则补填充；**截断二进制指数退避**（第 $i$ 次冲突 $r \in [0, 2^{\min(i,10)}-1]$，16 次放弃）；适合有线共享、**不能用于无线**（无法边发边检测冲突——无线用 CSMA/CA）
- [ ] CSMA/CA（802.11）：IFS、随机退避、ACK 确认、RTS/CTS 信道预约与隐藏站问题（概念级）
- [ ] 局域网：IEEE 802 体系（LLC/MAC 子层）；**以太网 V2 帧格式**：目的 MAC 6B + 源 MAC 6B + 类型 2B + 数据 46-1500B + FCS 4B；MAC 地址 48 位；**无连接、不可靠（无确认重传，纠错交给高层）**
- [ ] 10BASE-T（双绞线、星形、曼彻斯特）、适配器（网卡）功能；**网卡收到帧的过滤规则（单播/广播/多播/混杂模式）**
- [ ] **交换机（多端口网桥）**：自学习（源 MAC 登记 + 转发表老化）、转发/过滤规则（已知单播直接转发、未知泛洪、广播泛洪）；**每个端口独立冲突域、可全双工、独享带宽**——会做"主机对发送帧后转发表与转发行为"的分析题
- [ ] 冲突域 vs 广播域：**集线器不隔离两者；交换机隔离冲突域不隔离广播域；路由器两者都隔离**；VLAN（802.1Q 插 4 字节标签）隔离广播域
- [ ] 高速以太网：100BASE-T（4B/5B）、千兆（载波延伸）、万兆（光纤、全双工无 CSMA/CD）概述
- [ ] 广域网 PPP：帧格式（7E 首尾、地址固定 FF、控制 03、协议字段、FCS）、**字节填充**、不需要的功能（无纠错重传/无流量控制/不支持多点）、零比特填充用在同步（SONET）场合、LCP/NCP 协商
- [ ] **令牌传递协议（轮询访问）**：令牌是特殊短控制帧，各站组成**逻辑环**，**只有持有令牌的站才能发数据**，发完或超时即释放——**无冲突、轮流占用、各站公平**；**IEEE 802.5 令牌环网**、**IEEE 802.4 令牌总线**（物理总线 + 逻辑环，新站加入需执行"请求后继"等初始化）；先传**令牌帧**（空闲令牌），持有者把它改成数据帧发出（早期令牌释放：帧发完即产生新令牌；延迟释放：等帧头返回）；**令牌持有时间 THT** 限制单站占用，超时即释放；支持**优先级预约机制**（预约位/Priority/Reservation）；**监控站**（802.5 有且仅有一个主动监控站）检测**令牌丢失/重复令牌**与帧格式错误，清除环上残留数据并生成新令牌，FDDI 另用双环冗余；**与 CSMA/CD 对比**：令牌环**延迟确定、最坏等待可精确计算**（前面各站的令牌与帧时间之和）、重负载下信道利用率高、适合硬实时；缺点是低负载时开销大于 CSMA/CD、实现复杂、经典令牌环为半双工、不适应无线

- [ ] **流量控制与滑动窗口机制（总括）**：**发送窗口** = 已发送未确认帧的上限，**接收窗口** = 可接收（含缓存乱序帧）的范围；窗口按收到的确认**向前滑动**；**窗口与序号位数的关系**：序号 $n$ 位时 GBN 发送窗口 $\le 2^n - 1$、SR 发送窗口 = 接收窗口 $\le 2^{n-1}$（窗口过大将无法区分新旧帧）；确认分**累积确认**（GBN）与逐帧/选择确认（SR），停止-等待是窗口为 1 的特例

### 3.2 易错点 · 高频陷阱

- CRC 计算在**信息位后补 $r$ 个 0** 再除生成多项式（多项式位数 = 最高次幂+1）；余数不足 $r$ 位**高位补 0**。
- 比特填充是"发端 5 个 1 后插 0、收端删除"；PPP 异步链路用**字节填充**、同步用**零比特填充**——两种填充别混。
- GBN/SR 窗口公式取决于**序号字段位数 $n$**：GBN $W \le 2^n - 1$，SR $W \le 2^{n-1}$——题给 $n=3$ 时 GBN 最大 7、SR 最大 4。
- 停等协议利用率公式里 $T_A$ 常被忽略（可忽略但写明）；数据帧与确认帧的发送时延都要算时别漏。
- CSMA/CD 中"检测到冲突就停止发送 + 发强化干扰信号（Jam，32/48bit）+ 指数退避"——退避后从**争用期**重新计时。
- 最短帧长公式 $L_{\min} = 2\tau \times \text{数据率}$：64B 是 10Mb/s 的结论，速率变化最短帧长要重算（100Mb/s 时争用期缩小 10 倍或帧长加大）。
- 交换机自学习用的是**帧的源地址**，转发决策用的是**目的地址**——分析题的核心。
- 以太网数据字段 46-1500B：不足 46B 要填充（PAD）；1500 是 MTU——IP 分组的产生原因在下一章呼应。
- 广播地址 FF-FF-FF-FF-FF-FF；多播地址 01-00-5E 开头（IP 多播映射的低 23 位）。
- 令牌环网**正常工作时不存在冲突**（轮询访问，任一瞬间环上只有一个站在发）；"令牌环存在冲突"是典型错项。
- **令牌丢失、重复令牌、帧格式错误由监控站处理**；令牌环重负载下效率高于 CSMA/CD，但**低负载下不如 CSMA/CD**。

### 3.3 自测问答

**Q1. 信息码 101001，生成多项式 $G(x) = x^3 + x^2 + 1$。求 CRC 码字。**

<details><summary>▶ 展开答案</summary>

$G(x) = x^3 + x^2 + 1$ → 除数 1101（$r=3$）。信息后补 3 个 0：101001000 ÷ 1101（模 2 除）→ 余数 **001**。发送码字 = **101001001**（接收方用同一多项式除，余数为 0 判无错）。
</details>

**Q2. 信道速率 100Mb/s，端到端往返传播时延 $2\tau = 20\mu\text{s}$。最短帧长是多少？**

<details><summary>▶ 展开答案</summary>

$L_{\min} = 2\tau \times \text{数据率} = 20 \times 10^{-6} \times 100 \times 10^6 = 2000\text{bit} = \textbf{250B}$。（10Mb/s 时才是 64B——结论随速率变化，别背死。）
</details>

**Q3. 停等协议：数据帧 1000B、速率 1Mb/s、RTT=10ms、确认帧发送忽略。信道利用率是多少？**

<details><summary>▶ 展开答案</summary>

$T_D = \dfrac{1000 \times 8}{10^6} = 8\text{ms}$；$U = \dfrac{T_D}{T_D + RTT + T_A} = \dfrac{8}{8+10+0} \approx \textbf{44\%}$。
</details>

**Q4. 交换机转发表为空。主机 A（端口 1）向主机 B（端口 3）发帧，随后 B 回帧给 A，交换机各做什么动作？**

<details><summary>▶ 展开答案</summary>

A→B：转发表无 B → 向除端口 1 外所有端口**泛洪**；同时把（A, 端口1）**自学习**进表。
B→A：表中有 A → 直接从端口 1 **转发**（不泛洪）；并把（B, 端口3）学习进表。
</details>

**Q5. 判断：①SR 接收窗口可以大于 1；②GBN 采用累计确认，收到失序帧一律丢弃。**

<details><summary>▶ 展开答案</summary>

① 正确。② 正确（GBN 接收窗口为 1，失序帧丢弃，等发送方重传——代价是重传多）。
</details>

**Q6. 令牌环网中，当所有站点都有数据要发送时，一个站点在最坏情况下等待获得令牌并发送数据帧的时间等于什么？为什么说令牌传递的访问延迟是"确定"的？令牌丢失或出现重复令牌由谁处理？**

<details><summary>▶ 展开答案</summary>

等于**所有站点传送令牌的时间与发送数据帧的时间之总和**——令牌沿**逻辑环**单向逐站传递，本站必须等前面每个站点**依次拿到令牌并把数据帧发完**。只算令牌时间会漏掉数据帧的时间，折半更是无依据。
"确定"指**最坏等待时间可以精确计算**（站点数、令牌与帧长、THT 都已知），与 CSMA/CD 靠指数退避、冲突随负载加剧的随机性相反——故重负载下效率高、适合硬实时系统。
**监控站**（IEEE 802.5 中有且仅有一个**主动监控站**）负责检测**令牌丢失、重复令牌**与帧格式错误，清除环上残留数据并生成新的空闲令牌；令牌**持有时间 THT** 限制单站占用，主机还要靠**优先级预约**机制排队。
</details>

## 第4章 网络层

### 4.1 自查清单

- [ ] 网络层功能：转发（路由器内）与路由选择（全网）；异构网络互联；SDN 概念（控制面/数据面分离，概念级）
- [ ] IPv4 分组格式：**首部 20B 固定**，版本、首部长度（×4B）、总长度（×1B）、标识/标志（DF MF）/片偏移（×8B）、**TTL（每过一路由器减 1，为 0 丢弃并向源发 ICMP 超时）**、协议字段（6=TCP 17=UDP）、**首部校验和（只校验首部、逐跳重算）**、源/目的 IP
- [ ] **IP 分片**：会算给定链路 MTU（如 1500B，减 20B 首部 = 载荷 1480B）下的分片数量、每片长度、片偏移值与 MF 位；**片偏移单位 8B、总长度单位 1B、首部长度单位 4B**——三个单位是最大考点
- [ ] IPv4 地址：A/B/C/D/E 类；点分十进制；**特殊地址**（全 0 主机号=网络地址、全 1=广播、127 环回、0.0.0.0、169.254 链路本地）
- [ ] **子网划分**：借主机位做子网位；会算子网掩码、网络地址、广播地址、可用主机数（$2^h - 2$）；会做"给定拓扑和主机数需求"的 VLSM 规划题
- [ ] **CIDR 与路由聚合**：前缀表示 a.b.c.d/n；会做最长前缀匹配的转发决策与**路由聚合**（多个前缀合并成超网）
- [ ] 路由表与分组转发：默认路由 0.0.0.0/0；直接交付 vs 间接交付；**路由器逐跳转发、只看目的 IP**
- [ ] **ARP**：IP→MAC，同网段直接解析、跨网段解析**默认网关**的 MAC；请求**广播**、应答**单播**；ARP 缓存；免费 ARP
- [ ] **DHCP**：应用层协议（**UDP**，服务器 67/客户端 68）；Discover（广播）→ Offer → Request → ACK；可重用地址、支持移动（中继代理）
- [ ] **ICMP**：差错报告（终点不可达/超时/参数问题/改变路由）与询问（回送请求/应答=ping）；**ICMP 报文封装在 IP 中**；traceroute 原理（TTL 递增）
- [ ] NAT：私网地址（10/8、172.16/12、192.168/16）；NAT 路由器改写 IP+端口（NAPT）建立映射表；**NAT 使外网无法主动访问内网**（除非配置映射）
- [ ] IPv6：**128 位**、基本首部 **40B 固定**、无校验和、只在源端分片；地址表示（冒号十六进制+零压缩）；**IPv4→IPv6 过渡：双协议栈与隧道**；IPv6 无广播（任播/多播）
- [ ] 路由协议：**RIP**（距离向量、跳数≤15、16 不可达、坏消息传得慢/计数到无穷、**UDP 520**、30s 交换）、**OSPF**（链路状态、**直接用 IP（协议号 89）**、洪泛 LSA、Dijkstra、区域划分 ABR/ASBR、收敛快）、**BGP**（路径向量、**TCP 179**、域间 AS 级、策略型）
- [ ] 内部网关协议 IGP vs 外部网关协议 EGP 的层次关系；RIP/OSPF/BGP 对比表能默写（算法、承载、交换对象、度量）
- [ ] IP 组播：D 类地址；IGMP（主机加入组）；组播 MAC 映射（01-00-5E + IP 低 23 位，**32 个 IP 对应 1 个 MAC**）；移动 IP（概念级）
- [ ] 路由器组成与功能：输入端口/交换结构/输出端口/路由选择处理机；排队丢包、分组转发流程（查表→TTL→校验和→转发）

- [ ] **移动 IP 通信过程**：**归属代理**（归属网上的路由器，维护移动站的当前位置）、**外地代理**（外地网上的路由器，为移动站提供转交地址并代收转发）、**归属地址**（永久不变，标识移动站）、**转交地址 COA**（到外地网后获得的临时地址，分外地代理 COA 与共置 COA）；过程：移动站进入外地网 → 获得 COA → 向归属代理**注册**（登记 COA）→ 通信对端发给归属地址的报文被归属代理**隧道封装**（IP-in-IP）转发到 COA → 外地代理/移动站解封装交付；**三角路由问题**：对端仍把报文发往归属网，报文绕行归属代理转发，路径变长、时延增加（优化方案是由对端直接发往 COA）

### 4.2 易错点 · 高频陷阱

- 三个"乘数"：**首部长度字段 ×4B，总长度 ×1B，片偏移 ×8B**；分片时除最后一片外每片数据量必须是 **8 的倍数**。
- 分片后的片**只有在最终目的主机才重组**（中间路由器不重组）。
- TTL 与"协议"字段：TTL 防环 + traceroute；协议字段区分上层是 TCP(6)/UDP(17)/ICMP(1)/OSPF(89)。
- 127.0.0.1 是环回不进网络；广播地址主机位全 1；网络地址主机位全 0——写地址规划题先排掉这两类。
- ARP 请求是广播帧（目的 MAC 全 F），应答是单播；**ARP 属于网络层协议但直接封装在以太网帧中**（教材口径）。
- RIP 用 UDP（应用层实现的路由协议）、OSPF 直接用 IP、BGP 用 TCP——"哪个用 TCP/UDP/IP"是经典选择题。
- RIP 的"距离 16 不可达"与 30s 周期交换；OSPF 的 hello 间隔 10s、死亡间隔 40s（数字按教材记）。
- DHCP 四步里 **Discover/Request 是广播**（还没拿到地址）；Offer/ACK 按教材口径表述。
- IPv6 **没有首部校验和**（减少路由器处理）；扩展首部链式指向下一首部类型。
- 组播地址映射 MAC 只取 IP 低 23 位，所以 $32:1$ 冲突——"为什么组播 MAC 不唯一"的答案。
- 路由聚合取**共同前缀**；最长前缀匹配优先于默认路由。

### 4.3 自测问答

**Q1. 主机 IP 192.168.10.70/26，求所在子网的网络地址、广播地址、可用主机数与掩码。**

<details><summary>▶ 展开答案</summary>

/26 → 掩码 255.255.255.**192**；块大小 $256-192=64$，子网边界 0,64,128,192 → 70 落在 64-127。
网络地址 **192.168.10.64**，广播地址 **192.168.10.127**，可用主机 $2^6 - 2 = \textbf{62}$。
</details>

**Q2. 总长 3820B 的 IP 分组经 MTU=1500B 的链路，要分几片？各片数据长度、片偏移（单位 8B）与 MF 值？**

<details><summary>▶ 展开答案</summary>

每片最多装 $1500-20 = 1480\text{B}$ 数据（$3820-20 = 3800\text{B}$ 有效载荷）。$3800 = 1480+1480+840$ → **3 片**。
片 1：数据 1480B，偏移 $0/8=0$，MF=1；片 2：数据 1480B，偏移 $1480/8=\textbf{185}$，MF=1；片 3：数据 840B，偏移 $2960/8=\textbf{370}$，MF=0。
</details>

**Q3. 将 192.168.4.0/24 与 192.168.5.0/24 聚合成一条路由。**

第 3 字节 $4 = 00000100$、$5 = 00000101$，共同前缀 7 位 → 聚合为 **192.168.4.0/23**。
</details>

## 第5章 传输层

### 5.1 自查清单

- [ ] 传输层功能：进程到进程（端到端）的逻辑通信、复用与分用、差错检测；**端口 0-65535**：熟知 0-1023、登记 1024-49151、短暂 49152-65535；套接字 = IP:端口
- [ ] **UDP**：无连接、尽最大努力、面向报文（保留边界）、无拥塞控制、首部 **8B**（源/目的端口、长度、校验和）；校验和含**伪首部**（IP 层信息参与计算）；适用：实时音视频、DNS、一次性短事务
- [ ] **TCP**：面向连接、可靠、面向字节流、全双工、点对点；首部 20-60B：**序号/确认号（确认号 = 期望收到的下一字节序号）、数据偏移（×4B）、标志位（SYN ACK FIN RST PSH URG）**、窗口（流量控制）、校验和（含伪首部）
- [ ] TCP 连接建立三次握手：SYN=1,seq=x → SYN=1,ACK=1,seq=y,ack=x+1 → ACK=1,seq=x+1,ack=y+1；**为什么三次**（防止失效的连接请求突然到达造成资源浪费/双方收发能力确认）；SYN 消耗一个序号
- [ ] 连接释放四次挥手：FIN → ACK → FIN → ACK；**主动方最后进入 TIME-WAIT 等 2MSL**（保证最后 ACK 到达、旧报文消亡）；半关闭状态
- [ ] 可靠传输：序号 + 确认 + 重传；**超时重传的 RTO 由 RTT 加权平均 + RTT 偏差**估计（Karn 算法：重传段不采样）
- [ ] 连续 ARQ/滑动窗口：发送窗口 $\le \min(\text{rwnd},\ \text{cwnd})$；**累积确认**；SACK 概念级
- [ ] 流量控制：接收方用 rwnd 通告；**零窗口死锁 → 持续计时器 + 零窗口探测报文**
- [ ] **拥塞控制四大算法**（重点，会给场景画 cwnd 曲线或算数值）：慢开始（cwnd 从 1 起**每 RTT 翻倍**）、拥塞避免（$\ge \text{ssthresh}$ 后每 RTT **+1**）、**超时：$\text{ssthresh} = \text{cwnd}/2$，cwnd=1 重新慢开始**、快重传（3 个冗余 ACK 即重传）+ 快恢复（**$\text{ssthresh} = \text{cwnd}/2$，cwnd=新 ssthresh，进入拥塞避免**）
- [ ] 传输效率计算：发送周期内有效数据/总数据；考虑 ACK 捎带、Nagle（概念级）
- [ ] **TCP 流量控制与拥塞控制（总括）**：**流量控制**（端到端、防接收方缓冲溢出）——接收方用 **rwnd** 通告可接收窗口，发送窗口 $\le \min(\text{rwnd}, \text{cwnd})$，rwnd = 0 时停发并由**持续计时器**周期发送**零窗口探测报文**防止死锁；**拥塞控制**（全局、防网络过载）——慢开始（cwnd 从 1 起每 RTT 翻倍）→ 拥塞避免（每 RTT +1）→ 超时（ssthresh = cwnd/2，cwnd = 1，重回慢开始）／快重传（3 个冗余 ACK 立即重传）+ 快恢复（ssthresh = cwnd/2，cwnd = 新 ssthresh，进入拥塞避免）

### 5.2 易错点 · 高频陷阱

- 确认号 = **最后一个按序收到字节的序号 + 1**（期望下一个），不是已收字节数。
- 三次握手中第三次握手可以**捎带数据**；前两次不能。
- SYN、FIN **各消耗一个序号**（即使不携带数据），ACK 不消耗——序号推进计算题的关键。
- 主动关闭方经历 FIN_WAIT_1/2 → TIME_WAIT（2MSL）→ CLOSED；被动方是 LAST_ACK——状态转移图要能画。
- 慢开始的"慢"指**起点低**（cwnd=1 MSS），增长并不慢（指数）；到达 ssthresh 转线性。
- **超时**与**快重传（3 dupACK）**的处理不同：超时 cwnd 拉回 1，快恢复 cwnd=新 ssthresh（不回 1）——数值题最容易混。
- cwnd 与 rwnd：发送窗口取两者**最小值**；拥塞控制防"网络过载"，流量控制防"接收方溢出"——目的不同。
- UDP 校验和可选（IPv4），但 408 默认"UDP 校验和既检 UDP 又检 IP 层部分信息（伪首部）"。
- 端口号标识**应用进程**，IP 地址标识主机；"TCP 是主到主、UDP 是进程到进程"必错（两者都是端到端进程通信）。

### 5.3 自测问答

**Q1. TCP 拥塞控制：ssthresh 初始 16（MSS）。cwnd 从 1 开始，第几轮后进入拥塞避免？当 cwnd=20 时发生超时，写出 ssthresh 与 cwnd 的变化。若改为收到 3 个冗余 ACK 呢？**

<details><summary>▶ 展开答案</summary>

慢开始：1,2,4,8,16（达到 ssthresh=16）→ 拥塞避免 17,18,19,20——第 5 轮（cwnd=16）起进入拥塞避免。
超时：$\text{ssthresh} = 20/2 = \textbf{10}$，cwnd = **1**，重新慢开始（1,2,4,8,10,11…）。
3 个冗余 ACK（快重传+快恢复）：$\text{ssthresh} = \textbf{10}$，cwnd = **10**，直接拥塞避免（不回 1）。
</details>

**Q2. 主机 A 向 B 发送两个 TCP 报文段，序号分别为 70 和 100：①第一个报文段携带多少数据？②B 收到第一个后发的确认号是多少？**

<details><summary>▶ 展开答案</summary>

① $100 - 70 = \textbf{30}$ 字节；② 确认号 $= 70 + 30 = \textbf{100}$（期望下一个字节序号）。
</details>

**Q3. 为什么 TCP 采用三次握手而不是两次？**

<details><summary>▶ 展开答案</summary>

主要防止**已失效的连接请求报文**（在网络中滞留后到达服务器）造成资源浪费：若两次握手，服务器收到旧 SYN 即建立连接并等待数据，而客户端并不知情，服务端资源被无谓锁定；三次握手下该请求不会得到客户端的第三次确认，连接无法建立。同时三次让双方都确认了"自己和对方的收发能力"。
</details>

**Q4. 判断：①UDP 首部中有伪首部；②TCP 的 TIME_WAIT 状态出现在主动关闭方。**

<details><summary>▶ 展开答案</summary>

① 正确——伪首部仅用于**计算校验和**，随报文一起交给校验计算但不传输。
② 正确——主动关闭方发完最后一个 ACK 后等 2MSL 才 CLOSED。
</details>

## 第6章 应用层

### 6.1 自查清单

- [ ] C/S 模型（服务器常驻、客户请求）vs **P2P**（对等、自扩展、成本分摊）——能对比流量/扩展性
- [ ] **DNS**：层次域名空间（根/顶级/权限）、分布式数据库（根、顶级、权限、本地域名服务器）；**递归查询（主机→本地）与迭代查询（本地→其他）**；DNS 用 **UDP 53**（区域传送用 TCP）；高速缓存；会给"主机解析 www.xxx.edu.cn"写出查询顺序
- [ ] **FTP**：两条 TCP 连接：**控制连接 21（整个会话保持）、数据连接 20（按需建立）**；主动模式（PORT，服务器 20 连回）vs 被动模式（PASV）；控制信息带外传送
- [ ] 电子邮件：组成（用户代理 UA/邮件服务器/协议）；**SMTP（TCP 25，推，只传 ASCII→MIME 扩展）**；**POP3（110，拉，下载并/或保留）**、**IMAP**（在线操作，服务器管理邮件）；基于万维网的电子邮件（网页→HTTP→服务器→SMTP→对方→HTTP）
- [ ] **WWW/HTTP**：URL 格式；**HTTP/1.0 非持久连接（每对象 2RTT）vs 1.1 持久连接（流水线与否）**——会算总时延；HTTP 报文（请求行/状态行、首部、实体）；GET/POST；无状态 → Cookie；代理服务器/Web 缓存（条件 GET）
- [ ] HTTPS（HTTP+SSL/TLS，443）概念级
- [ ] 其他：万维网文档 HTML/浏览器组成；搜索引擎（全文/目录）；CDN 概念级

### 6.2 易错点 · 高频陷阱

- DNS 查询方式：**主机到本地服务器递归，本地到根/顶级/权限迭代**（教材默认）；"根服务器也递归"的说法错。
- FTP 控制连接**不传数据**、始终打开；数据连接传一个文件就关。
- SMTP 只能推**不能拉**，且早先只支持 7 位 ASCII（二进制需 MIME 编码）；从服务器取信用 POP3/IMAP——"SMTP 直接把邮件放到用户 PC"错（放服务器）。
- HTTP 无状态靠 **Cookie** 维持会话；持久连接不等于同一时刻多对象并行（流水线才连发）。
- 时延计算：非持久连接每个对象 2RTT+传输；持久连接首个对象 2RTT、后续 1RTT——区分是否流水线。
- DNS 缓存减少根服务器压力；本地域名服务器不属于层次结构（是代理查询的入口）。

### 6.3 自测问答

**Q1. 页面含 1 个 HTML（很小）+ 5 张图片，RTT=100ms，传输时间忽略。非持久连接与持久非流水线连接各需多少时间（TCP 建连按 1RTT 计）？**

<details><summary>▶ 展开答案</summary>

非持久：每个对象 = 建连 1RTT + 请求响应 1RTT = 2RTT；6 个对象 = $12\text{RTT} = \textbf{1.2s}$。
持久非流水线：首个对象 2RTT，之后每对象 1RTT → $2+5 = 7\text{RTT} = \textbf{0.7s}$（流水线则 ≈ 2+1 = 3RTT）。
</details>

**Q2. 主机查询 www.cs.tsinghua.edu.cn（本地缓存全空），按"递归+迭代"写出查询顺序。**

<details><summary>▶ 展开答案</summary>

主机→本地域名服务器（递归）；本地→**根**（迭代）→ 指向 **cn 顶级**；本地→cn 顶级 → 指向 **edu.cn**；本地→edu.cn → 指向 **tsinghua.edu.cn 权限**；本地→权限服务器得到 IP 返回主机（沿途各级缓存）。
</details>

**Q3. 判断：①FTP 的控制连接在整个会话期间保持；②POP3 下载邮件后服务器上一定删除。**

<details><summary>▶ 展开答案</summary>

① 正确（数据连接按需建立/关闭）。② 错误——POP3 有"下载并保留"模式，是否删除由用户设置决定。
</details>
