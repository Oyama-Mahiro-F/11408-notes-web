## 第1章 计算机系统概述

### 1.1 自查清单

- [ ] 能说出操作系统四个基本特征（并发、共享、虚拟、异步）的定义，并各举一个例子；知道**并发与共享互为存在条件**、是最基本的两个特征
- [ ] 能区分并发与并行；共享的两种方式（互斥共享 vs 同时访问）
- [ ] 能按时间线讲出操作系统发展：手工 → 单道批处理 → 多道批处理 → 分时 → 实时，并说明每一步解决了什么问题
- [ ] 多道批处理的优点（提高 CPU/内存/IO 利用率、吞吐量）与缺点（无交互、周转时间长）；分时系统四个特点（同时性、交互性、独立性、及时性）
- [ ] 能区分**内中断（异常）**的三类：陷阱（trap，有意）、故障（fault，如缺页，可恢复）、终止（abort，致命）；外中断分为可屏蔽/不可屏蔽（NMI）
- [ ] **用户态→核心态的唯一途径是中断/异常**；核心态→用户态靠修改程序状态字（执行中断返回指令），反向不行
- [ ] 能完整描述一次系统调用的过程：传参 → 执行陷入（trap/访管）指令 → 切核心态 → 内核服务程序处理 → 返回；知道**陷入指令在用户态执行**，服务处理在核心态
- [ ] 知道系统调用按功能分类（设备管理/文件管理/进程控制/进程通信/内存管理），以及"凡与共享资源有关的操作必须通过系统调用"
- [ ] 操作系统内核包含：时钟管理、中断处理、原语、系统控制的数据结构与处理；能区分内核级功能与非内核功能
- [ ] 能比较宏内核（大内核）与微内核的优缺点（性能 vs 可靠性/可扩展性），以及分层结构、模块化结构的优缺点
- [ ] 能讲出操作系统引导的完整流程（BIOS 自检 → 读 MBR → 分区表 → 读 PBR/启动管理器 → 加载内核）
- [ ] 能区分两类虚拟机管理程序（一类直接运行在硬件上如 ESXi，二类运行在宿主 OS 上如 VMware Workstation），并知道半虚拟化的思想

### 1.2 易错点 · 高频陷阱

- **"并发"是宏观并行、微观串行**；单处理机上同一时刻只有一个程序在运行。
- 用户态→核心态**只能**通过中断/异常（含系统调用）；调用库函数不一定进核心态（普通库函数不陷入）。
- 系统调用执行时：陷入指令本身在用户态执行，之后的处理在核心态；**整个过程发生两次状态转换**（进/出核心态）。
- 中断是让操作系统夺回 CPU 使用权的**唯一途径**；没有中断，OS 无法实现并发。
- 分时系统用**时间片轮转**；实时系统强调**及时性与可靠性**， deadline 内必须完成。
- 引导时 BIOS 程序存放在 **ROM** 中；MBR 是磁盘第一个扇区（512B），含磁盘引导程序与分区表。

### 1.3 自测问答

**Q1. 为什么说"并发与共享互为存在条件"？**

<details><summary>▶ 展开答案</summary>

一方面，共享以并发为前提：若系统不能并发执行，就不存在多个进程同时竞争资源的问题，也就无需共享；另一方面，并发以共享为基础：若资源不能共享，多个进程无法同时使用有限的系统资源（如内存、设备），并发就无法实现。
</details>

**Q2. 简述系统调用全过程，并说明其中哪一步可能引起处理机状态转换。**

<details><summary>▶ 展开答案</summary>

① 用户程序传递系统调用参数（如寄存器/栈）；② 执行**陷入指令**（用户态），主动引发内中断（陷阱）；③ 硬件切换到**核心态**，转入系统调用入口，由内核服务例程处理请求；④ 处理完成，执行中断返回指令恢复**用户态**，返回调用处。状态转换发生在 ②→③（用户态→核心态）和 ④（核心态→用户态）。
</details>

**Q3. 判断：中断返回指令（如 iret）可以在用户态执行吗？**

<details><summary>▶ 展开答案</summary>

不能。中断返回会修改程序状态字、把状态从核心态切回用户态，属于特权指令，只能在核心态执行。反过来，陷入指令不是特权指令，用户态可以执行。
</details>

## 第2章 进程管理

### 2.1 自查清单

- [ ] 进程实体 = PCB + 程序段 + 数据段；**PCB 是进程存在的唯一标志**；进程是资源分配和独立调度的基本单位
- [ ] 五状态模型：能默画 运行/就绪/阻塞/创建/终止 之间的全部转换；明确 **运行→阻塞是主动行为，阻塞→就绪是被动行为**；不存在 阻塞→运行、就绪→阻塞
- [ ] 七状态模型：增加"挂起"相关状态；挂起（suspend）与激活（activate）原语；中级调度=挂起操作相关
- [ ] 三级调度：高级（作业，决定哪个作业进内存）、中级（换入换出，提高内存利用率）、低级（进程，频率最高）；批处理/分时/实时系统分别必须有哪些调度
- [ ] 进程控制原语：创建、撤销、阻塞（block）、唤醒（wakeup）各做了什么；**block 与 wakeup 必须成对使用**
- [ ] 进程通信三种方式：共享存储（数据结构级/存储区级）、消息传递（直接通信/信箱间接通信）、管道；管道的四个要点（半双工、内核缓冲区、固定大小、各进程对管道的读写互斥）
- [ ] 线程属性：TCB、线程是处理机调度的基本单位；**用户级线程**（内核不可见，切换不需要核心态，一个线程阻塞整进程阻塞）与**内核级线程**（切换需核心态，可多核并行）的区别
- [ ] 多线程模型：多对一、一对一、多对多各自的问题与适用场景
- [ ] 调度算法：FCFS、SJF/SRTN、HRRN（响应比 =(等待+要求服务)/要求服务）、RR、优先级调度、多级反馈队列——每个的规则、优缺点、是否饥饿
- [ ] **SJF 平均等待时间最短但可能饥饿长作业**；RR 时间片过大退化为 FCFS、过小切换开销大；多级反馈队列的完整规则（新进程进最高队列、用完时间片降级、最低队列 RR、可被更高队列抢占）
- [ ] 调度评价指标：CPU 利用率、吞吐量、周转时间、带权周转时间（≥1，越小越好）、等待时间、响应时间——会给甘特图算平均周转/等待时间
- [ ] 临界区四部分（进入区/临界区/退出区/剩余区）与四准则（空闲让进、忙则等待、有限等待、让权等待）
- [ ] 能手写/手推：单标志法的问题（必须交替进入）、Peterson 算法（flag[]+turn，满足前三条但不满足让权等待）、TSL/swap 指令、互斥锁（自旋等待 vs 阻塞队列）
- [ ] 记录型信号量：P(wait)/V(signal) 的伪代码（S.value 减 1 判断、阻塞队列进出）；**整型信号量不满足让权等待**
- [ ] 能独立写出并讲清：生产者-消费者（empty=n、full=0、mutex=1，**互斥 P 操作必须在同步 P 之后**，否则死锁）、读者-写者（计数器+互斥两个信号量）、吸烟者问题、哲学家进餐（三种防死锁方案）
- [ ] 管程的组成（共享数据结构+操作过程+初始化+入口等待队列）与本质：**互斥由编译器负责**，条件变量 x.wait / x.signal
- [ ] 死锁四个必要条件（互斥、不可剥夺、请求并保持、循环等待）；**发生死锁必有循环等待，但循环等待不一定死锁**（同类资源有多个实例时）
- [ ] 死锁处理策略对比：预防（破坏四条件：一次性申请/可剥夺/资源有序分配）、避免（银行家，动态判断安全状态）、检测+解除（资源分配图化简、死锁定理）；解除手段（剥夺资源/撤销进程/进程回退）
- [ ] 银行家算法完整流程：Need = Max − Allocation，找 Work 满足 Need_i 的进程，释放其 Allocation，重复；**安全状态一定无死锁，不安全状态未必死锁**
- [ ] 死锁 vs 饥饿 vs 死循环三者的区别（死锁至少两个进程且互相等待、均阻塞；饥饿可能只有一个进程、可就绪可阻塞）

### 2.2 易错点 · 高频陷阱

- 阻塞是**进程自身主动调用 block 原语**；等待 I/O、等信号量都是阻塞。就绪→运行靠调度，运行→就绪靠时间片到/被抢占。
- 优先级调度中**高响应比优先解决了饥饿**；单纯静态优先级会饿死低优先级。
- **单核系统**下进程并发：任意时刻最多一个进程在运行态；有 n 个进程时，就绪队列进程数最多 n−1，阻塞最多 n。
- 互斥 P 操作放在同步 P 操作**前面**可能死锁（生产者拿到 mutex 后申请 empty 失败，双双阻塞）——生产者：先 P(empty) 再 P(mutex)。
- 管道写满后写进程阻塞、读空后读进程阻塞；管道中的数据**读走即消失**。
- 系统中**死锁进程数 ≥2**；有死锁必然有进程阻塞，但反过来不成立。
- 银行家算法是**死锁避免**（不是预防）；资源有序分配是**预防**（破坏循环等待）。
- 用户级线程切换**不需要**进入核心态（内核根本不知道线程存在）——常考"无需核心态介入的切换"。
- 时间片轮转**不区分**进程优先级与长短；它保证响应时间但不能优化平均周转时间。

### 2.3 自测问答

**Q1. 三个进程 P1、P2、P3，运行时间分别 24、3、3（ms），按 P1→P2→P3 顺序到达（t=0）。分别用 FCFS、SJF、RR（时间片 4）计算平均周转时间与平均等待时间。**

<details><summary>▶ 展开答案</summary>

**FCFS**：完成时刻 24、27、30。周转 = 24+27+30 = 81，平均 27；等待 = 0+24+27 = 51，平均 17。
**SJF**：顺序 P2、P3、P1，完成 3、6、30。周转 = 3+6+30 = 39，平均 13；等待 = 0+3+6 = 9，平均 3。
**RR(4)**：P1(0–4) P2(4–7 完) P3(7–10 完) P1(10–14) P1(14–18) P1(18–22) P1(22–24 完)。周转 = 24+7+10 = 41，平均 41/3≈13.67；等待 = 0+4+7 = 11，平均 11/3≈3.67。
</details>

**Q2. 生产者-消费者：为什么 mutex 的 P 操作必须在同步信号量（empty/full）之后？给出死锁场景。**

<details><summary>▶ 展开答案</summary>

若生产者先执行 P(mutex) 再执行 P(empty)：当缓冲区满时，生产者持有 mutex 后在 P(empty) 上阻塞；消费者要取产品必须先 P(mutex)，也被阻塞——生产者等消费者腾出空缓冲，消费者等生产者释放 mutex，互相等待形成死锁。先做同步 P 再做互斥 P 可保证：申请不到资源时**不会持有互斥锁**睡眠。
</details>

**Q3. 某系统有 3 类资源 A(9)、B(3)、C(6)，5 个进程（_allocation/_max 如下），T 时刻是否安全？**

P1: Alloc(2,1,0) Max(4,2,2)；P2: Alloc(2,0,1) Max(3,2,2)；P3: Alloc(3,0,1) Max(9,0,2)；P4: Alloc(2,1,1) Max(2,2,2)；P5: Alloc(0,0,2) Max(4,3,3)。

<details><summary>▶ 展开答案</summary>

剩余 Available = (9−2−2−3−2−0, 3−1−0−0−1−0, 6−0−1−1−1−2) = **(0,1,2)**（经典例题数据）。
Need：P1(2,1,2) P2(1,2,1) P3(6,0,1) P4(0,1,1) P5(4,3,1)。
安全序列尝试：P4→(2,2,3)；P1? Need(2,1,2)≤(2,2,3)✓→(4,3,3)；P2(1,2,1)✓→(6,3,4)；P3(6,0,1)✓→(9,3,5)；P5✓。存在安全序列 **P4→P1→P2→P3→P5**（不唯一），系统安全。
</details>

**Q4. 判断并说明理由：①处于阻塞态的进程可以被剥夺处理机；②死锁一定伴随循环等待。**

<details><summary>▶ 展开答案</summary>

① 错误。阻塞态进程**不在处理机上运行**，谈不上"被剥夺处理机"；剥夺的是运行态进程（运行→就绪）。
② 正确。循环等待是死锁的必要条件之一，死锁发生时资源等待关系必成环；但逆命题不成立——同类资源多个实例时，存在循环等待环也可能不发生死锁。
</details>

## 第3章 内存管理

### 3.1 自查清单

- [ ] 三种装入方式：绝对装入（单道/编译期定地址）、**静态重定位**（装入时一次变换，之后不能移动、不能申请新空间）、**动态重定位**（运行时借重定位寄存器变换，支持离散分配，是虚拟内存的基础）
- [ ] 链接：静态链接 vs 动态链接（运行时才链接共享库）
- [ ] 覆盖技术（固定区+覆盖区，程序内，程序员声明）vs 交换技术（进程级，换出到磁盘对换区，由中级调度控制）；两者的针对对象与场合
- [ ] 连续分配：单一连续分配、固定分区（**内部碎片**）、动态分区（**外部碎片**，用紧凑/拼接解决，需要动态重定位支持）
- [ ] 动态分区分配算法：First Fit、Next Fit、Best Fit、Worst Fit 的规则与性能排序（**综合性能 First Fit 最优，Best Fit 会产生最多小碎片**）
- [ ] 基本分页：逻辑地址结构（页号+页内偏移）、页表项内容；**物理地址 = 页框号 × 页面大小 + 页内偏移**；页面大小通常 2 的幂（如 4KB，偏移 12 位）
- [ ] 会做地址变换数值题：32 位系统、4KB 页面、给定逻辑地址求页号/偏移/物理地址
- [ ] 单级页表的两个问题（页表自身要连续且很大、必须常驻内存）→ 两级/多级页表（顶级页表常驻一张即可，**每级页表大小不超过一页**）
- [ ] 各级页表均命中时，n 级页表系统一次数据访问需 **n+1 次访存**（含取数据）
- [ ] 快表 TLB：相联存储器、存放最近访问的页表项副本；会给命中率算有效访问时间 EAT（如 EAT = a×(t_TLB+t_M) + (1−a)×(t_TLB+2t_M)，单级页表）
- [ ] 基本分段：段表项含**段长与基址**（显式），偏移≥段长→越界中断；分段按逻辑模块划分、**便于共享与保护**；分页按物理大小划分、对用户透明
- [ ] 碎片对比：**分页无外部碎片（最后一页有内部碎片）；分段无内部碎片（有外部碎片）**；段页式先分段后分页、每段一张页表、有一次内部碎片
- [ ] 虚拟内存三个特征：**多次性、对换性、虚拟性**；理论基础是**局部性原理**（时间局部性/空间局部性）
- [ ] 请求分页的页表项扩充：状态位/访问字段/修改位/外存地址；缺页处理流程（保留现场→查外存→分配页框→调入→修改页表→重新执行被中断指令）；缺页是**内中断中的"故障"**
- [ ] 页面置换算法：OPT（不可实现、作评价标准）、FIFO（**Belady 异常**：页框增多缺页可能反而增多）、LRU（堆栈类、无 Belady、硬件开销大）、CLOCK（访问位+循环指针）、改进 CLOCK（按 (访问,修改) 位优先级 (0,0)→(0,1) 淘汰）
- [ ] 会手算给定访问串在不同算法、不同页框数下的缺页次数（**首次调入也算缺页**）
- [ ] 页面分配与置换策略：固定/可变局部置换、全局置换（只能可变分配）；预调页 vs 请求调页；抖动（颠簸）的原因（分配页框 < 工作集）与工作集模型

### 3.2 易错点 · 高频陷阱

- 页表项里**没有页号字段**（页号隐含，按下标对应），只有页框号/状态位等——考"页表项内容包括什么"的坑。
- 4KB 页面：地址低 12 位是页内偏移，**与虚拟/物理无关**；页号位数由虚拟地址总位数决定。
- 快表命中时不需要访问页表所在内存（TLB 直接给出页框号），算 EAT 时别把页表访存又加一次。
- 缺页中断处理完成后**重新执行**引起缺页的那条指令（fault 特点）；一条指令可能触发多次缺页（多操作数跨页）。
- FIFO 有 Belady 异常，LRU/OPT 没有——判断"增加页框数缺页次数必不增加"只有堆栈类算法成立。
- CLOCK 算法扫描中遇到 (访问位=1) 就置 0 并继续走，遇到 (0,0) 才淘汰；改进 CLOCK 第一轮扫不到 (0,1) 之外还会把扫过的访问位清零。
- 交换以**进程**为单位（整体换出），覆盖以**程序段**为单位；两者都不需要硬件地址变换支持的是覆盖。
- Best Fit 名字有欺骗性：它针对每次请求找最小可用洞，结果产生大量难以利用的小碎片。
- 动态分区没有内部碎片；固定分区只有内部碎片；分页只有（最后一页的）内部碎片——选择题常混着问。
- 虚拟内存最大容量由**地址结构位数**决定（如 32 位 → 4GB），实际容量 ≤ min(内存+对换区, 2^位数)。

### 3.3 自测问答

**Q1. 32 位系统，页面 4KB，页表项 4B。逻辑地址 0x00402A56（十六进制）的页号和页内偏移各是多少？若该页放在页框 0x1A，物理地址是多少？**

<details><summary>▶ 展开答案</summary>

4KB = 2¹²，低 12 位为偏移：0xA56（十进制 2646）。页号 = 0x00402 − 0（即 0x0040 2A56 → 高 20 位 0x00402，十进制 1026）。
物理地址 = 页框号 0x1A 拼偏移 = **0x01AA56**（0x1A × 0x1000 + 0xA56）。
</details>

**Q2. 单级页表、TLB 命中率 90%，TLB 查找 20ns，访存 100ns。忽略 Cache，求平均有效访问时间。**

<details><summary>▶ 展开答案</summary>

命中 TLB：20（TLB）+ 100（取数据）= 120ns；未命中：20 + 100（查页表）+ 100（取数据）= 220ns。
EAT = 0.9×120 + 0.1×220 = 108 + 22 = **130ns**。
</details>

**Q3. 访问串 1,2,3,4,1,2,5,1,2,3,4,5，3 个页框，分别用 FIFO 和 LRU 求缺页次数。页框增加到 4 个后 FIFO 结果如何变化？**

<details><summary>▶ 展开答案</summary>

FIFO(3 框)：缺页 **9** 次（1,2,3,4,1,2,5,3,4 缺；命中 1,2,5）。LRU(3 框)：缺页 **10** 次。
FIFO(4 框)：缺页 **10** 次 > 9 次，出现 **Belady 异常**（页框增多缺页反而变多）。
</details>

**Q4. 分页与分段的主要区别（至少 4 条）。**

<details><summary>▶ 展开答案</summary>

① 目的不同：页是物理划分（对用户透明，提高内存利用率），段是逻辑划分（用户可见，满足模块化/共享保护需求）；② 大小：页固定由系统决定，段长不定由用户程序决定；③ 地址空间：分页是一维线性（一个地址即可定位），分段是二维（段号+段内偏移都要给）；④ 碎片：分页有内部碎片无外部碎片，分段相反；⑤ 共享与保护：段更容易（逻辑完整单元）。
</details>

## 第4章 文件管理

### 4.1 自查清单

- [ ] 文件的逻辑结构：无结构（流式）；有结构：**顺序文件**（串结构/顺序结构；定长记录支持随机存取，变长只能顺序）、**索引文件**（为变长记录建索引表，索引表按关键字有序，支持快速随机检索）、**索引顺序文件**（分组+多级索引，经典结论：N 条记录分 √N 组检索次数从 N/2 降到 √N/2）
- [ ] 文件目录：FCB 的组成；**索引结点（inode）把文件名以外的信息移出目录项**，目录项只剩 文件名+inode 号，大幅减少检索时读盘量
- [ ] 磁盘 inode 与内存 inode 的区别（内存版增加：是否被打开、引用计数、是否修改未写回等状态信息）
- [ ] 目录结构：单级/两级/树形（绝对路径、相对路径、当前目录，引入"当前目录"减少路径解析的磁盘访问）/无环图目录（实现共享，带共享计数）
- [ ] 文件物理结构（分配方式）：连续分配（支持随机、扩展难、外部碎片）、隐式链接（只能顺序存取、可靠性差）、显式链接 FAT（表常驻内存、支持随机、但占内存）、索引分配（索引块；大文件三种方案：链接方案/多层索引/混合索引）
- [ ] 混合索引计算：4KB 块、4B 地址，一级间接块能寻址 4MB（1024 块），二级间接 4GB（1024² 块）；UNIX 的 10 直接 + 1 一级 + 1 二级 + 1 三级
- [ ] 会算"访问某逻辑块需要几次访存"（连续/链接/索引/多级索引在目录项、索引块已/未缓存情形下）
- [ ] 空闲空间管理四种：空闲表法（连续分配）、空闲链表法（盘块链/盘区链）、**位图法**（盘块号 = 字号×字长+位号）、**成组链接法**（UNIX：空闲盘块号栈，栈底块是"下一组"链接块）
- [ ] 文件共享：**硬链接**（多个目录项指向同一 inode，inode 共享计数；不能跨文件系统、不能对目录）vs **符号链接/软链接**（新文件内容是被链路径；原文件删除后软链接悬空；可跨文件系统）
- [ ] 文件保护：口令、加密、访问控制（访问控制表 ACL，按用户/组设置 读/写/执行）
- [ ] 文件系统调用：open 的作用（把目录项/inode 复制进内存打开文件表，返回 fd；之后读写不再查目录）、系统级打开文件表 vs 进程级打开文件表、read 的数据流向（磁盘→内核缓冲区→用户区）
- [ ] 文件系统布局：物理格式化（划分扇区、检测坏扇区）与逻辑格式化（建立文件系统元数据）；引导块的作用；虚拟文件系统 VFS 的意义（统一接口，四对象：超级块/inode/dentry/file）

### 4.2 易错点 · 高频陷阱

- inode **不包含文件名**；文件名只存在目录项里——"查找文件需要几次访存"类题目的关键。
- FAT 是**显式链接**：物理块内**不含**下一块指针（指针集中在内存 FAT 表中），因此支持随机存取；隐式链接才在块内放指针。
- 硬链接删除原文件：只要共享计数 >0 文件仍在，新建的目录项仍可访问；软链接删除原文件后变成悬空链接。
- 位图法盘块号换算：字号×字长+位号（注意题目给的字长是 16 位还是 32 位）。
- 打开文件后的 read/write 用 fd 定位文件，**不再需要路径解析**；close 释放的是 fd 与内存表项。
- 多级索引中"10 个直接块"这种约定属于 UNIX 类文件系统，题目不给就按通用多层索引算（无直接块）。
- 树形目录不便于文件共享 → 无环图目录；两级目录的作用是"允许用户重名+提高检索速度"，不是共享。
- 成组链接法中空闲盘块号栈满了要"压栈"新组、只剩 1 项时该项指向"下一组空块号块"——取空块的顺序别搞反。

### 4.3 自测问答

**Q1. 文件系统块 4KB，地址 4B。采用索引分配，求：①一个索引块可索引多大文件？②二级索引最大文件？③UNIX 混合索引（10 直接+1 一次+1 二次间接）最大文件（只算到二级）。**

<details><summary>▶ 展开答案</summary>

每块可存 4KB/4B = 1024 个地址。① 1024×4KB = **4MB**；② 1024×1024×4KB = **4GB**；③ 10×4KB + 4MB + 4GB ≈ **4GB + 4MB + 40KB**。
</details>

**Q2. 目录中有 100 个文件，每个 FCB 64B，盘块 1KB。若采用"文件名+inode 号"的目录项（10B），检索一个文件平均少读多少块（按目录平均查到一半计）？**

<details><summary>▶ 展开答案</summary>

FCB 方案：目录总大小 100×64B = 6400B ≈ 6.4 块，平均查到一半需读约 6.4/2 ≈ 3.2 → 约 3~4 块。
瘦身方案：100×10B = 1000B ≈ 1 块，平均不到 1 块即可命中文件名，再按 inode 号读 inode。节省的正是"目录块"的读盘次数——这正是引入索引结点的意义。
</details>

**Q3. 判断：①显式链接（FAT）方式的文件支持随机存取；②连续分配的文件便于动态增长。**

<details><summary>▶ 展开答案</summary>

① 正确。FAT 在内存中，顺着表项可 O(块号) 定位任意逻辑块对应的物理块（查表+一次访存）。
② 错误。连续分配要求文件占连续盘区，动态增长可能无处可扩（需搬迁），**不便于**动态增长；链接与索引分配才便于增长。
</details>

## 第5章 输入输出管理

### 5.1 自查清单

- [ ] I/O 接口的三类寄存器（数据/状态/控制）与端口编址：统一编址（内存映射，普通访存指令）vs 独立编址（专用 IN/OUT 指令）的优缺点
- [ ] I/O 软件四层结构从上到下：用户层 I/O 软件 → **设备独立性软件**（系统调用接口、设备保护、命名与映射、缓冲、分配与回收、差错控制）→ 设备驱动程序 → 中断处理程序 → 硬件；能给"read() 调用、设备名解析、写控制器寄存器、响应中断"归类到层
- [ ] I/O 控制方式演进：程序直接控制（轮询忙等）→ 中断驱动（每字一次中断，数据仍走 CPU）→ **DMA**（数据块为单位、数据直接设备↔内存不经过 CPU、仅块首尾需要 CPU）→ 通道
- [ ] DMA 控制器组成（CR/MAR/DAR/DC 等）与 DMA 传送三阶段（预处理→数据传送→后处理，后处理以中断方式通知 CPU）
- [ ] 中断处理流程：**中断隐指令**（关中断、保存断点、引出中断服务程序）由硬件完成；服务程序：保存现场与屏蔽字→开中断（服务中允许更高优先级）→服务→恢复现场→开中断→中断返回
- [ ] 单重中断 vs 多重中断；**屏蔽字技术：某位置 1 表示屏蔽**，处理优先级由屏蔽字决定，响应优先级由硬件排队器决定——会按给定优先级设计各中断的屏蔽字
- [ ] 缓冲区计算（重点）：T=输入，M=传送，C=处理；**单缓冲每块 max(C,T)+M；双缓冲 max(C+M,T)**；循环缓冲与缓冲池（公用、在主存）
- [ ] 设备分配中的数据结构：DCT（设备控制表）→ COCT（控制器）→ CHCT（通道）；设备分配的安全方式（发出请求即阻塞）与不安全方式
- [ ] 设备独立性（用户程序用逻辑设备名）；**逻辑设备表 LUT** 实现逻辑设备→物理设备映射
- [ ] SPOOLing（假脱机）：输入井/输出井（磁盘）+ 输入/输出缓冲区（内存）+ 输入/输出进程；**用共享设备模拟独占设备**（打印机），宏观上多进程"同时"打印，微观串行
- [ ] 磁盘结构与时间：寻道时间+旋转延迟（平均半圈）+传输时间；会算给定转速（如 7200rpm）下的平均旋转延迟与一个磁道读取时间
- [ ] 磁盘调度：FCFS、SSTF（会饥饿）、SCAN（电梯，扫到**边缘**才折返）、LOOK（扫到**最远请求**即折返）、C-SCAN/C-LOOK——给磁道号序列手算总移动道数
- [ ] 磁盘管理：格式化（低级/逻辑）、引导块（MBR 与引导控制块）、坏块管理（FAT 标记 / 备用扇区替换）

### 5.2 易错点 · 高频陷阱

- 中断驱动方式：CPU 在**每字**传输后都要介入（执行中断程序搬字），DMA 是**每块**才打断一次且数据不经过 CPU——"块设备适合 DMA"的原因。
- 中断响应条件：CPU 允许中断 + 有中断请求 + **一条指令执行完毕**（不是任意时刻）。
- 中断隐指令**不是指令**，是硬件自动完成的操作序列（关中断/存断点/找入口），不含保存通用寄存器现场（那是服务程序做的）。
- 屏蔽字中 1=屏蔽 0=开放；设计屏蔽字时**自身位置恒为 1**；处理优先级最高的中断屏蔽字全 1。
- 单缓冲公式 max(C,T)+M 的来源：处理与下一块输入可并行，但传送必须串行插入；双缓冲两块之间 max(C+M, T)。
- SCAN 要求扫到磁盘**边缘**再折返，即使边缘无请求；LOOK 只到最远请求——题目给"到边缘/不到边缘"两种答案不同。
- C-SCAN 回程**快速返回起点不服务**，优点是各磁道等待时间更均匀。
- SPOOLing 的输入井/输出井在**磁盘**上，缓冲区在**内存**中；它把独占设备改造成共享（虚拟）设备。
- DMA 响应的是"存取周期结束"，中断响应的是"指令周期结束"——DMA 与中断的响应时机对比（也是计组考点）。

### 5.3 自测问答

**Q1. 设备速率 100KB/s，CPU 处理每块 100μs（C），缓冲区到用户区传送 50μs（M），读入一块到缓冲区需 200μs（T）。单缓冲和双缓冲下系统处理一块数据的平均时间？**

<details><summary>▶ 展开答案</summary>

单缓冲：max(C, T) + M = max(100, 200) + 50 = **250μs**；
双缓冲：max(C+M, T) = max(150, 200) = **200μs**。
</details>

**Q2. 磁盘转速 6000rpm，求平均旋转延迟和读取一个磁道的时间（一磁道一圈）。**

<details><summary>▶ 展开答案</summary>

每圈 = 60s / 6000 = 10ms。平均旋转延迟 = 半圈 = **5ms**；读完一个磁道（一整圈）= **10ms**（不含寻道）。
</details>

**Q3. 磁盘请求到达顺序：98, 183, 37, 122, 14, 124, 65, 67，当前磁头在 53，磁道 0–199。分别求 SSTF 与 SCAN（向磁道号增大方向，扫到 199 才折返）的总移动道数。**

<details><summary>▶ 展开答案</summary>

**SSTF**：53→65→67→37→14→98→122→124→183：移动 12+2+30+23+84+24+2+59 = **236**。
**SCAN**：53→65→67→98→122→124→183→199→（折返）37→14：移动 (199−53) + (199−14) = 146+185 = **331**。
</details>

**Q4. 四个中断 A、B、C、D，处理优先级 C > A > D > B。写出 A 的中断屏蔽字（1=屏蔽，顺序 A B C D）。**

<details><summary>▶ 展开答案</summary>

A 的屏蔽字要屏蔽**处理优先级不高于自己**的（含自身）：A(=) 屏、B(低) 屏、C(高) 开、D(低) 屏 → **1 1 0 1**。
（同理：B=1111，C=1000，D=1101。处理优先级最高的 C 屏蔽字全 1。）
</details>
