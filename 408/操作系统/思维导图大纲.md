## 一、操作系统概述（笔记：第1章 计算机系统概述）
- [📖 本章笔记](%E7%AC%94%E8%AE%B0/%E7%AC%AC1%E7%AB%A0%20%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%B3%BB%E7%BB%9F%E6%A6%82%E8%BF%B0.md) · [🧭 本章自查](%E5%A4%8D%E4%B9%A0%E8%87%AA%E6%9F%A5.md)
- 基本概念：OS 是管理硬件与软件资源、为用户和程序提供服务的系统软件；四大特征 = 并发、共享、虚拟、异步
  - **并发与共享互为存在条件**，是最基本的两个特征；并发（宏观同时、微观交替）≠ 并行（同一时刻真正同时）
  - 共享两方式：互斥共享（临界资源，如打印机）与同时访问（如磁盘文件）；虚拟 = 时分复用（虚拟处理机）+ 空分复用（虚拟存储器）
  - 异步性：进程以不可预知的速度向前推进，因而需要同步机制；常考：并发与并行、互斥共享与同时访问的辨析；单处理机同一时刻只有一个程序运行
  - OS 的三大作用：作为资源管理者、作为用户与硬件的接口、作为扩充机器（虚拟机观点）
- 发展历程：手工 → 单道批处理 → 多道批处理 → 分时 → 实时
  - 多道批处理优点（提高 CPU/内存/I/O 利用率与吞吐量）与缺点（无交互、周转时间长）；分时四特点：同时性、交互性、独立性、及时性
  - 实时系统强调**及时性与可靠性**，必须在 deadline 内完成；分时靠时间片轮转
  - 易错：单道批处理**内存中始终只有一道程序**，多道批处理才存在并发与宏观上"同时"运行；分时系统的"及时性"靠时间片足够小保证
- 【22增】程序运行环境：CPU 运行模式与中断异常（一(三)1–2）
  - CPU 运行模式：内核模式（管态/核心态，可执行特权指令）与用户模式（目态）；**用户态 → 核心态唯一途径是中断/异常**
  - 中断与异常：内中断 = 陷阱 trap（有意，如系统调用）、故障 fault（如缺页，可恢复）、终止 abort（致命）；外中断分可屏蔽与不可屏蔽（NMI）
  - 中断处理：**中断隐指令**（关中断、保存断点、引出服务程序）由硬件完成，保存通用寄存器现场由服务程序完成；多重中断靠屏蔽字实现
  - 易错：缺页属于"故障"（处理后重新执行该指令），系统调用属于"陷阱"（处理后返回下一条指令）
- 【22增】程序运行环境：链接与装入、内存映像（一(三)4–5）
  - 【22增】链接：静态链接（装入前链接成完整模块）· 装入时动态链接（装入内存时边装入边链接）· 运行时动态链接（执行中才链接，未用到的目标模块不调入，节省内存）
  - 【22增】装入三方式：绝对装入（编译期定物理地址，只适合单道）· 可重定位装入/静态重定位（装入时一次变换，**之后不能移动、不能申请新空间**）· 动态运行时装入/动态重定位（运行时由重定位寄存器变换，支持离散分配，是虚拟内存的基础）
  - 【22增】程序运行时内存映像（低地址→高地址）：代码段 text · 已初始化数据段 data · 未初始化数据段 bss · **堆 heap（向上增长）** · 共享库映射区 · **栈 stack（向下增长）** · 内核区
  - 【22增】地址空间 = 进程可用的逻辑地址集合；**ASLR（地址空间布局随机化）**把栈、堆、共享库基址随机化以抵御缓冲区溢出攻击
- 系统调用：用户程序请求内核服务的唯一合法入口，**陷入（trap/访管）指令在用户态执行，服务处理在核心态**
  - 过程：传参 → 执行陷入指令（用户态，引发陷阱）→ 切核心态 → 内核服务例程 → 中断返回恢复用户态（**共两次状态转换**）
  - 分类：设备管理、文件管理、进程控制、进程通信、内存管理；"凡与共享资源有关的操作必须通过系统调用"
  - 易错：普通库函数不陷入；中断返回指令 iret 是特权指令，只能核心态执行
- 内核与 OS 结构：内核含时钟管理、中断处理、原语、系统控制的数据结构与处理
  - 分层结构（层层单向依赖，易于调试但效率低）· 模块化（模块间可调用，灵活但接口难定）· 宏内核/大内核（性能高、可靠性差）· 微内核（只留最基本功能，可靠可扩展但**频繁态切换开销大**）
  - **外核 exokernel**：只负责资源的保护与分配，把抽象与管理交给用户库，追求最小内核与最大灵活性
  - 对比记忆：宏内核把"机制与策略"都放内核；微内核只放机制；外核连机制都尽量外移
  - 常考：微内核把什么移出内核（文件系统、设备驱动、进程管理等服务）、由此带来的性能损失原因
- 【22增】操作系统引导/虚拟机
  - 引导流程：CPU 复位取 ROM 中 BIOS → 自检 POST → 读 MBR（磁盘第一个扇区 512B，含引导程序+分区表）→ 活动分区 PBR/启动管理器 → 加载内核
  - 虚拟机：一类管理程序（裸机/VMM 直接跑在硬件，如 ESXi）vs 二类（跑在宿主 OS 上，如 VMware Workstation）；半虚拟化修改客户 OS 以提升性能
  - 易错：BIOS 在 **ROM**；MBR 只负责找活动分区与加载 PBR，不直接加载内核
- 高频题型：概念辨析选择题（特征、态转换、中断分类）+ 引导与虚拟机简答 + "链接与装入、内存映像"新增点简答

## 二、进程管理（笔记：第2章 进程管理）
- [📖 本章笔记](%E7%AC%94%E8%AE%B0/%E7%AC%AC2%E7%AB%A0%20%E8%BF%9B%E7%A8%8B%E7%AE%A1%E7%90%86.md) · [🧭 本章自查](%E5%A4%8D%E4%B9%A0%E8%87%AA%E6%9F%A5.md)
- 进程与线程：进程实体 = PCB + 程序段 + 数据段，**PCB 是进程存在的唯一标志**；进程是资源分配的基本单位，线程是处理机调度的基本单位
  - 五态：创建、就绪、运行、阻塞、终止；**运行→阻塞主动（block），阻塞→就绪被动（wakeup），二者必须成对**；不存在 阻塞→运行、就绪→阻塞
  - 七态增加挂起（就绪挂起/阻塞挂起）与激活；挂起/激活原语，中级调度负责换入换出
  - 原语：创建、撤销、阻塞、唤醒；原语由**关中断**保证原子性
- 进程控制与组织：进程控制原语（创建、终止、阻塞、唤醒、切换）；PCB 通过链接方式（就绪队列/阻塞队列）或索引方式组织
  - PCB 是内核中唯一的进程数据结构，**PCB 是进程存在的唯一标志**；进程切换由内核完成；阻塞是**进程自身主动**调用原语，唤醒由别的进程或中断处理程序执行
  - 易错：**block 与 wakeup 必须成对使用**，否则进程永久阻塞；"就绪→阻塞"这一转换不存在
- 线程实现：用户级线程 ULT（内核不可见，切换不需核心态，**一个线程阻塞导致整进程阻塞**）vs 内核级线程 KLT（切换需核心态，可多核真并行）vs 组合/多对多
  - 多线程模型：多对一（不能真并行）、一对一（线程数受限、开销大）、多对多
  - 线程与进程对比：线程是调度单位、进程是资源分配单位；同进程内线程共享地址空间、打开文件、信号处理等，但各有栈与寄存器
  - 高频：单核上进程数 $n$ 时就绪队列最多 $n-1$ 个、阻塞最多 $n$ 个
- 进程间通信 IPC：共享存储（数据结构级/存储区级，需同步互斥工具）· 消息传递（直接通信/信箱间接通信）· 管道（半双工、内核缓冲区、固定大小、读写互斥）
  - 管道四要点：半双工（双向需两条）、以**内核缓冲区**为中介、缓冲区固定大小、各进程对管道的读写互斥；管道数据**读走即消失**
  - 易错：共享存储最快但必须由用户自己实现同步互斥；消息传递适合分布式系统但每次通信都要陷入内核
- 【25新增】进程间通信：信号（signal）
  - 【25新增】信号（signal）：由内核投递给进程的**异步事件通知**，机制上是"软中断"，进程无法预知其到达时刻
  - 【25新增】常见信号：SIGINT（Ctrl+C 中断）、SIGKILL（强制杀死，不可捕获/忽略）、SIGSEGV（段错误）、SIGTERM、SIGCHLD、SIGALRM
  - 【25新增】处理方式三种：默认动作（如终止）、忽略、捕获（注册自定义处理函数）；不可靠信号（1–31，可能丢失、不排队）vs 可靠信号（实时信号，排队不丢失）
  - 【25新增】易错：信号是**异步事件通知**，信号量是**同步互斥原语**（P/V 操作、有整数值、进程主动调用），二者毫不相干，仅名字相近
- CPU 调度：三级调度——高级（作业调度，决定谁进内存）、中级（换入换出）、低级（进程调度，频率最高）
  - 调度目标：CPU 利用率、吞吐量、周转时间、带权周转时间、等待时间、响应时间；批处理重吞吐与周转、分时重响应、实时重 deadline
  - 指标公式：$\text{带权周转时间} = \dfrac{\text{周转时间}}{\text{实际运行时间}} \ge 1$；$\text{周转时间} = \text{完成时间} - \text{到达时间}$
  - 三级调度对比：高级调度频率最低（分钟级）、中级调度面向换入换出、低级调度频率最高（毫秒级）；分时系统可以只有低级调度；等待时间 = 周转时间 − 实际运行时间，响应时间是**首次响应**的延迟
- 典型调度算法：FCFS（简单、对短作业不利）· SJF/SPF（**平均等待时间最短**但长作业饥饿；SRTN 抢占式）· HRRN（$\text{响应比} = \frac{\text{等待时间}+\text{要求服务时间}}{\text{要求服务时间}}$，兼顾长短作业）· RR（时间片过大退化为 FCFS、过小切换开销大）· 优先级（静态会饿死低优先级）· 多级反馈队列（新进程进最高级，用完时间片降级，最低级 RR，可被更高级抢占）
  - 会给甘特图算平均周转/等待时间；抢占式与非抢占式的判定（SJF vs SRTN、FCFS 一律非抢占）；多级反馈队列中"新进程一律进最高优先级队列"，不要记成按需分配队列
  - 多处理机调度：专用处理器队列（静态、局部性好但负载难均衡）vs 全局就绪队列（动态、天然均衡但公共队列加锁成瓶颈）；处理器亲和性（软/硬）与负载均衡（推/拉迁移）目标相反；SMP vs AMP
- 【22增】上下文切换及其机制（二(二)5）
  - 上下文（context）组成：PCB（进程控制块）、通用寄存器、程序计数器 PC、程序状态字 PSW、栈指针、地址空间/页表基址等
  - 进程切换步骤：保存旧进程上下文到 PCB → 更新 PCB（状态、队列）→ 调度程序选新进程 → 恢复其上下文并跳转
  - **模式切换 vs 进程切换**：中断/异常引起的用户态↔核心态转换只换态不换进程（模式切换）；只有当调度程序选中了另一个进程才发生真正的进程切换
  - 开销来源：寄存器保存/恢复、**Cache 与 TLB 失效**、页表切换、调度器本身开销——切换越频繁，有效算力越低
- 【22增】上下文切换常考陷阱
  - 系统调用返回原进程只发生模式切换（2 次态转换），认为"进核心态就是进程切换"是错的
  - 进程切换本身必须在**关中断**保护下完成；时间片过小会使切换开销占比升高、CPU 有效利用率下降
- 【22增】二(二)3 调度的实现：调度器/调度程序 scheduler；调度时机（创建、终止、阻塞、I/O 中断、时间片到、更高优先级到达）；抢占式 vs 非抢占式
  - 闲逛进程 idle：就绪队列为空时运行，优先级最低、**不阻塞 CPU**（否则无进程可运行），是"CPU 利用率不为 0"的保证
  - 内核级线程 vs 用户级线程的调度：ULT 对内核不可见，内核以**进程**为调度单位，一个 ULT 阻塞整进程阻塞；KLT 可被内核**单独调度**，多线程可并行上多核
  - 易错："不能进行进程调度"的时机不存在——创建/终止/阻塞/中断处理结束都可调度，只有处理中断的过程中不立即切换
- 同步与互斥：临界区四部分（进入区、临界区、退出区、剩余区）与四准则（空闲让进、忙则等待、有限等待、让权等待）
  - 软件方法：单标志法（必须交替进入）· 双标志先检查（**都进**，违忙则等待）· 双标志后检查（**都进不去**，违空闲让进，可死锁）· Peterson（flag[]+turn，满足前三准则但不满足让权等待）
  - 硬件方法：中断屏蔽、TSL/swap 指令（**忙等、不满足让权等待**，但适用于任意数目进程且简单）
  - 【22增】锁与条件变量：自旋锁（忙等，适合临界区极短、多核）vs 互斥锁（拿不到就阻塞睡眠，需内核支持）；管程中条件变量 x.wait / x.signal，**互斥由编译器负责**
- 信号量：整型信号量（不满足让权等待）· 记录型信号量 P/V；$S.value$ 减 1 后若 $<0$ 则阻塞入队，V 加 1 后若 $\le 0$ 则唤醒队首
  - 经典同步问题：生产者-消费者（empty 初值 $n$、full 初值 $0$、mutex 初值 $1$，**互斥 P 必须在同步 P 之后**）· 读者-写者（计数器 count + mutex + rw）· 哲学家进餐（至多 4 人同时取 / 奇偶顺序 / 原子拿两支）
  - 高频考点：给场景写 P/V 伪代码并判断是否死锁；"先同步后互斥"的原因；利用信号量实现前驱图（每条有向边一个信号量、初值 0）
  - 易错：$S.value < 0$ 时 $|S.value|$ 表示**阻塞队列中的进程数**；信号量的初值由资源数目与同步方向共同决定，不能死记
- 死锁：四个必要条件 = 互斥、不可剥夺、请求并保持、循环等待
  - 处理策略：预防（破坏四条件：一次性申请、可剥夺、资源有序分配）· 避免（银行家算法，$\text{Need} = \text{Max} - \text{Allocation}$，找安全序列）· 检测与解除（资源分配图化简、死锁定理；剥夺资源/撤销进程/进程回退）
  - 结论：**发生死锁必有循环等待，循环等待不一定死锁**（同类资源多实例）；**安全状态一定无死锁，不安全状态未必死锁**
  - 易错：死锁进程数 $\ge 2$ 且均阻塞；饥饿可能只有 1 个进程且可就绪可阻塞；死循环是占用 CPU 运行
- 高频题型：调度计算题、PV 大题、银行家算法安全性判断、概念辨析题

## 三、内存管理（笔记：第3章 内存管理）
- [📖 本章笔记](%E7%AC%94%E8%AE%B0/%E7%AC%AC3%E7%AB%A0%20%E5%86%85%E5%AD%98%E7%AE%A1%E7%90%86.md) · [🧭 本章自查](%E5%A4%8D%E4%B9%A0%E8%87%AA%E6%9F%A5.md)
- 基本概念：逻辑地址空间 vs 物理地址空间；地址变换（重定位）；内存保护（上下界寄存器、基址+限长）
  - 内存分配与回收：连续分配与离散分配；分配算法服务的是"进程/段/页"的请求，回收时要把空间并回空闲区并考虑相邻空闲区合并
  - 内存共享实现：页共享/共享内存段（多个进程页表项指向**同一物理页框**，物理页只需一份）；写时复制 COW（fork 后先共享只读，任一方写入才复制，减少复制开销）
  - 易错：共享代码段必须**只读**（可重入）；COW 页被写时才分配新页框并更新页表
- 连续分配管理方式：单一连续分配 · 固定分区（**内部碎片**）· 动态分区（**外部碎片**，靠紧凑/拼接解决且需动态重定位支持）
  - 动态分区算法：First Fit（综合性能最优）· Next Fit · Best Fit（留下最多难利用的小碎片）· Worst Fit
  - 覆盖（程序内、程序员声明、无需硬件支持）vs 交换（进程级整体换出到对换区、中级调度控制）
  - 易错：固定分区有内部碎片、动态分区有外部碎片；紧凑（拼接）必须**动态重定位**支持，静态重定位下无法移动程序
- 页式管理：逻辑地址 = 页号 + 页内偏移；$\text{物理地址} = \text{页框号} \times \text{页面大小} + \text{页内偏移}$
  - 页表项内容：页框号、状态位、访问位、修改位、外存地址——**没有页号字段**（页号按下标隐含）
  - 页面大小取 2 的幂（4KB → 偏移 12 位）；单级页表两大问题（页表需连续且大、必须常驻内存）→ 两级/多级页表（顶级页表常驻一张，**每级页表不超过一页**）
  - $n$ 级页表全命中时一次数据访问需 $n+1$ 次访存；快表 TLB 命中则不需访问内存中的页表
  - $EAT = a \cdot (t_{TLB} + t_M) + (1-a) \cdot (t_{TLB} + 2t_M)$（单级页表）；有 Cache 时再分层计算
- 段式管理与段页式管理
  - 段式：段表项含**段长与基址**；偏移 $\ge$ 段长 → 越界中断；按逻辑模块划分（二维地址：段号+段内偏移），**便于共享与保护**；分页按物理大小划分、对用户透明（一维地址）
  - 碎片对比：分页无外部碎片（最后一页有内部碎片）；分段无内部碎片（有外部碎片）
  - 段页式：先分段后分页，每段一张页表，地址 = 段号 + 页号 + 页内偏移，有**一次内部碎片**；不命中 TLB 时访存三次（段表、页表、数据）
  - 易错：段表项**含段长**（用于越界检查）；段页式对用户可见的是地址是"段号 + 段内偏移"（二维），页号在段内划分、对用户透明
- 虚拟内存管理：三特征 = **多次性、对换性、虚拟性**；理论基础是**局部性原理**（时间/空间局部性）
  - 请求页式页表项扩充：状态位/访问字段/修改位/外存地址；缺页流程：保留现场 → 查外存 → 分配页框 → 调入 → 改页表 → **重新执行被中断指令**
  - 缺页是**内中断中的"故障"（fault）**；一条指令可能触发多次缺页（多操作数跨页）
  - 虚拟内存最大容量由**地址结构位数**决定；实际容量 $\le \min(\text{内存}+\text{对换区},\ 2^{\text{地址位数}})$
- 页置换算法：OPT（不可实现，评价基准）· FIFO（有 Belady 异常）· LRU（堆栈类，无 Belady，硬件开销大）· CLOCK（访问位+循环指针）· 改进 CLOCK（按 (访问,修改) 优先淘汰 (0,0)→(0,1)）
  - 缺页率计算要把**首次调入算作缺页**；FIFO 页框增多缺页可能反而增多
  - 只有堆栈类算法（LRU/OPT）满足"增加页框数缺页次数必不增加"
- 【25新增】页框分配与回收
  - 分配策略：固定分配（每个进程页框数固定）vs 可变分配；局部置换 vs 全局置换——**全局置换只能配可变分配**，固定分配+全局置换不成立
  - 补充方式：预调页（一次调入多页，利用空间局部性）vs 请求调页（缺页才调）；调页时机与调页策略要配套选择
  - 回收时机与流程：进程结束、页被置换、内存紧张时回收 → 脏页先**写回外存**、更新页表项（有效位清 0）、页框加入**空闲页框链**/位示图
  - 易错：**全局置换只能配可变分配**；页框回收时脏页必须写回；"分配策略（给多少页框）、调页策略（何时调入）、置换算法（淘汰哪页）"三者的分工不要混
- 【25新增】页框分配与工作集、抖动的关系
  - 分配页框数 $<$ **工作集**大小 → **抖动（颠簸）**；工作集模型用窗口 $\Delta$ 内的访问页集合估算各进程实际需求
  - 改进方法：按工作集分配页框、挂起部分进程（降低多道程度）、选择合适的置换算法与页面大小
  - 易错：页面大小过大（内部碎片多、局部性差）或过小（页表大、缺页频繁）都会影响性能，不是越小越好
- 内存映射文件（memory-mapped files）
  - 原理：mmap 把文件的一段直接映射到进程虚拟地址空间，读写内存即读写文件，由**按需调页**自动把缺页从磁盘调入
  - 类型：共享映射（MAP_SHARED，修改对其他进程可见并回写文件，可用于**共享内存**）vs 私有映射（MAP_PRIVATE，写时复制，修改不回写）
  - 与 read/write 的区别与优势：省去用户缓冲区与内核缓冲区之间的**数据拷贝**与频繁系统调用，按页访问更灵活；也用于加载可执行文件与共享库
  - 易错：映射不改变文件大小，超出文件末尾的访问可能触发 SIGBUS；解除映射用 munmap
- 高频题型：地址变换数值题、缺页次数与缺页率手算题、EAT 计算、分页与分段对比简答

## 四、文件管理（笔记：第4章 文件管理）
- [📖 本章笔记](%E7%AC%94%E8%AE%B0/%E7%AC%AC4%E7%AB%A0%20%E6%96%87%E4%BB%B6%E7%AE%A1%E7%90%86.md) · [🧭 本章自查](%E5%A4%8D%E4%B9%A0%E8%87%AA%E6%9F%A5.md)
- 文件基本概念：文件是以名字为标识、逻辑上相关信息的集合；按用途/保护/存取方式/物理结构分类
  - 文件属性：名称、标识符、类型、位置、大小、保护、时间戳；所有文件信息（除文件名）都在 inode 中
  - 易错：文件"按逻辑结构"与"按物理结构"分类是两条独立线索，无结构文件（流式）也可以有连续/链接/索引等物理结构
- 文件元数据与索引结点 inode：目录项瘦身为 **文件名 + inode 号**，减少检索时的读盘量
  - 磁盘 inode vs 内存 inode（内存版增加：是否被打开、引用计数、是否修改未写回、文件锁等状态）；inode 用**多级索引**记录数据块位置
  - 易错：inode **不包含文件名**——"查找文件需几次访存"的关键；一个 inode 可被多个目录项（硬链接）指向，inode 中记录链接计数
- 文件的操作：建立（分配 inode 与目录项）、删除、打开（把 inode 复制进内存打开文件表，返回 fd）、关闭（释放 fd 与内存表项）、读、写
  - open 后 read/write 用 fd 定位，**不再需要路径解析**；系统级打开文件表（含 inode 副本、引用计数）vs 进程级（fd → 表项指针）
  - read 数据流向：磁盘 → 内核缓冲区 → 用户区；写则反向（用户区 → 内核缓冲区 → 按需写回磁盘）
  - 易错：多个进程可同时打开同一文件，系统级表只有一份表项、引用计数 $>1$，但各自有独立的读写位置（除非用 dup 或共享偏移）
- 文件的保护与共享：口令（最弱）· 加密 · 访问控制（ACL，按用户/组设 读/写/执行）
  - 硬链接（多目录项指向同一 inode，inode 共享计数；**不能跨文件系统、不能对目录**）vs 软链接/符号链接（新文件内容是被链路径，可跨文件系统，原文件删除后**悬空**）
  - 易错：硬链接删除原文件后只要计数 $>0$ 数据仍在；软链接不影响计数，且访问软链接要多一次"读链接文件内容"的开销
- 文件的逻辑结构：无结构（流式）与有结构
  - 顺序文件：串结构（按存入顺序）vs 顺序结构（按关键字）；定长记录支持随机存取，变长只能顺序检索；易错："顺序"指记录按某种次序排列，不等于只能顺序查找
  - 索引文件：为变长记录建索引表，索引表按关键字有序，支持快速随机检索；索引顺序文件：$N$ 条记录分 $\sqrt{N}$ 组，平均检索次数从 $N/2$ 降到 $\sqrt{N}/2$
- 文件的物理结构：连续分配 · 隐式链接（块内放指针，只能顺序存取、可靠性差）· 显式链接 FAT（指针集中在内存 FAT 表，支持随机存取但占内存）· 索引分配
  - 索引分配大文件三方案：链接方案（索引块串起来）· 多层索引（二级/三级）· 混合索引（UNIX：10 直接 + 1 一级 + 1 二级 + 1 三级）
  - 计算：4KB 块、4B 地址 → 一个索引块可索引 $1024 \times 4\text{KB} = 4\text{MB}$，二级 $4\text{GB}$，三级 $4\text{TB}$
  - 易错：题目不给"10 个直接块"就按通用多层索引算；"10 直接块"属 UNIX 约定
- 目录：FCB 组成 · 单级/两级/树形（绝对路径、相对路径、当前目录减少解析开销）· 无环图目录（实现共享，带共享计数）
  - 目录操作：创建、删除、检索（按名查找/线性检索）、列出、重命名、建立/删除链接
  - 易错：树形目录不便共享 → 无环图目录；两级目录的作用是"允许用户重名 + 提高检索速度"，不是共享
  - 路径解析访存：读目录项 → 读 inode → 读数据块；目录项瘦身后每次查目录读的盘块数大幅减少
- 文件系统全局结构 layout：外存中的结构（引导块、超级块、inode 区、数据区）· 内存中的结构（超级块副本、inode 副本、目录项缓存、打开文件表）
  - 格式化：物理格式化（划分扇区、检测坏扇区）与逻辑格式化（建立文件系统元数据）；引导块负责找到并加载 OS
  - 易错：超级块描述文件系统的整体信息（空闲块数、inode 数、块大小等），必须**先读入内存**才能操作文件系统；引导块位于分区起始且内容为引导程序
- 外存空闲空间管理：空闲表法（连续分配）· 空闲链表法（盘块链/盘区链）· **位图法**（盘块号 = 字号 $\times$ 字长 + 位号）· **成组链接法**（UNIX：空闲盘块号栈，栈底块记录下一组）
  - 易错：位图换算注意题目给的字长（16 位/32 位）；成组链接法栈满要压栈新组、只剩 1 项时该项指向下一组空块号块
  - 对比：位图法适合大文件系统且支持随机查找空闲块；成组链接法兼顾空闲块号栈常驻内存与快速分配
- 【22增】虚拟文件系统与挂载
  - VFS：统一不同文件系统的接口，向上提供一致的系统调用；四个对象 = 超级块 superblock、索引结点 inode、目录项 dentry、文件 file
  - 挂载 mounting：把新文件系统挂到某个目录（挂载点），VFS 在挂载点用一个 dentry 覆盖原目录并指向新文件系统的根，卸载时还原
  - 易错：VFS 不是一种实际文件系统而是抽象层；挂载点原目录内容在挂载期间不可见
- 高频题型：物理结构容量计算（一级/二级/三级索引）、"访问某逻辑块需几次访存"、位示图盘块号换算、inode 与目录项辨析

## 五、输入输出管理（笔记：第5章 输入输出管理）
- [📖 本章笔记](%E7%AC%94%E8%AE%B0/%E7%AC%AC5%E7%AB%A0%20%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA%E7%AE%A1%E7%90%86.md) · [🧭 本章自查](%E5%A4%8D%E4%B9%A0%E8%87%AA%E6%9F%A5.md)
- I/O 设备与接口：按传输速率/信息交换单位（块设备、字符设备）/共享属性（独占、共享、虚拟）分类
  - I/O 接口三类寄存器：数据、状态、控制；端口编址：统一编址（内存映射，用普通访存指令）vs 独立编址（专用 IN/OUT 指令）
  - 易错：统一编址占用内存地址空间但不需要专用指令；独立编址不占内存空间但需专用指令；I/O 接口中数据寄存器可读可写、状态寄存器通常只读
- I/O 控制方式：程序直接控制（轮询忙等，CPU 利用率最低）→ 中断驱动（**每字**一次中断，数据仍经 CPU）→ DMA（**每块**一次中断，数据直接设备↔内存）
  - DMA 控制器组成：CR、MAR、DAR、DC；三阶段 = 预处理 → 数据传送 → 后处理（以中断方式通知 CPU）
  - 易错：DMA 响应"存取周期结束"，中断响应"指令周期结束"；通道方式可控制多台设备、进一步减少 CPU 干预；DMA 传送时 CPU 仍可访存（周期挪用/交替访存）
- I/O 软件层次结构（自上而下）：用户层 I/O 软件 → **设备独立软件** → 设备驱动程序 → 中断处理程序 → 硬件
  - 设备独立软件职责：系统调用接口、设备保护、命名与映射（逻辑设备名→物理设备）、缓冲、分配与回收、差错控制、逻辑设备表 LUT
  - 常考归类："read() 调用 → 用户层；设备名解析 → 设备独立层；写控制器寄存器 → 驱动程序；响应中断 → 中断处理程序"
  - 易错：**中断处理程序在最底层**（紧贴硬件），设备驱动程序在其上；"设备独立性"意味着换设备只要换驱动、上层程序不变
- 【22增】输入输出应用程序接口
  - 字符设备接口：以字节流为单位、通常**不可寻址**、常配缓冲；用 get/put 类操作，适合键盘、打印机
  - 块设备接口：以块为单位、**可随机寻址**（seek/read/write），适合磁盘，是文件系统的基石
  - 网络设备接口：不通过设备文件，用 socket 抽象（socket/bind/connect/send/recv），与文件 I/O 语义不同
  - 阻塞 I/O（调用后进程睡眠直到完成）vs 非阻塞 I/O（立即返回，用轮询/多路复用检查）；同步 I/O（调用者参与等待）与异步 I/O（内核完成后通知，调用者不阻塞）
- 【22增】输入输出应用程序接口：设备文件与调用约定
  - 设备文件与系统调用接口：以文件方式访问设备，open/read/write/ioctl 统一入口；fcntl 可设置 O_NONBLOCK 切换阻塞/非阻塞
  - 易错：非阻塞 I/O ≠ 异步 I/O——非阻塞只是"立即返回未就绪"，数据拷贝阶段往往仍是同步的；字符设备不提供随机寻址
- 缓冲区管理：单缓冲每块 $\max(C, T) + M$ · 双缓冲 $\max(C + M, T)$ · 循环缓冲 · 缓冲池（公用、在主存）
  - 设输入耗时 $T$、传送耗时 $M$、处理耗时 $C$；双缓冲可让输入与处理并行，实现"设备与设备并行"
  - 易错：单缓冲公式里传送 $M$ 必须串行插入；循环缓冲有 nextg/nexti/current 三个指针；缓冲的作用是缓和 CPU 与 I/O 速度矛盾、减少中断频率、提高并行度
- 设备分配与回收：数据结构 DCT（设备控制表）→ COCT（控制器控制表）→ CHCT（通道控制表）→ SDT；分配的安全方式（发出请求即阻塞）与不安全方式
  - 设备独立性：用户程序用逻辑设备名，LUT 完成逻辑设备 → 物理设备映射；分配原则：充分发挥设备效率、避免死锁、考虑设备特性
  - 易错：独占设备只能静态分配、共享设备可动态分配；先分配设备再分配控制器、通道，回收顺序相反；SPOOLing 是**虚拟设备技术**，井在磁盘、缓冲区在内存
- SPOOLing（假脱机）：输入井/输出井（**磁盘**）+ 输入/输出缓冲区（**内存**）+ 输入/输出进程；**用共享设备模拟独占设备**（如打印机），宏观上多进程"同时"打印、微观串行
  - 易错：SPOOLing 是**虚拟设备技术**，井在磁盘、缓冲区在内存，不要把两者的位置说反；它需要多道程序设计技术支持（否则无进程可切换）
- 设备驱动程序接口：驱动程序屏蔽设备差异，向上提供统一的 read/write/ioctl 入口；与硬件交互、完成寄存器级操作与中断处理
  - 驱动程序通常由设备厂商提供并动态加载；设备独立软件通过函数指针表（设备开关表）调用具体驱动
  - 易错：驱动程序属于**内核态**代码；同一类设备可换驱动而不改上层软件，这正是"设备无关性"的体现
- 外存管理：磁盘结构与读取时间
  - 磁盘结构：盘面、磁道、扇区、柱面；磁盘地址 = 柱面号 + 磁头号 + 扇区号；**同一柱面的各磁道**一次寻道后可连续读写
  - 格式化：低级格式化（划分扇区、检测坏块）· 分区 · 逻辑格式化（建立文件系统元数据）
  - $\text{读取时间} = \text{寻道时间} + \text{旋转延迟} + \text{传输时间}$；平均旋转延迟 = 半圈 = $\frac{1}{2} \times \frac{60}{r}\,\text{s}$
  - 减少旋转延迟的优化：交替编号（相邻逻辑块物理上间隔）与错位命名（不同盘面起始位置错开）
- 外存管理：磁盘调度方法与坏块管理
  - 磁盘调度方法：FCFS · SSTF（会饥饿）· SCAN（扫到**边缘**才折返）· LOOK（到**最远请求**即折返）· C-SCAN/C-LOOK（回程不服务，等待时间更均匀）
  - 坏块管理：FAT 标记 / 备用扇区替换（扇区滑动）；引导块含 MBR 与引导控制块
  - 易错：SSTF 不一定总移动道数最少（贪心）；SCAN 的"边缘"是磁盘物理边界而非最远请求；磁头初始移动方向不同结果不同，题目没给方向要按题设
- 【22增】固态硬盘
  - 结构：由 Flash 芯片组成，读写单位是**页**、擦除单位是**块**（先擦后写：改写一页要先擦整块再写回，因此写比读慢得多）
  - FTL 闪存翻译层：把逻辑块地址映射到物理页，负责磨损均衡与垃圾回收，对上层伪装成普通块设备
  - 读写性能特性：**随机读快、随机写慢**（写入需擦除）、无寻道与旋转延迟；写放大（实际写入量大于请求量）、寿命受擦写次数限制
  - 【22增】TRIM 通知 SSD 哪些页已作废可提前回收；Garbage Collection 搬移有效页、整块擦除
- 【22增】固态硬盘：磨损均衡与对比
  - **磨损均衡**：动态（写入时才选块、实现简单）vs 静态（把冷数据也搬移，兼顾长期不动的块），使各块擦写次数接近以延长寿命
  - 与磁盘对比：无机械部件、抗震、延迟低、功耗小，但单位容量成本高、写寿命有限，适合随机读密集场景
  - 易错：磨损均衡 ≠ 垃圾回收；擦除单位（块）大于读写单位（页）是"写慢"的根源
- 高频题型：单/双缓冲时间计算、磁盘调度移动道数计算、中断屏蔽字设计、I/O 层次归类、"缓冲/SPOOLing/SSD"概念辨析
