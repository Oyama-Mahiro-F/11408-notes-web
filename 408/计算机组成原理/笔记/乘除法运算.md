<h2 align="center">乘除法运算</h2>

> 本文是《第 2 章 数据的表示和运算》的**专题拆解**，专攻**定点数的乘法与除法**——408 里唯一需要"动手演算"的运算部件内容（原码一位乘 / Booth / 阵列乘法器 / 恢复余数 / 加减交替），也是失分最集中的地方。文中每个演算表的每一步都可逐步复算，末尾附**官方"加减—移位次数"口径表**与**真题演练**。系统章节见 `第2章 数据的表示和计算.md`。

> **408 高频考点提醒**：
>
> **乘法**
> - 原码乘法**符号位不参加运算**（符号=两数符号**异或**、数值=绝对值相乘）；补码乘法**符号位参加运算、乘积符号自然形成**
> - 原码一位乘 = **n 次加法 + n 次移位**；补码（Booth）一位乘 = **n+1 次加法 + n 次移位**（最后一步只加不移位）
> - Booth 判据：看 $Y_iY_{i-1}$ 两位——`01` 加 X、`10` 减 X、`00`/`11` 只移位（**末位加 $y_{n+1}=0$**，算术右移）
> - 原码一位乘里"参与操作的是绝对值、移位用**逻辑移位**（补 0）、部分积至少 n+1 位"——三条都是易错判断点
> - 阵列乘法器：**与门并行产生部分积 + 全加器阵列压缩，一个时钟周期出结果**（Booth 与阵列的时间差是 2024 年真题考点）
> - 乘积位数：n 位数值位补码一位乘 → **2n+1 位**（含符号位）
>
> **除法**
> - 原码除法：符号位不参加（**异或**）；**先判商溢出**（定点小数须 $|X| < |Y|$）
> - 恢复余数法 vs 不恢复余数法（加减交替）：后者每步只需 **1 次加法**，**整个过程中从不恢复，只在最后一步余数为负时恢复一次**
> - 补码除法：符号位参与，**够不够减看"余数与除数是否同号"**（不是看余数正负！），第一位商即**商符**
> - 补码除法**末位恒置 1**，最大误差 $2^{-n}$；除不尽且商为负时末位 +1（反码→补码）
> - 一句话辨析：**串行乘法 = 多次累加 + 右移，串行除法 = 多次累加 + 左移**
>
> **实现方式**
> - 软件循环（移位—加法）最慢 → ALU+移位器（多个时钟周期）→ 阵列乘法器（一个时钟周期）最快（2024.15、2020.43）

### （一）两条前置：移位与补码加减

> **主线**：乘除法的一切机器实现都建立在"**加 + 移**"两个动作上——乘法是把 n 个部分积累加起来（配合右移），除法是把余数逐次试商（配合左移）。所以先把这两条地基夯实。

#### 一、移位运算（速览）

| <nobr>**类型**</nobr> | <nobr>**对象**</nobr> | <nobr>**左移补入**</nobr> | <nobr>**右移补入**</nobr> | <nobr>**在乘除中怎么用**</nobr> |
|:---|:---|:---|:---|:---|
| **算术移位** | 带符号数 | 补 0（补码） | 补**符号位** | Booth 的部分积右移（正数补 0、负数补 1） |
| **逻辑移位** | 无符号数 / 位串 | 补 0 | 补 0 | **原码一位乘**的部分积右移（绝对值无正负可言） |
| **循环移位** | 位串 | 移出位补回另一端 | 同左 | 字节内位操作（带进位时经 CF） |

> ⚠️ **不要弄反**：原码一位乘参与运算的是**真值的绝对值**，没有正负可言，所以移位一律是**逻辑移位（高位补 0）**；补码一位乘（Booth）是**带符号数**，移位是**算术右移**（符号位不动）。

#### 二、补码加减与溢出（速览）

- 加法：$[A+B]_补 = [A]_补 + [B]_补 \pmod{2^{n+1}}$，**符号位一起参与**，最高位进位丢弃。
- 减法：$[A-B]_补 = [A]_补 + [-B]_补$；求 $[-B]_补$ = 连同符号位**全部取反、末位 +1**。
- 溢出的三种判别（同号相加 / 异号相减才可能溢出）：单符号位法、$V = C_n \oplus C_{n-1}$、双符号位法（`01` 正溢出、`10` 负溢出）。

> **双符号位（变形补码）在乘除里的两处用途**：① Booth 的部分积用双符号位，容纳累加过程中的数值溢出；② 补码除法中被除数/余数与除数用双符号位，第一位商即可定出商符——这两处在后面会反复出现。

### （二）定点乘法运算

> **主线**：乘法 = **加 + 移位**。按"符号位怎么处理"分成两条线：**原码一位乘**（符号位异或、数值位取绝对值累加右移）和**补码一位乘 Booth**（符号位参与、按两位判据做加减）。最后是"不用迭代"的硬件方案——**阵列乘法器**。**一切结论都由"加法次数 / 移位次数 / 位数"三个量收口**，这也是选择题最爱的出题点。

#### 一、乘法运算的三种实现方式

| <nobr>**实现方式**</nobr> | <nobr>**硬件代价**</nobr> | <nobr>**时间**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|
| **① 软件循环实现** | 无（只要 ALU + 移位器） | **最长** | 编译器把乘法展开为"移位 + 加减"的循环代码；每条指令都要取指、译码、取数、执行、写回 |
| **② 一位乘（ALU + 移位器）** | 1 个加法器 + 移位寄存器 | 中等（**n+1 个时钟周期量级**） | 一条乘法指令完成，但要反复迭代 |
| **③ 阵列乘法器** | 与门阵列 + 全加器阵列 | **最短（一个时钟周期）** | 纯组合逻辑，用硬件面积换时间 |

> **2024.15 真题口径**：阵列乘法器**可在一个时钟周期完成**；ALU + 移位器的乘法**无法**在一个时钟周期内完成；变量与常数的乘法可编译优化为若干次移位及加减指令；**两个变量的乘法也可以**编译为"移位 + 加法"的循环实现（即①，所以说"无法"是错的）。
>
> **2020.43 大题口径**：a) 无乘法指令 → 软件循环，执行时间**最长**；b) 有 ALU + 移位器实现的乘法指令 → 一条指令但多周期；c) 有阵列乘法器实现的乘法指令 → **最短**。控制逻辑的作用是**控制循环次数、控制加法和移位操作**。

#### 二、原码一位乘法

##### 1. 三要素

> **符号位**：**不参加运算**。乘积符号 = $X_S \oplus Y_S$（**异或**：同号为正、异号为负）；数值部分 = **两数绝对值之积**，单独算完再把符号位拼上去。

$$
[X \times Y]_{原} = (X_S \oplus Y_S)\,(|X| \times |Y|)
$$

- **累加**：乘数最低位为 1，部分积加被乘数；为 0 则加 0。
- **右移**：每处理完一位，部分积与乘数**联合逻辑右移一位**（部分积最低位移入乘数的最高位）。
- **循环次数**：乘数有 **n 位数值位 → n 次加法 + n 次移位**。

##### 2. 完整演算（0.1101 × 0.1011）

**例**：$X = 0.1101$，$Y = 0.1011$，求 $X \times Y$。

设部分积寄存器 A（取**双符号位**，容纳累加时两小数相加可能出现的进位），乘数寄存器 C = 1011：

| <nobr>**步**</nobr> | <nobr>**操作**</nobr> | <nobr>**部分积 A**</nobr> | <nobr>**乘数 C**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|:---|
| — | 初值 | `00.0000` | `1011` | 部分积清零 |
| 1 | $C_0=1$ → 加 $|X|$ | `00.1101` | `1011` | `00.0000 + 00.1101` |
| 1 | 联合右移一位 | `00.0110` | `1101` | A 移出的 1 进入 C 最高位 |
| 2 | $C_0=1$ → 加 $|X|$ | `01.0011` | `1101` | `00.0110 + 00.1101`，产生了进位 |
| 2 | 联合右移一位 | `00.1001` | `1110` | 进位被"拉回"小数部分 |
| 3 | $C_0=0$ → 加 0 | `00.1001` | `1111` | 加 0，A 不变 |
| 3 | 联合右移一位 | `00.0100` | `1111` | |
| 4 | $C_0=1$ → 加 $|X|$ | `01.0001` | `1111` | `00.0100 + 00.1101` |
| 4 | 联合右移一位 | `00.1000` | `1111` | 4 次移位结束 |

**结果拼接**：符号位 $= 0 \oplus 0 = 0$（正）；数值位 = A 的小数部分 `1000` 拼接 C 的 `1111`：

$$
X \times Y = 0.10001111
$$

**验算**：$0.8125 \times 0.6875 = 0.55859375$，而 $0.10001111_2 = 143/256 = 0.55859375$ ✓

> 若 $Y = -0.1011$（符号 $Y_S=1$）：数值部分不变，符号位 $= 0 \oplus 1 = 1$，故 $X \times Y = -0.10001111$。

##### 3. 三条易错正解（选择题常考）

| <nobr>**常见错说**</nobr> | <nobr>**正确结论**</nobr> | <nobr>**理由**</nobr> |
|:---|:---|:---|
| "符号位不参加运算，**根据数值位的运算结果**确定结果符号" | ✗ 结果是**两符号位异或**定的 | 数值位是绝对值，算不出符号来 |
| "原码一位乘中**所有移位都是算术移位**" | ✗ 是**逻辑移位**（高位补 0） | 参与操作的是真值的绝对值，没有正负可言 |
| "部分积**至少需要 n 位**寄存器" | ✗ 至少 **n+1 位** | 两个小数部分积相加可能 ≥ 1，需要 1 位容进位（取双符号位则更多） |

> **原码两位乘**（拓展）：每次考虑乘数两位，参加操作的数是**绝对值的补码**（便于做 $\pm|X|$、$\pm 2|X|$ 的加减）。

#### 三、定点补码一位乘法（Booth 算法）

##### 1. 为什么补码乘法要"特殊处理"

补码乘法的目标是**符号位直接参与运算、乘积符号自然形成**（不再像原码那样单独异或）。但补码的负数形式 $[X]_补 = 1.x_1x_2\cdots x_n$ 对应真值 $-1 + 0.x_1x_2\cdots x_n$，不能像无符号数那样"逐位加 + 移位"直接累加。

Booth 算法的巧思：把乘数 $[Y]_补$ 按**相邻两位之差**展开，从而把"加被乘数"变成"加 / 减被乘数"的稀疏操作——**连续的 1 只做一次加减**。

##### 2. 判据（两种记法，同一规则）

| <nobr>**本位 $Y_i$**</nobr> | <nobr>**低位 $Y_{i-1}$**</nobr> | <nobr>**判断**</nobr> | <nobr>**操作**</nobr> |
|:---|:---|:---|:---|
| 0 | 0 | 连续 0，无变化 | 部分积**只右移一位** |
| 0 | 1 | **0→1（上升沿）** | 部分积 **$+[X]_补$**，再右移一位 |
| 1 | 0 | **1→0（下降沿）** | 部分积 **$+[-X]_补$**（即减 $[X]_补$），再右移一位 |
| 1 | 1 | 连续 1，无变化 | 部分积**只右移一位** |

> **记忆口诀**：**升加降减**（$Y_{i-1}\to Y_i$ 由 0 变 1 则加 X，由 1 变 0 则减 X）。
>
> **记法提示**：部分资料（含教材）写成 $(y_i,\,y_{i+1})$、用差值 $y_{i+1}-y_i$ 判正负，本质是同一规则——**看相邻两位是否变化、往哪个方向变**，不要被下标顺序绕晕。

##### 3. 基本约定

- **末尾增加附加位 $y_{n+1} = 0$**，与乘数最低位配成第一对判据。
- **符号位参与运算**：乘数 $1.0101$ 参与移位的串是 `10101`（含符号位），不是 `0101`。
- 部分积取**双符号位**；移位一律为**算术右移**。
- **最后一步只加（减）不移位**——所以加法总共 $n+1$ 次、移位 $n$ 次。

##### 4. 完整演算（−0.1101 × +0.1011）

**例**：$X = -0.1101$，$Y = +0.1011$，用 Booth 算法求 $X \times Y$。

准备：$[X]_补 = 11.0011$，$[-X]_补 = 00.1101$，$[Y]_补 = 0.1011$（乘数寄存器 `01011`），附加位 $y_5 = 0$。

| <nobr>**步**</nobr> | <nobr>**部分积（双符号位）**</nobr> | <nobr>**乘数寄存器**</nobr> | <nobr>**$y_5$**</nobr> | <nobr>**判据 $(y_4,y_5)$**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|:---|:---|
| — | `00.0000` | `01011` | 0 | 初始 | 部分积清零，附加位 0 |
| 1 | `00.1101` | `01011` | 0 | `10` → 减 X | `00.0000 + 00.1101`（$-X = +0.8125$） |
| 1 | `00.0110` | `10101` | 1 | 算术右移 | 部分积移出位 1 进乘数最高位 |
| 2 | `00.0110` | `10101` | 1 | `11` → 只移位 | 连续 1，不加 |
| 2 | `00.0011` | `01010` | 1 | 算术右移 | |
| 3 | `11.0110` | `01010` | 1 | `01` → 加 X | `00.0011 + 11.0011` |
| 3 | `11.1011` | `00101` | 0 | 算术右移 | 负数右移，高位补符号位 1 |
| 4 | `00.1000` | `00101` | 0 | `10` → 减 X | `11.1011 + 00.1101`（进位丢弃） |
| 4 | `00.0100` | `00010` | 1 | 算术右移 | |
| 5 | `11.0111` | `00010` | 1 | `01` → 加 X（**不移位**） | `00.0100 + 11.0011` |

**结果拼接**：$[X \times Y]_补$ = 部分积的小数部分 `0111` 拼接乘数寄存器高 4 位 `0001`：

$$
[X \times Y]_补 = 11.01110001
$$

**验算**：$X \times Y = -0.8125 \times 0.6875 = -0.55859375$；$11.01110001_补$ 的真值 $= -0.10001111_2 = -143/256$ ✓

##### 5. 教材版的两条规则（可互相印证）

- **乘数为正**（$Y_0=0$）：操作同原码乘（逐位加 |X| 再右移），但**加减与移位都按补码规则**，乘积符号自然形成。
- **乘数为负**（$Y_0=1$）：先去掉符号位按上一条操作，**最后再加 $[-X]_补$ 作校正**。

##### 6. 易错点清单

| <nobr>**易错**</nobr> | <nobr>**正解**</nobr> |
|:---|:---|
| 漏掉附加位，把乘数数值位当成判断串 | 末尾补 $y_{n+1}=0$，**符号位也参与移位** |
| 最后一步仍右移 | **最后一步只加不移位**（故加法 n+1 次、移位 n 次） |
| 把"减 X"当成加 $-0.1101$ 的原码 | 减 X 即**加上 $[-X]_补$**（全部位取反末位 +1） |
| 右移时高位补 0 | 部分积是带符号补码，**算术右移**：正数补 0、负数补 1 |
| 记成左移 | Booth 只有**右移**，不存在左移 |

#### 四、阵列乘法器（原码并行乘法）

##### 1. 从竖式到阵列

手工竖式乘法"每行部分积右移错位相加"，本质是 $(a_ib_j)$ 这些**位积**的按权重求和：

$$
P = \Big(\sum_{i} a_i 2^i\Big)\Big(\sum_{j} b_j 2^j\Big) = \sum_i \sum_j (a_ib_j)\,2^{i+j}
$$

于是：

- $m$ 位 × $n$ 位共产生 **$m \times n$ 个位积 $a_ib_j$**，可用 **$m \times n$ 个与门并行**地一瞬间产生；
- 这些位积按权重用**全加器（FA）/半加器阵列**逐级压缩求和 → 这就是**不带符号的阵列乘法器**。

```
        a3  a2  a1  a0      (被乘数 A)
      × b3  b2  b1  b0      (乘数 B)
      ──────────────────
        a3b0 a2b0 a1b0 a0b0     ← 与门并行产生第 0 行位积
     a3b1 a2b1 a1b1 a0b1
  a3b2 a2b2 a1b2 a0b2
a3b3 a2b3 a1b3 a0b3
───────────────────────────
p7  p6  p5  p4  p3  p2  p1  p0   ← 全加器阵列求和（进位向左传）
```

> 图：m 位 × n 位阵列乘法器的位积矩阵：每行由一个乘数位与被乘数**与门**并行产生，各行的和垂直向下传、进位水平向左传，经全加器阵列压缩成乘积。

##### 2. 时延与取舍

- 延迟由**最长进位链**决定，$n$ 位乘法约需 $2n-1$ 级全加器延迟，但**全部在一个时钟周期内完成**（组合逻辑）。
- 代价是**面积/成本**：器件数为 $O(n^2)$。这就是"**并行乘除法运算器通过牺牲硬件的代价换取运算速度**"的由来。
- 机器字长通常只有 n 位，而乘积可能 $2n$ 位（通常保留低 n 位）；只有两个输入端口的加法器难以一次相加 n 个位积，故用阵列逐级压缩。

##### 3. 带符号阵列乘法器：算前求补—相乘—算后求补

**流程**：输入补码 → ① **算前求补**（把操作数变成原码/绝对值）→ ② 用不带符号的阵列乘法器算数值部分 → ③ **算后求补**（结果若为负，再转回补码）。符号位由 $X_S \oplus Y_S$ 单独处理。

**求补电路规则**（一位符号控制端 E）：

- $E=0$：输入与输出**相同**（正数直接通过）。
- $E=1$：从数最右端往左扫描，**遇到第一个 1（含该位及其右边各位）保持不变，左边各数值位按位取反**（末尾加 1 的等价实现）。

> **示例（教材例）**：$x = +15$，$y = -13$，用带求补器的原码阵列乘法器求 $x \cdot y$。
> $[x]_原 = 01111$，$[y]_原 = 11101$，故 $|x| = 1111$，$|y| = 1101$，符号位 $0 \oplus 1 = 1$。
> 阵列算出 $1111 \times 1101 = 11000011$；结果为负 → 算后求补 → $[x \cdot y]_原 = 1\,11000011$，真值 $x \cdot y = -11000011_2 = -195$。

#### 五、乘积的位数与溢出判断

| <nobr>**情形**</nobr> | <nobr>**乘积位数**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|
| 两个 n 位（数值位）定点小数相乘 | 最多 **2n 位** | 原码相乘时 n 次加法 n 次移位 |
| **n 位数值位补码一位乘** | **2n+1 位**（含 1 位符号位） | 右移 n 次得 2n 位数值位，再加符号位（选择题考点） |
| 机器字长 n 位，只取乘积**低 n 位** | n 位 | 高位被丢弃 → **可能溢出** |

**取低 n 位时的溢出判断**：

| <nobr>**运算**</nobr> | <nobr>**不溢出的条件（看 2n 位乘积的高 n 位）**</nobr> |
|:---|:---|
| **无符号整数乘法** | 高 n 位**全为 0**（否则溢出） |
| **带符号整数乘法** | 高 n 位是**低 n 位最高位的符号扩展**（全 0 或全 1，否则溢出） |

> **2020.43 真题落点**：$n=32$、$x=2^{31}-1$、$y=2$ 时，带符号与无符号乘法指令得到的 **64 位乘积都是 `0000 0000 FFFF FFFEH`**；但 `int` 的范围是 $[-2^{31},\,2^{31}-1]$，故 **`imul()` 溢出**；`unsigned int` 的范围是 $[0,\,2^{32}-1]$，故 **`umul()` 不溢出**。无符号乘法取低 32 位时，**高 32 位全 0 即不溢出**。

### （三）定点除法运算

> **主线**：除法 = **减（试商）+ 移位**。它的困难不在算术，而在"**够不够减**"这个判断：原码除法看**余数的正负**，补码除法看**余数与除数是否同号**——这一条差别是整节最容易失分的地方。三条演进线：恢复余数法 → 不恢复余数法（加减交替，每步 1 次加法）→ 补码加减交替法（符号位参与、末位恒置 1）。

#### 一、除法总体框架

##### 1. 商与余数的关系

$$
D = Q \times d + R, \qquad 0 \leq R < d
$$

##### 2. 三条共同的"起手式"

| <nobr>**问题**</nobr> | <nobr>**规则**</nobr> |
|:---|:---|
| **商的符号** | **原码除法**：符号位不参加运算，商符 = 两数符号**异或**（半加和）<br>**补码除法**：符号位参加运算，**商符即第一位商**（在运算中自然形成） |
| **商溢出** | **定点小数除法必须先比较 $|X|$ 与 $|Y|$**：只有 $|X| < |Y|$ 商才不溢出（否则商 ≥ 1，超出定点小数范围） |
| **寄存器组织** | 被除数的位数可以是除数的**两倍**，低位部分一开始放在商寄存器中；运算过程中**被除数/余数寄存器与商寄存器联合左移一位** |

> ⚠️ **"串行除法 = 多次累加 + 左移"**：注意方向与乘法相反——**乘法是右移（乘数逐位从低位消耗），除法是左移（余数逐次放大、商逐位从低位挤入）**。选择题专设此类比较（例：串行乘法"多次累加和左移"的说法是错的）。

#### 二、原码一位除法：恢复余数法

##### 1. 规则（不够减则恢复）

- **符号位不参加运算**；数值部分用**绝对值**相除。
- 每轮：余数**左移一位**（等价于 ×2）→ 减除数 → 看余数：
  - **够减（余数 ≥ 0）**：商 **1**，保留新余数；
  - **不够减（余数 < 0）**：商 **0**，**把除数加回去（恢复原余数）**。
- 缺点：不够减时要多做一次加法，**每步需要 1~2 次加法**，速度慢。

##### 2. 完整演算（教材例：$X = 0.1011$，$Y = 0.1101$）

$|Y| = 0.1101$，$[-|Y|]_{补} = 1.0011$；余数寄存器取**双符号位**。

| <nobr>**步**</nobr> | <nobr>**操作**</nobr> | <nobr>**余数（值）**</nobr> | <nobr>**商**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|:---|
| — | 初值 | `0.1011` (0.6875) | — | 被除数送入余数寄存器 |
| 1 | 左移后减 $|Y|$ | `0.1001` (0.5625) | 1 | $1.0110 + 1.0011 = 10.1001$，≥ 0 → 够减 |
| 2 | 左移后减 $|Y|$ | `0.0101` (0.3125) | 1 | $1.0010 + 1.0011 = 10.0101$，≥ 0 → 够减 |
| 3 | 左移后减 $|Y|$ | `1.1101` (−0.1875) | 0 | $0.1010 + 1.0011 = 1.1101$，< 0 → 不够减 |
| 3' | **恢复**（加回 $|Y|$） | `0.1010` (0.625) | 0 | $1.1101 + 0.1101 = 10.1010$ |
| 4 | 左移后减 $|Y|$ | `0.0111` (0.4375) | 1 | $1.0100 + 1.0011 = 10.0111$，≥ 0 → 够减 |

**结果**：商 $= 0.1101$；余数 $= 0.0111 \times 2^{-4} = 0.00000111$（第 3 步"多一次加法"就是恢复余数的代价）。

**验算**：$Q \times Y = 0.1101 \times 0.1101 = 0.66015625$，余数 $= 0.4375 \times 2^{-4} = 0.02734375$，两者之和 $= 0.6875 = X$ ✓（真值 $X/Y = 0.84615\ldots$，4 位商的误差在 $2^{-4}$ 内）

#### 三、原码一位除法：不恢复余数法（加减交替法）

##### 1. 为什么可以"不恢复"

恢复余数法在 $R<0$ 时的动作是"先 $+d$ 恢复、再左移、再 $-d$"，合并后为：

$$
2(R + d) - d = 2R + d
$$

而"不恢复"版本**直接算 $2R + d$**，结果完全相同，却省掉了一次加法——这就是**加减交替**的由来。

##### 2. 规则（加减交替）

| <nobr>**当前余数**</nobr> | <nobr>**上商**</nobr> | <nobr>**下一轮操作（先左移）**</nobr> |
|:---|:---|:---|
| $R \geq 0$（够减） | 1 | 减除数：$2R - d$ |
| $R < 0$（不够减） | 0 | **加**除数：$2R + d$ |

> **教材口径**：① 符号位不参加运算；② 余数为正商 1，正余数左移一位再减除数；③ 余数为负商 0，负余数左移一位再**加**除数。整个过程中**从不恢复**。

##### 3. 完整演算（同一组数据）

| <nobr>**步**</nobr> | <nobr>**上一轮商**</nobr> | <nobr>**操作**</nobr> | <nobr>**余数（值）**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|:---|
| — | — | 初值 | `0.1011` (0.6875) | |
| 1 | — | 左移后减 $|Y|$ | `0.1001` (0.5625) | 商 1（$\geq 0$） |
| 2 | 1 | 左移后减 $|Y|$ | `0.0101` (0.3125) | 商 1（$\geq 0$） |
| 3 | 1 | 左移后减 $|Y|$ | `1.1101` (−0.1875) | 商 0（$<0$，**不恢复**） |
| 4 | 0 | 左移后**加** $|Y|$ | `0.0111` (0.4375) | 商 1（$\geq 0$） |

**结果**：商 $= 0.1101$（与原码恢复余数法完全一致）、余数 $= 0.0111 \times 2^{-4}$——**加法只做了 4 次**（恢复余数法要 5 次）。

##### 4. 最后一步：唯一一次"恢复"

**当第 n+1 步余数为负时，需加上 $|Y|$ 得到正确的余数**（余数与被除数同号）。所以准确的说法是：

> 不恢复余数法**整个过程中从不恢复余数，只在最终余数为负时恢复一次**（选择题原话）。

#### 四、定点补码一位除法（加减交替法）

##### 1. 规则（符号位参与、末位恒置 1）

**（1）符号位参与运算，商符自然形成**

| <nobr>**第一步：被除数与除数**</nobr> | <nobr>**操作**</nobr> |
|:---|:---|
| **同号** | 做**减法**（被除数 − 除数） |
| **异号** | 做**加法**（被除数 + 除数） |

做完后看"余数与除数"的关系上商：**同号商 1、异号商 0**，**这一位商就是结果的符号位（商符）**。

**（2）求商的数值部分**

| <nobr>**余数与除数**</nobr> | <nobr>**上商**</nobr> | <nobr>**下一轮操作（先左移）**</nobr> |
|:---|:---|:---|
| **同号**（够减） | 1 | 减除数 |
| **异号**（不够减） | 0 | 加除数 |

> ⚠️ **与原码除法的根本区别**：原码除法"够不够减"看**余数的正负**（≥0 够减）；补码除法看**余数与除数是否同号**。不要混用！
>
> **等价记忆**：上商 0 的条件 = **余数与除数异号**。

**（3）商的修正**

- 精度要求不高时：**末位恒置 1**，最大误差 $|2^{-n}|$。
- 精度要求高时：按规则（2）**再做一次操作**求第 n 位；除不尽时若商为负，**末位 +1**（使商由反码变补码）；若除尽且除数为负，末位 +1。

##### 2. 完整演算

**例**：机器字长 5 位（1 位符号位 + 4 位数值位），$x = +0.1000$，$y = -0.1011$，用补码加减交替除法求 $x / y$。

准备：$[x]_补 = 00.1000$，$[y]_补 = 11.0101$，$[-y]_补 = 00.1011$；余数与除数取**双符号位**。

| <nobr>**步骤**</nobr> | <nobr>**余数（ACC）**</nobr> | <nobr>**商（MQ）**</nobr> | <nobr>**说明**</nobr> |
|:---|:---|:---|:---|
| 初值 | `001000` (00.1000) | `00000` | 被除数正、除数负 → **异号做加法** |
| $+[y]_补$ | `111101` (11.1101) | `00001` | 余数 11.1101 与除数 11.0101 **同号** → 商 **1**（**此位即商符**） |
| 左移 | `111010` (11.1010) | `00010` | 同号 → 下一步**减**除数 |
| $+[-y]_补$ | `000101` (00.0101) | `00010` | 余数与除数**异号** → 商 **0** |
| 左移 | `001010` (00.1010) | `00100` | 异号 → 下一步**加**除数 |
| $+[y]_补$ | `111111` (11.1111) | `00101` | 与除数**同号** → 商 **1** |
| 左移 | `111110` (11.1110) | `01010` | 同号 → 下一步**减**除数 |
| $+[-y]_补$ | `001001` (00.1001) | `01010` | 与除数**异号** → 商 **0** |
| 左移 | `010010` (01.0010) | `10100` | 异号 → 下一步**加**除数 |
| $+[y]_补$ | `000111` (00.0111) | `10101` | 末位商**恒置 1** |

**结果**：$[x / y]_补 = 1.0101$，即 $x / y = -0.1011$（真值 $-0.6875$）。

**精度验算**：真值 $x/y = 0.5 \div (-0.6875) = -0.72727\ldots$，误差 $|0.72727 - 0.6875| = 0.0398 < 2^{-4} = 0.0625$ ✓（**末位恒置 1 换来的就是这个误差上界**）

**余数验算**：$x - Q \times y = 0.5 - (-0.6875) \times (-0.6875) = 0.0273 = 0.0111 \times 2^{-4}$ ✓

##### 3. 硬件视角

```
  ACC (remainder, 双符号位)  |  MQ (quotient)
  ┌──┬──┬──┬──┬──┬──┐        ┌──┬──┬──┬──┬──┐
  │  │  │  │  │  │  │  ←──   │  │  │  │  │  │
  └──┴──┴──┴──┴──┴──┘        └──┴──┴──┴──┴──┘
        joint shift left  ←──  quotient bit enters at MQ low end
        ACC ± [y]补  (sign of ACC vs sign of y decides next op)
```

> 图：补码加减交替除法的硬件组织：余数寄存器 ACC 与商寄存器 MQ **联合左移**，每轮由"ACC 与除数的符号是否相同"决定商 1/0 与 加/减 $[y]_补$。

#### 五、原码除与补码除对比

| <nobr>**维度**</nobr> | <nobr>**原码除法**</nobr> | <nobr>**补码除法**</nobr> |
|:---|:---|:---|
| **符号处理** | 不参加运算（符号位异或得商符） | **参加运算**，符号位与数值位一起加减/移位 |
| **商符形成** | 运算前由异或确定 | **第一位商即商符**，运算中自然形成 |
| **参加操作的数** | 绝对值（的补码） | **补码** |
| **够不够减的判据** | 余数**正负**（≥ 0 够减） | 余数与除数**是否同号**（同号够减） |
| **上商规则** | 够减 1、不够减 0 | 同号 1、异号 0 |
| **末位处理** | 正常上商 | **恒置 1**（误差 ≤ $2^{-n}$） |
| **最终余数** | 必为正；仅最后一步不够减时恢复一次 | 若为负需加除数恢复为正 |
| **适用** | 原码运算器 | 补码运算器（现代计算机主流） |

#### 六、加法与移位次数小结

| <nobr>**运算**</nobr> | <nobr>**加减运算次数**</nobr> | <nobr>**移位次数**</nobr> | <nobr>**备注**</nobr> |
|:---|:---|:---|:---|
| 原码一位乘法 | $n$ | $n$ | 乘数最低位为 0 时不加 |
| **补码一位乘法（Booth）** | $n+1$ | $n$ | 最后一步只加不移位 |
| 原码除法（恢复余数） | $n+1 \sim 2n$ | $n$ | 每步不够减要加回 |
| 原码除法（不恢复余数） | $n+1$ 或 $n+2$ | $n$ | 末步余数为负再恢复一次 |
| **补码除法（加减交替）** | $n+1$ | $n$ | 含第一步定商符的加减 |

> **n = 数值位位数**。上表是官方口径（《题型精练》2.2.2 第 14 题）：**补码一位乘 = n+1 次加法 + n 次移位 = 2n+1 个时钟周期**（若每次加法与移位各占 1 个时钟周期，32 位补码一位乘最多 65 个周期）。

#### 一、判断题式易错清单

| <nobr>**命题**</nobr> | <nobr>**判定**</nobr> | <nobr>**理由**</nobr> |
|:---|:---|:---|
| 原码乘法中符号位与数值位分开运算，结果符号由两符号异或得到 | **✔** | 原码一位乘的标准做法 |
| 原码一位乘中所有移位都是算术移位 | **✘** | 参与操作的是**绝对值**，没有正负可言 → **逻辑移位**（高位补 0） |
| 原码一位乘的部分积至少需要 n 位寄存器 | **✘** | 至少 **n+1 位**——两小数相加可能 ≥ 1 |
| 补码一位乘中符号位不参加运算 | **✘** | 补码乘**符号位参加**，且乘数符号位也参与移位（如 `1.0101` 参与移位的是 `10101`） |
| 补码一位乘的最后一步仍要右移 | **✘** | **最后一步只加不移位** |
| N 位（不含符号位）补码一位乘，乘积为 N 位 | **✘** | 共 **2N+1 位**（2N 位数值位 + 1 位符号位） |
| 补码一位乘中，判据 $Y_nY_{n+1}=01$ 时"加 $[X]_补$ 后右移一位" | **✔** | 上升沿加 X、下降沿减 X；**一定是右移**，不存在左移 |
| 原码除法的符号位参加运算 | **✘** | 原码除法符号位**不参加**，商符由两数符号异或得到 |
| 原码不恢复余数法中，余数为负就要恢复余数 | **✘** | 负余数**不恢复**，左移后改为**加除数**；仅**最终**余数为负时恢复一次 |
| 补码除法中"够减"的判断依据是余数的正负 | **✘** | 看**余数与除数是否同号**（同号够减），不是看余数正负 |
| 补码除法中，余数与除数同号商 1、异号商 0 | **✔** | 即"上商 0 的条件是余数与除数异号" |
| 补码加减交替除法中参加操作的数是绝对值的补码，商符由异或形成 | **✘** | 参加操作的是**补码**（符号位参与）；**商符在运算中自然形成** |
| 串行乘法通过多次累加和右移实现，串行除法通过多次累加和左移实现 | **✔** | 乘法消耗乘数低位（右移），除法放大余数（左移） |
| 并行乘除法运算器通过牺牲硬件代价换取运算速度提高 | **✔** | 阵列乘法器就是"面积换时间" |
| 阵列乘法器实现乘法可以在一个时钟周期完成 | **✔** | 纯组合逻辑（2024 真题） |
| 两个变量的乘法无法编译为移位及加法等指令的循环实现 | **✘** | 可以（移位—加法乘法算法的循环） |

#### 二、判据速查

| <nobr>**要判断的事**</nobr> | <nobr>**口诀 / 判据**</nobr> |
|:---|:---|
| 原码乘除的符号位 | **不参加运算**，符号 = 两数符号**异或** |
| 补码乘除的符号位 | **参加运算**，乘积符号自然形成 / 商符即第一位商 |
| 原码一位乘的移位 | **逻辑移位**（补 0） |
| Booth 的移位 | **算术右移**（正数补 0、负数补 1） |
| Booth 判据 | 看 $(Y_i, Y_{i-1})$：**01 加 X、10 减 X、00/11 只移位**（升加降减） |
| Booth 的附加位 | 末尾补 $y_{n+1}=0$，**符号位参与移位**，**最后一步不移位** |
| 除法"够减"（原码） | 余数 **≥ 0** |
| 除法"够减"（补码） | 余数与除数**同号** |
| 除法上商 | 够减 1、不够减 0（补码：同号 1、异号 0） |
| 补码除法的末位 | **恒置 1**，最大误差 $2^{-n}$ |
| 除法第一步 | 同号**减**除数、异号**加**除数（定商符） |
| 加减 / 移位次数 | 原码乘 n 加 n 移；Booth **n+1 加 n 移**；原码除 n+1（或 n+2）加 n 移；补码除 n+1 加 n 移 |
| 乘积位数 | n 位数值位补码一位乘 → **2n+1 位** |
| 阵列乘法器 | 与门产生位积 + 全加器阵列压缩，**1 个时钟周期** |
| 带符号阵列乘法器 | **算前求补 → 相乘 → 算后求补** |

#### 三、真题演练

**（1）【2024.15】下列关于整数乘法运算的叙述中，错误的是（　）**

> A. 用阵列乘法器实现乘运算可以在一个时钟周期完成
> B. 用 ALU 和移位器实现的乘运算无法在一个时钟周期内完成
> C. 变量与常数的乘运算可编译优化为若干次移位及加减运算指令
> D. 两个变量的乘运算无法编译为移位及加法等指令的循环实现

**答案：D**

> **要点**：除法器和乘法器都可用阵列（并行）方式实现"面积换时间"（A ✔）；ALU + 移位器实现的乘法需要多次"加 + 移"迭代，多周期（B ✔）；乘常数可展开为移位与加减（C ✔）；**两个变量**的乘法同样可以编译为"移位—加法乘法算法"的循环实现（D ✘）。

**（2）【2020.43】有实现 $x \times y$ 的两个 C 语言函数**：

```c
unsigned umul(unsigned x, unsigned y) { return x * y; }
int      imul(int x, int y)            { return x * y; }
```

假定某计算机 M 中 ALU 只能进行加减运算和逻辑运算：

| <nobr>**问题**</nobr> | <nobr>**答案要点**</nobr> |
|:---|:---|
| ① 没有乘法指令时，能否实现这两个函数中的乘法？为什么 | **能**。编译器把乘法转换为**循环代码段**，通过**比较、加法和移位**等指令实现乘法运算 |
| ② 有乘法指令时，控制逻辑的作用是什么 | **控制循环次数，控制加法和移位操作** |
| ③ 三种情况下 `umul()` 执行时间排序 | a) 无乘法指令**最长**（软件循环，每条指令都要取指、译码、取数、执行、写回）；c) 阵列乘法器**最短**（一个时钟周期） |
| ④ $n=32$、$x=2^{31}-1$、$y=2$ 时的溢出判断 | 带符号与无符号指令得到的 **64 位乘积都是 `0000 0000 FFFF FFFEH`**；`imul()` 的 `int` 范围是 $[-2^{31},\,2^{31}-1]$ → **溢出**；`umul()` 的 `unsigned int` 范围是 $[0,\,2^{32}-1]$ → **不溢出** |

> **④ 的口径（写进结论）**：无符号整数乘法只取乘积低 n 位时，**2n 位乘积的高 n 位全为 0 即不溢出**，否则溢出；带符号整数同理，判据是"高 n 位为低 n 位最高位的符号扩展"。

### （五）小结

**知识结构图**：

```
乘除法运算
│
├── （一）前置：移位与补码加减
│   ├── 算术移位（右移补符号位）／逻辑移位（补 0）／循环移位
│   └── 补码加减 + 溢出三判（单符号位 / Cₙ⊕Cₙ₋₁ / 双符号位 01 正溢 10 负溢）
│
├── （二）乘法
│   ├── 三种实现方式
│   │   ├── 软件循环（移位—加法）→ 最慢（2020.43）
│   │   ├── 一位乘（ALU + 移位器）→ n+1 个时钟周期量级
│   │   └── 阵列乘法器（与门 + 全加器阵列）→ 一个时钟周期（2024.15）
│   ├── 原码一位乘
│   │   ├── 符号位不参加、符号异或；数值 = 绝对值之积
│   │   ├── n 次加法 + n 次移位；**逻辑右移**；部分积至少 n+1 位
│   │   └── 完整演算 0.1101 × 0.1011 = 0.10001111
│   ├── 补码一位乘（Booth）
│   │   ├── 符号位参加、乘积符号自然形成；末尾补 yₙ₊₁=0
│   │   ├── 判据 (Yᵢ, Yᵢ₋₁)：01 加 X、10 减 X、00/11 只移位（升加降减）
│   │   ├── 算术右移；最后一步只加不移 → n+1 次加法 + n 次移位
│   │   └── 完整演算 (−0.1101) × (+0.1011) → [X·Y]补 = 11.01110001
│   ├── 阵列乘法器
│   │   ├── m×n 个与门并行产生位积 + 全加器阵列压缩；延迟 ∝ 最长进位链
│   │   └── 带符号：算前求补 → 相乘 → 算后求补（求补电路：E=1 时右起第一个 1 及其右侧不变、左侧取反）
│   └── 位数与溢出：n 位补码一位乘 → 2n+1 位；取低 n 位判溢（无符号看高 n 位是否全 0；有符号看是否符号扩展）
│
├── （三）除法
│   ├── 共同起手式：商符（原码异或 / 补码第一位商）、**先判商溢出 |X|<|Y|**、[R|Q] 联合左移
│   ├── 原码恢复余数法：左移 → 减除数 → 够减商 1、不够减商 0 并**恢复余数**（每步 1~2 次加法）
│   ├── 原码不恢复余数法（加减交替）：2R−d ≥ 0 商 1 下一步减；< 0 商 0 下一步加；**仅最后一步恢复一次**
│   ├── 补码加减交替除法
│   │   ├── 第一步：同号减、异号加；上商看"余数与除数同号/异号"，**该位即商符**
│   │   ├── 之后：同号商 1 减、异号商 0 加
│   │   ├── **末位恒置 1**，最大误差 2^−n；高精度可再做一次求第 n 位
│   │   └── 完整演算 (+0.1000) ÷ (−0.1011) → 商 −0.1011（ACC/MQ 表）
│   └── 次数小结：原码除 n+1 或 n+2 次加减、n 次移位；补码除 n+1 次加减、n 次移位
│
└── （四）考点速查：判断题清单 + 判据口诀 + 真题（2024.15 / 2020.43）
```

**高频考点速记**：

| 考点 | 一句话记忆 |
|:---|:---|
| 原码乘除符号 | 符号位**不参加**运算，符号 = 两数符号**异或**（同号正、异号负） |
| 补码乘除符号 | 符号位**参加**运算，乘积符号自然形成、商符即第一位商 |
| 原码一位乘三要素 | 符号异或 + 绝对值相乘 + **累加右移**（逻辑移位） |
| 原码一位乘次数 | **n 次加法 + n 次移位**（n 为数值位位数） |
| 部分积位数 | 原码一位乘部分积**至少 n+1 位**（取双符号位更多），防两小数相加 ≥ 1 |
| Booth 判据 | (Yᵢ, Yᵢ₋₁)：`01` 加 X、`10` 减 X、`00`/`11` 只移位——**升加降减** |
| Booth 三条约定 | 末尾补 **yₙ₊₁ = 0**；符号位参与移位；**最后一步只加不移位** |
| Booth 次数与周期 | **n+1 次加法 + n 次移位 = 2n+1 个时钟周期**（32 位 → 最多 65） |
| Booth 移位类型 | **算术右移**（正数补 0、负数补 1），部分积取双符号位 |
| 补码乘的位数 | n 位数值位 → 乘积 **2n+1 位**（含 1 位符号位） |
| 乘数符号的处理 | 乘数为正：同原码乘；乘数为负：去掉符号位照做，**最后加 [−X]补 校正** |
| 阵列乘法器 | 与门并行产生 m×n 个位积 + 全加器阵列压缩 → **一个时钟周期**，面积换时间 |
| 带符号阵列乘法器 | **算前求补 → 无符号阵列相乘 → 算后求补**；符号位单独异或 |
| 求补电路规则 | E=0 直通；E=1 时**右起第一个 1 及其右侧保持不变，左侧各位取反** |
| 乘法溢出判断 | 取低 n 位：无符号看高 n 位是否**全 0**；有符号看高 n 位是否**符号扩展** |
| 除法起手式 | 商符：原码异或 / 补码第一位商；**定点小数先判 $|X| < |Y|$**（商溢出） |
| 恢复余数法 | 左移后减除数；不够减则**加回除数恢复**，每步 1~2 次加法 |
| 不恢复余数法 | 2R−d ≥ 0 商 1 下一步减；< 0 商 0 下一步加；**仅最后一步恢复一次** |
| 不恢复的原理 | $2(R+d)-d = 2R+d$：把"恢复 + 下一步减"合并成"直接加" |
| 补码除法判据 | 够不够减看**余数与除数是否同号**（不是看余数正负） |
| 补码除法第一步 | 同号**减**除数、异号**加**除数 → 余数与除数同号商 1、异号商 0（**即商符**） |
| 补码除法末位 | **末位恒置 1**，最大误差 $2^{-n}$；除不尽且商为负时末位 +1 |
| 串行乘 vs 串行除 | 串行乘法 = 多次累加 + **右移**；串行除法 = 多次累加 + **左移** |
| 移位次数 | 一位乘、一位除的移位次数都是 **n 次** |
| 时间排序 | 软件循环 > ALU+移位器整除 ≈ 一位乘 > 阵列乘法器（一个时钟周期） |
