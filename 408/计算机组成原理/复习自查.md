## 第1章 计算机系统概述

### 1.1 自查清单

- [ ] 冯·诺依曼机的核心思想：**存储程序**、指令和数据同等对待存放于存储器、按地址访问、五部件（运算器/控制器/存储器/输入/输出）；以**运算器为中心**，现代机器以存储器为中心
- [ ] 五个部件各自的功能；CPU = 运算器 + 控制器；主机 = CPU + 主存
- [ ] 计算机系统的多层次结构（微程序级—机器级—操作系统级—汇编/高级语言级）；软硬件在逻辑功能上**等价**
- [ ] 编译程序（整体翻译后执行）vs 解释程序（逐句翻译执行）的区别
- [ ] 性能指标会算：主频、CPI（平均时钟周期数）、MIPS、FLOPS；**CPU 执行时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频**
- [ ] 字长、数据通路带宽（外存的，一次能传的位数）、主存容量、主频的准确含义
- [ ] 基准程序（benchmark）的意义与局限；"主频高一定快"为什么不对（CPI、指令数、访存都影响）

### 1.2 易错点 · 高频陷阱

- MIPS 与主频、CPI 的换算：MIPS = 主频 / (CPI × 10⁶)——注意主频单位是 Hz。
- 数据通路带宽指**数据总线一次所能并行传送的位数**，不是 CPU 字长。
- 比较两机器性能必须用**同一程序的总执行时间**（或同基准程序），单比主频/单比 MIPS 都不严谨。
- MDR 位数 = 存储字长，MAR 位数 = 地址位数（决定最大寻址空间 2ⁿ）——"MAR 16 位、MDR 8 位"的机器寻址范围 64K × 8bit。
- 翻译（编译）生成等价的目标程序后再执行，执行期不需源程序；解释则边翻边执行、不生成目标程序。

### 1.3 自测问答

**Q1. 机器 A 主频 2GHz，程序在 A 上执行 1×10⁹ 条指令，平均 CPI=2；机器 B 主频 3GHz，同程序平均 CPI=3。哪个快？快多少？**

<details><summary>▶ 展开答案</summary>

A：10⁹ × 2 / 2×10⁹ = 1s；B：10⁹ × 3 / 3×10⁹ = 1s。**一样快**——主频和 CPI 的影响恰好抵消，说明不能只看主频。
</details>

**Q2. MAR 为 24 位、MDR 为 16 位的存储器，容量是多少？**

<details><summary>▶ 展开答案</summary>

寻址单元数 2²⁴ = 16M，每个单元（存储字）16 位 = 2B → 容量 16M × 2B = **32MB**。
</details>

## 第2章 数据的表示和运算

### 2.1 自查清单

- [ ] 进制转换：二/八/十六进制互转、十进制↔二进制（整数除 2 取余、小数乘 2 取整）；**十进制小数转二进制可能无限循环**
- [ ] BCD 码（8421 码）运算的"+6 修正"条件；余 3 码、2421 码的特点
- [ ] 校验码：奇偶校验（检奇数位错，不能纠错）；**海明码：2^k ≥ n+k+1**（k 位校验位）；会算信息位数 n 对应的校验位数、会分组/定位错误
- [ ] 循环冗余校验 CRC：模 2 除法；生成多项式 G(x) 的位数 r+1 → 校验位 r 位；会手算信息码 + 校验码
- [ ] 定点数的原码/反码/补码/移码表示与互换；**补码整数 n+1 位范围 [−2ⁿ, 2ⁿ−1]，比原码/反码多表示一个最小负数**；定点小数补码范围 [−1, 1−2⁻ⁿ]
- [ ] 变形补码（双符号位）判溢出：**两符号位不同则溢出，01 正溢、10 负溢**；单符号位判溢出：符号位进位与最高数值位进位**异或**
- [ ] 补码加减运算与自动丢弃双符号位进位；补码算术右移**符号位不变**、逻辑右移补 0；**补码左移低位补 0 可能溢出**
- [ ] 原码一位乘（符号位单独异或、绝对值相加移位）与**补码一位乘（Booth 算法）**：附加位 Yₙ₊₁，按 YₙYₙ₊₁ = 00/01/10/11 决定 +0/[+X]/[−X]/+0，算术右移——会完整手算一道题
- [ ] 除法：原码恢复余数法与**加减交替法**（余数为负加除数、为正减除数，左移一位后上商规则）；补码除法加减交替——理解流程并能手算小规模题
- [ ] IEEE 754：**单精度 1+8+23（偏置 127）、双精度 1+11+52（偏置 1023）**；隐藏最高位 1（规格化数）；阶码全 0（非规格化/±0）、全 1（±∞/NaN）的特殊情形
- [ ] 会做：十进制 ↔ IEEE754 十六进制互转；求给定 float 能表示的最大/最小正规数；判断两个 float 相减的精度损失
- [ ] 浮点加减五步：**对阶（小阶向大阶）→ 尾数加减 → 规格化 → 舍入 → 溢出判断**（阶码溢出才算溢出）；会手算一道完整题
- [ ] C 语言类型转换：int→float 可能丢精度（float 尾数 23 位）、float→int 向零截断；无符号与有符号比较的坑（有符号被转无符号）
- [ ] 加法器：一位全加器、串行进位与**先行进位（CLA）**的思想；ALU 是组合逻辑、为核心部件

### 2.2 易错点 · 高频陷阱

- 补码表示范围的不对称：n+1 位（含符号）补码没有 +2ⁿ，只有 −2ⁿ——求"−(−2ⁿ)"的补码会出错（结果仍为 −2ⁿ 自身）。
- 移码 = 补码符号位取反；同一真值移码可直接比大小（用于阶码）——常考"为什么浮点阶码用移码"。
- Booth 算法最后**不移位**；乘积共 2n+1 位（含双符号位）——手算时数错步数是最高频错误。
- 对阶必须**小阶向大阶对齐**（尾数右移），反过来大阶向小阶会丢高位——"为什么"要能答。
- 规格化判断：补码尾数形如 0.1xx…（正）或 1.0xx…（负）；右规最多一次、左规可能多次。
- IEEE754 中 float 的 −0 与 +0 不同位串但值相等；比较阶码用移码可直接比较。
- 海明码校验位放在 2 的幂次位置；纠错时对"出错位置编号=各校验组异或结果"要能推。
- CRC 只能**检错**（配合重传），不能纠错；海明码能纠 1 位错。
- 十六进制中"每 4 位二进制对应 1 位十六进制"，先转二进制再转比直接算快且不易错。

### 2.3 自测问答

**Q1. 求 −110.101（二进制）的 8 位（含符号）定点小数补码（小数点后 7 位）。**

<details><summary>▶ 展开答案</summary>

原码：1.1101010（符号 1，数值位补足 7 位）。反码：1.0010101，补码 = 反码 +1 = **1.0010110**。
</details>

**Q2. x=−0.1011，y=−0.0111。x·y 应为正还是负？用 Booth 算法时 [y]补 对应的判断位序列是什么？给出 [x·y]补。**

<details><summary>▶ 展开答案</summary>

两负数相乘积为**正**：x·y = (11/16)×(7/16) = 77/256 = **+0.01001101**，故 [x·y]补 = 00.01001101。
[y]补 = 1.1001，末尾附加 0。判断位（从低位起两两看）：(y₄y₅)=(1,0)→+[−x]补；(y₃y₄)=(0,1)→+[x]补；(y₂y₃)=(0,0)→+0；(y₁y₂)=(1,0)→+[−x]补。
即加法序列 **[−x]补、[x]补、+0、[−x]补**：共 4 次加法、3 次算术右移，**最后一次加完不再移位**；右移时符号位保持（补码算术右移，最高位补符号位）。
</details>

**Q3. 将十进制 −0.75 表示为 IEEE754 单精度（十六进制）。**

<details><summary>▶ 展开答案</summary>

−0.75 = −0.11₂ = −1.1×2⁻¹。符号 1；阶码 = −1+127 = 126 = 0111 1110；尾数 = 100…0（23 位）。
结果：**1 01111110 10000000000000000000000** = 0xBF400000。
</details>

**Q4. 两浮点数 x=2⁰¹×0.1101、y=2⁰⁰×(−0.1010)（补码尾数，阶码 2 位）求 x+y，写出五步。**

<details><summary>▶ 展开答案</summary>

① 对阶：y 阶小，y 尾数右移 1 位 → 2⁰¹×(−0.0101)；
② 尾数相加：0.1101 + [−0.0101]补(=1.1011) = 10.1000 → 丢进位得 0.1000；
③ 规格化：已是 0.1xx… 形式，无需规格化，阶码保持 01；
④ 舍入：无舍入；
⑤ 判溢出：阶码 01 在范围内，不溢出。
结果 = 2⁰¹×0.1000 = **1.0**（验算：1.625 − 0.625 = 1 ✓）。
</details>

## 第3章 存储器层次结构

### 3.1 自查清单

- [ ] 存储层次：寄存器—Cache—主存—辅存；"Cache—主存"解决**速度**，"主存—辅存（虚存）"解决**容量**
- [ ] SRAM（触发器、快、贵、功耗大 → Cache）vs DRAM（电容、需**刷新**、集成度高 → 主存）；DRAM 刷新方式：集中/分散/异步，**按行刷新**、刷新以行为单位
- [ ] DRAM 为什么用地址复用（行/列分两次送，省引脚）；SDRAM 与同步、DDR 的上升/下降双沿
- [ ] ROM 家族：MROM/PROM/EPROM/EEPROM/**Flash**（SSD）；Flash 读快写慢、先擦后写
- [ ] 主存与 CPU 的连接：会做**存储扩展**（位扩展/字扩展/字位同时扩展），会算所需芯片数、画出片选译码（线选/译码器 74LS138）
- [ ] 双端口存储器（两套端口，冲突时busy）与**多体并行**：高位交叉编址（顺序编址，利于扩容）vs **低位交叉编址（各体轮流，流水线存取）**
- [ ] 低位交叉 m 体流水存取：连续访问 m 个字耗时 **T + (m−1)r**（存取周期 T、总线传送周期 r，条件 m·r ≥ T）；会算带宽提升
- [ ] Cache 工作原理：局部性原理；命中率 H = Nc/(Nc+Nm)；**平均访问时间 t = H·tc + (1−H)·tm**（先 Cache 后主存口口径：t = H·tc + (1−H)(tc+tm)——按教材口径看清题目）
- [ ] 三种映射：**直接映射**（主存块 → 唯一行，行号 = 主存块号 mod 行数；地址划分 tag|行号|块内；无替换问题）、**全相联**（任意放，tag 最长、比较最贵）、**组相联**（组间直接、组内全相联；地址划分 tag|组号|块内）
- [ ] 会做映射计算：给主存地址位分配（如 32 位、Cache 8KB、块 64B、2 路组相联：块内 6 位、组号 3+... 位、tag 其余）并判断某地址是否命中
- [ ] 替换算法：直接映射无需替换；全相联/组相联组内用 LRU（计数器法）、FIFO、LFU、随机——会推 LRU 计数器变化与命中/替换过程
- [ ] 修改策略：**写直达 write-through**（同时写主存，配写缓冲）vs **写回 write-back**（置换时才写回，需**脏位/修改位**）；写不命中时：写分配法（调块）vs 非写分配
- [ ] Cache 写命中率提升手段（写缓冲）；多级 Cache（L1/L2/L3）中局部性/全局命中率的算法
- [ ] 页式虚拟存储器：虚地址→实地址经页表；**TLB（快表）+ Cache + 主存**三级查找的组合情形（TLB 命中→不访问页表；TLB 命中且 Cache 命中→仅 1 次访存取数）；页表基址寄存器 PTBR
- [ ] TLB、Cache 的容量/映射方式设计题（给条件算 TLB tag 位数等）

### 3.2 易错点 · 高频陷阱

- 刷新对 CPU 是**透明**的（CPU 感觉不到）；刷新按**行**、一行一整行（不是按存储单元逐个刷）。
- 低位交叉编址体号在**地址低位**；高位交叉体号在高位——决定"连续地址是否分布在不同存储体"。
- Cache 命中率的两种平均时间口径（并行访问 vs 顺序访问）差别是 (1−H)·tc 一项——看清题目假设。
- 直接映射没有替换算法；写回法必须有脏位，写直达可以没有；**写分配 ↔ 写回**搭配，**非写分配 ↔ 写直达**搭配（教材典型组合）。
- 块大小变化影响命中率：块太小空间局部性利用不足，太大则行数变少冲突上升——论述题要点。
- TLB 中存放的是**页表项的副本**，Cache 存放**主存数据的副本**——两者层次不同、别混。
- 全相联 tag = 主存地址去掉块内偏移的全部位；组相联 tag = 主存地址去掉组号与块内偏移；直接映射 tag 还要去掉行号——三种划分写清楚。
- 存储扩展时芯片的片选逻辑：位扩展共用片选；字扩展用高位地址译码。

### 3.3 自测问答

**Q1. 主存 32 位地址，Cache 数据容量 8KB、块大小 64B、2 路组相联。写出主存地址划分（tag|组号|块内），共多少组？**

<details><summary>▶ 展开答案</summary>

块内偏移 = log₂64 = **6 位**；行数 = 8KB/64B = 128 行，每组 2 行 → 组数 = 64，组号 = **6 位**；tag = 32−6−6 = **20 位**。
划分：**tag(20) | 组号(6) | 块内(6)**。
</details>

**Q2. Cache 速度 20ns、命中率 95%；主存 200ns。求平均访问时间（先访 Cache、未命中再访主存口径）。**

<details><summary>▶ 展开答案</summary>

t = 0.95×20 + 0.05×(20+200) = 19 + 11 = **30ns**。（若口径为同时访问两级，则 t = 0.95×20 + 0.05×200 = 29ns——答题时说明口径。）
</details>

**Q3. 四体低位交叉编址存储器，存取周期 100ns、总线传送周期 25ns。流水方式连续读取 4 个字需多久？带宽是单体存取的几倍？**

<details><summary>▶ 展开答案</summary>

T + (m−1)r = 100 + 3×25 = **175ns** 读 4 字；单体读 4 字 = 400ns → 约 **2.3 倍**（极限上界为 m=4 倍）。
</details>

**Q4. 判断：①Cache 对应用程序员和系统程序员都透明；②TLB 全部命中时一次取数最少只需 1 次访存。**

<details><summary>▶ 展开答案</summary>

① 正确——Cache 完全由硬件管理，对所有程序员透明。② 正确——TLB 命中免去页表访存，若 Cache 也命中则取数也在 Cache 完成，无主存访问；"1 次访存"指取数访问（若指主存访问则是 0 次，视口径，关键是**不访问页表**）。
</details>

## 第4章 指令系统

### 4.1 自查清单

- [ ] 指令格式：操作码 + 地址码；四地址/三地址/二地址/一地址/零地址（堆栈型）各自的语义与访存次数
- [ ] 定长操作码 vs **扩展操作码**（变长）：会算给定分层方案下各长度操作码能表示的指令数（如 4 位基本 + 扩展方案）
- [ ] 指令寻址：顺序寻址 **(PC)+1（"1"=一条指令字长）**、跳跃寻址（转移指令修改 PC）
- [ ] 数据寻址各方式及有效地址：立即寻址（操作数在指令中，取指后**不需再访存**）、直接（EA=A，1 次访存）、一次间接（EA=(A)，≥2 次访存）、寄存器（EA=Rᵢ，**0 次访存**）、寄存器间接（1 次）、相对寻址（**EA = (PC) + A**，取指后 PC 已指向下一条；A 用补码，可实现程序浮动/转移）、基址（EA=(BR)+A，BR 由**操作系统**管理，面向系统/重定位/多道程序）、变址（EA=(IX)+A，IX 用户可改，面向用户/数组循环处理）、堆栈寻址（SP；硬堆栈=寄存器组、软堆栈=内存）
- [ ] 相对寻址取指前后 PC 的差别：**转移目标 = 取指后 PC + 偏移**，偏移 = 目标地址 − (本条指令地址 + 指令字长)
- [ ] 基址 vs 变址的对比（管理者、用途、能否成批修改）；基址+变址复合寻址 EA=((BR)+IX)+A
- [ ] RISC vs CISC：指令数/定长/寻址方式/大部分指令单周期/Load-Store 结构/流水线/控制器（组合逻辑 vs 微程序）/通用寄存器数量——对比表能默写
- [ ] 程序在内存的存放：大端（高字节低地址）vs 小端；边界对齐的意义（一次访存取到）

### 4.2 易错点 · 高频陷阱

- 相对寻址的基准 PC：转移指令**取指完成后**的 PC 值（= 本指令地址 + 指令字长），不是本指令地址——计算偏移必错点。
- 立即寻址最快（A 就是操作数）；间接寻址最慢且需多次访存；寄存器寻址不用访存但要占指令中寄存器编号字段。
- 扩展操作码方案中**短码不能是长码的前缀**；还要检查"每种操作码组合是否够用、有无浪费"——考"是否能成为完整编码方案"。
- 变址寻址适合处理**数组/循环**（IX 自动 +1），基址适合**程序重定位/多道程序**（BR 由 OS 设置）——方向别反。
- RISC 一定采用流水线、指令定长、Load/Store 型——但"RISC 不支持访存指令"错误，是**只有 Load/Store 能访存**。
- 零地址指令在**堆栈计算机**或不需要操作数（如 NOP、停机）两种情形。
- 大端机器存 0x12345678：低地址放 0x12；x86 是小端、网络字节序是大端。

### 4.3 自测问答

**Q1. 某机指令字长 16 位，采用扩展操作码：前 15 条三地址指令（各地址 4 位）。还能安排多少条二地址、一地址指令？给出一种方案。**

<details><summary>▶ 展开答案</summary>

4 位操作码留 1111 做扩展前缀 → 二地址指令可用 1111 + 4 位 = 16 种，同样留一个前缀 11111111 扩展一地址 → 方案：二地址 15 条（1111 0000~1110），一地址 16 条（1111 1111 + 4 位）。需检查"短码非长码前缀、数量够用"。
</details>

**Q2. 转移指令在内存 2000H 处，指令长 2B，目标地址 2010H，相对寻址。求偏移量 A。**

<details><summary>▶ 展开答案</summary>

取指后 PC = 2000H + 2 = 2002H；A = 2010H − 2002H = **0EH（14）**（补码，8 位表示为 0EH）。
</details>

**Q3. 判断：①变址寻址中变址寄存器内容由用户设定；②基址寻址有利于多道程序设计。**

<details><summary>▶ 展开答案</summary>

① 正确（IX 由用户程序修改，用于数组遍历）。② 正确（基址寄存器由 OS 管理、存放程序基地址，程序可在内存中浮动，正是多道程序需要的重定位手段）。
</details>

## 第5章 中央处理器

### 5.1 自查清单

- [ ] CPU 四大功能（指令控制/操作控制/时间控制/数据加工）；CPU = 运算器 + 控制器，能列出两部件的主要寄存器
- [ ] 用户可见寄存器（通用寄存器、PC? —教材口径：PC/IR/MAR/MDR/PSW **对用户（汇编程序员）透明**）vs 不可见；PSW 的作用（OF SF ZF CF 标志位）
- [ ] 取指周期/间址周期/执行周期/中断周期的微操作序列（M(MAR)→MDR→IR、(PC)+1→PC 的位置）；**取指后 PC 自动 +1**
- [ ] 指令执行方案：单周期/多周期/流水线（各指令周期不等长）
- [ ] 数据通路：单总线结构（冲突多、慢）→ 多总线 → 专用通路；内部总线 vs 系统总线
- [ ] 硬布线控制器：微操作控制信号 = 译码输出 & 节拍 & 状态的组合逻辑；RISC 常用、速度快
- [ ] 微程序控制器：**一条机器指令 → 一段微程序 → 若干微指令**；控制存储器 CM（ROM）存微程序；CMAR/μIR/地址转移逻辑；水平型微指令（并行能力强、字长长）vs 垂直型（类似机器指令、需译码）
- [ ] 字段直接编码：互斥微命令分到同字段、**每字段留全 0 表示"无操作"**，n 位字段最多表示 2ⁿ−1 个微命令；字段间接编码
- [ ] 微指令后继微地址形成：增量计数器法（μPC+1）、断定方式（下址字段+转移条件）
- [ ] 五段流水线：**IF ID EX MEM WB**；时钟周期取决于最慢段
- [ ] 流水线性能计算：n 条指令 m 段流水总时间 **(m + n − 1)Δt**；实际吞吐率 = n/((m+n−1)Δt)、最大吞吐率 1/Δt；加速比 = nm/(m+n−1)；效率
- [ ] 三类冒险与对策：**结构冒险**（部件冲突，如 IF 与 MEM 同时访存 → 停顿一拍/指令存储器与数据存储器分开）；**数据冒险**（RAW 写后读 → 转发/旁路，load-use 需加气泡 + 编译调度）；**控制冒险**（转移 → 分支预测（静态/动态 BHT）、延迟分支）
- [ ] 会算：含数据冒险/分支的指令序列各需几个周期（"转发后相邻指令无停顿；load-use 插 1 个气泡"）
- [ ] 高级流水线技术：超标量（多条流水线并发、**不改变时钟周期而是每周期发射多条**）、超流水（更细分段、更高主频）、超长指令字 VLIW、多发射与动态调度（乱序执行、按序完成）

### 5.2 易错点 · 高频陷阱

- PC、IR、MAR、MDR、PSW 都是**用户不可见**寄存器；通用寄存器可见——判断"汇编程序员能否访问"就用这条。
- 微程序控制器里**每条机器指令对应一段微程序**；取指周期的微程序是公用的。
- 水平型微指令一条可定义多个并行微命令（指令字长但快）；垂直型一条只控制一个基本操作——两者性能对比方向别背反。
- 字段直接编码的 2ⁿ−1：全 0 已被"无操作"占用——数微命令数时记得减。
- load-use 冒险**即使有转发也不能完全消除**（生产者 WB 在消费者 EX 之后），必须停 1 拍——高频考点。
- 超标量 ≠ 超流水：前者横向多发射、后者纵向细分段提高频率。
- 中断周期在"执行周期之后"响应（一条指令执行完），断点入栈/存指定单元。
- 转移指令在流水线中：分支预测错误要**清除已取的后续指令**（冲刷流水线），代价 = 惩罚周期。

### 5.3 自测问答

**Q1. 某流水线 5 段、每段 1ns。执行 20 条指令的总时间、加速比、实际吞吐率。**

<details><summary>▶ 展开答案</summary>

总时间 = (5+20−1)×1 = **24ns**；串行 = 20×5 = 100ns → 加速比 = 100/24 ≈ **4.17**；吞吐率 = 20/24ns ≈ **0.83 条/ns**（极限 1 条/ns）。
</details>

**Q2. 序列 `I1: lw R1, 0(R2)`；`I2: add R3, R1, R4`；`I3: sub R5, R3, R6`。五段流水线（EX 前可转发）需要几个周期（含气泡）？**

<details><summary>▶ 展开答案</summary>

I1 与 I2 是 **load-use**：转发也不够（数据 EX 后才产生），I2 需停 1 拍；I2→I3 是 ALU→ALU 相关，靠**转发**解决无停顿。共需 5 + (4−1) + 1 = **8 个周期**（含 1 个气泡）。
</details>

**Q3. 某字段直接编码：字段 A 3 位、字段 B 4 位、字段 C 5 位，每字段留全 0 表示无操作。这些字段最多能表示多少个互斥微命令？**

<details><summary>▶ 展开答案</summary>

(2³−1) + (2⁴−1) + (2⁵−1) = 7+15+31 = **53 个**。
</details>

## 第6章 总线系统

### 6.1 自查清单

- [ ] 总线的概念与分类：片内/系统总线（数据、地址、控制）/通信总线；**数据总线双向、地址总线单向（CPU→外）**
- [ ] 总线性能：总线宽度（位数）、**总线带宽 = 工作频率 × 每次传送的字节数**——会算（如 32 位、100MHz、每周期传 1 次 → 400MB/s；DDR 双沿 ×2）
- [ ] 总线仲裁：**集中式三种**——链式查询（BG 串行，离控制器近优先级高、对故障敏感、线少）、计数器定时查询（设备地址计数、优先级可改）、独立请求（每设备独立 BR/BG，并行响应快、灵活可编程、线最多）；分布式仲裁（自举式，竞争时仲裁号）
- [ ] 总线定时（传输方式）：**同步通信**（统一时钟、速度快、须迁就最慢设备/强制同步）、**异步通信**（应答：不互锁/半互锁/全互锁，慢但可靠灵活）、半同步通信（加 WAIT 应答）、分离式通信（总线周期拆分，总线利用率最高）
- [ ] 一次数传输的四个阶段：申请分配→寻址→传输→结束
- [ ] 常见总线标准：ISA/EISA/PCI/PCIe/USB/AGP 的大致定位（PCI 并行、PCIe 串行点对点、USB 通用串行、支持热插拔）

### 6.2 易错点 · 高频陷阱

- 链式查询的优先级**固定**（物理位置决定）；计数器查询可循环改变；独立请求可用编程改变——"优先级灵活"对应独立请求。
- 地址线是单向的，**数据线是双向的**；总线带宽计算时数据线位数决定每周期字节数。
- "带宽 = 工作频率×宽度/8"里若每周期传两次（DDR）要 ×2；给出时钟与传送周期不同的（如每 4 个时钟传 1 次）要按传送周期算。
- 异步全互锁最可靠但最慢；不互锁速度快可靠性差——排序题：不互锁 < 半互锁 < 全互锁（速度依次变慢）。
- 分离式通信把从设备准备数据的时间让出总线给其他主设备用——它提高的是**总线利用率**而非单次传输速度。

### 6.3 自测问答

**Q1. 同步总线：时钟 200MHz，每个时钟周期传送 64 位数据。总线带宽是多少？若改为每个数据 2 个时钟周期传送一次呢？**

<details><summary>▶ 展开答案</summary>

每周期 64bit = 8B，200M 周期/s → 8B×200M = **1.6GB/s**；若 2 周期传一次：**800MB/s**。
</details>

**Q2. 判断：①链式查询方式对电路故障很敏感；②独立请求方式所需控制线最少。**

<details><summary>▶ 展开答案</summary>

① 正确——BG 链上任一接口故障会阻断后面所有设备。
② 错误——独立请求需要每设备一对 BRᵢ/BGᵢ，**控制线最多**；链式查询仅 BR、BG、BS 三根，线最少。
</details>

## 第7章 输入输出系统

### 7.1 自查清单

- [ ] I/O 接口的功能与基本结构（数据缓冲寄存器 DBR、状态/控制寄存器、端口地址译码）；接口 vs 端口 vs 设备的关系
- [ ] I/O 端口编址：统一编址（占内存空间、可用访存指令但译码慢）vs 独立编址（专用 I/O 指令、地址空间独立、需控制线区分）
- [ ] 程序查询方式：CPU 轮询忙等、**CPU 与设备完全串行**、接口简单；会算查询方式 CPU 利用率
- [ ] 中断方式（重点）：中断请求→**中断判优**→响应条件（CPU 允许中断、有请求、一条指令执行完）→中断隐指令（关中断、保存断点、引出入口）→服务程序（保护现场→设备服务→恢复现场→开中断→返回）
- [ ] 单重中断 vs 多重中断（服务中开中断才可实现嵌套）；中断判优：硬件排队器/软件查询
- [ ] **响应优先级（硬件排队，不可变）vs 处理优先级（屏蔽字，可变）**；会按处理优先级设计屏蔽字（1=屏蔽，自身恒 1）
- [ ] 中断向量：向量地址 vs 中断服务程序入口地址；向量中断（中断向量表/中断类型号）的思想
- [ ] DMA 方式（重点）：数据块为单位、**主存与设备直接通路、不经过 CPU**、CPU 仅在预处理/后处理介入；DMA 控制器组成（主存地址计数器、传送长度计数器、数据缓冲、中断逻辑、控制/状态逻辑）
- [ ] DMA 传送方法：**周期挪用（周期窃取）**、停止 CPU 访存、交替访存——各自对 CPU 的影响对比
- [ ] DMA 与程序中断的对比（数据通路、响应时机：**DMA 在存取周期结束、中断在指令周期结束**；优先级：DMA 高于中断——不丢失数据；CPU 开销；适用对象）
- [ ] DMA 的三个阶段：预处理（初始化 MAR/字计数器/启动）→ 数据传送（硬件完成）→ 后处理（校验、以中断方式报告 CPU）
- [ ] 通道方式（概念级）：通道程序、字节多路/数组选择/数组多路通道的适用对象

### 7.2 易错点 · 高频陷阱

- 中断隐指令**由硬件自动执行，不是指令系统里的指令**；它做三件事：关中断、保存断点、引出服务程序入口。保存通用寄存器（现场）由**服务程序（软件）**完成。
- 屏蔽字设计：处理优先级高的中断要屏蔽**所有低于等于自己**的；最高优先级的屏蔽字全 1——给出新优先级重新设计屏蔽字是高频计算题。
- "CPU 响应中断一定在一条指令执行结束时"对程序中断成立；**DMA 请求可在存取周期结束时响应**（不必等指令结束）——两者响应时机的区别是经典考点。
- DMA 数据**不经过 CPU**（不经 CPU 寄存器），中断方式数据经过 CPU（累加器/寄存器中转）。
- 周期挪用时若 CPU 与 DMA 同时要访存，**DMA 优先**（不挪用会丢数据）。
- 统一编址下"访问 I/O 的指令"就是普通访存指令，无专用 I/O 指令；独立编址必须专用指令、且需指明是 I/O 访问。
- 程序查询方式的 CPU 效率最低但硬件最少；中断方式提高了 CPU 利用率但仍按字传送（适合低速设备）；DMA 适合高速块设备。

### 7.3 自测问答

**Q1. 设备 B、C、D 处理优先级要求为 C > B > D，响应优先级为 D > C > B。写出 B、C、D 的屏蔽字（顺序 B C D，1=屏蔽）。**

<details><summary>▶ 展开答案</summary>

屏蔽所有"处理优先级 ≤ 自身"的：
B：屏蔽 B、D，开放 C → **1 0 1**；C：全 1 → **1 1 1**；D：全 1 → **1 1 1**。
（最高处理优先级 C 的屏蔽字必全 1；D 只比自身高，也全 1。）
</details>

**Q2. 判断：①DMA 方式中 CPU 完全不参与数据传送；②中断方式下数据传送经过 CPU。**

<details><summary>▶ 展开答案</summary>

① 正确（传送阶段完全由 DMA 控制器硬件完成；CPU 只做预处理和后处理）。
② 正确（中断方式每字都要 CPU 执行服务程序从接口取走/写入——数据流经 CPU）。
</details>

**Q3. 比较程序查询、程序中断、DMA 三种 I/O 方式的 CPU 介入程度与适用设备类型。**

<details><summary>▶ 展开答案</summary>

程序查询：CPU 全程忙等，与设备串行，适合速度慢、任务简单的场合（CPU 利用率最低）；程序中断：CPU 仅在每字传输完成时短暂介入（执行服务程序），CPU 与设备并行、适合中低速设备；DMA：以数据块为单位，CPU 仅在块前后介入，主存与设备直传，适合磁盘等高速块设备，CPU 开销最小。
</details>
