## 第1章 计算机系统概述

### 1.1 自查清单

- [ ] 冯·诺依曼机的核心思想：**存储程序**、指令和数据同等对待存放于存储器、按地址访问、五部件（运算器/控制器/存储器/输入/输出）；以**运算器为中心**，现代机器以存储器为中心
- [ ] 五个部件各自的功能；CPU = 运算器 + 控制器；主机 = CPU + 主存
- [ ] 计算机系统的多层次结构（微程序级—机器级—操作系统级—汇编/高级语言级）；软硬件在逻辑功能上**等价**
- [ ] 编译程序（整体翻译后执行）vs 解释程序（逐句翻译执行）的区别
- [ ] 性能指标会算：主频、CPI（平均时钟周期数）、MIPS、FLOPS；$T_{\text{CPU}} = \text{指令数} \times CPI \times T_{\text{时钟}} = \dfrac{\text{指令数} \times CPI}{\text{主频}}$
- [ ] 字长、数据通路带宽（外存的，一次能传的位数）、主存容量、主频的准确含义
- [ ] 基准程序（benchmark）的意义与局限；"主频高一定快"为什么不对（CPI、指令数、访存都影响）

### 1.2 易错点 · 高频陷阱

- MIPS 与主频、CPI 的换算：$MIPS = \dfrac{\text{主频}}{CPI \times 10^6}$——注意主频单位是 Hz。
- 数据通路带宽指**数据总线一次所能并行传送的位数**，不是 CPU 字长。
- 比较两机器性能必须用**同一程序的总执行时间**（或同基准程序），单比主频/单比 MIPS 都不严谨。
- MDR 位数 = 存储字长，MAR 位数 = 地址位数（决定最大寻址空间 $2^n$）——"MAR 16 位、MDR 8 位"的机器寻址范围 $2^{16} \times 8$ bit。
- 翻译（编译）生成等价的目标程序后再执行，执行期不需源程序；解释则边翻边执行、不生成目标程序。

### 1.3 自测问答

**Q1. 机器 A 主频 2GHz，程序在 A 上执行 $1\times10^9$ 条指令，平均 CPI=2；机器 B 主频 3GHz，同程序平均 CPI=3。哪个快？快多少？**

<details><summary>▶ 展开答案</summary>

A：$\dfrac{10^9 \times 2}{2 \times 10^9} = 1\text{s}$；B：$\dfrac{10^9 \times 3}{3 \times 10^9} = 1\text{s}$。**一样快**——主频和 CPI 的影响恰好抵消，说明不能只看主频。
</details>

**Q2. MAR 为 24 位、MDR 为 16 位的存储器，容量是多少？**

<details><summary>▶ 展开答案</summary>

寻址单元数 $2^{24} = 16\text{M}$，每个单元（存储字）16 位 = 2B → 容量 $16\text{M} \times 2\text{B} = \textbf{32MB}$。
</details>

## 第2章 数据的表示和运算

### 2.1 自查清单

- [ ] 进制转换：二/八/十六进制互转、十进制↔二进制（整数除 2 取余、小数乘 2 取整）；**十进制小数转二进制可能无限循环**
- [ ] BCD 码（8421 码）运算的"+6 修正"条件；余 3 码、2421 码的特点
- [ ] 校验码：奇偶校验（检奇数位错，不能纠错）；**海明码：$2^k \ge n + k + 1$**（k 位校验位）；会算信息位数 n 对应的校验位数、会分组/定位错误
- [ ] 循环冗余校验 CRC：模 2 除法；生成多项式最高 $r$ 次幂 → 校验位 $r$ 位；会手算信息码 + 校验码
- [ ] 定点数的原码/反码/补码/移码表示与互换；**补码整数 $n+1$ 位范围 $[-2^n,\ 2^n-1]$，比原码/反码多表示一个最小负数**；定点小数补码范围 $[-1,\ 1-2^{-n}]$
- [ ] 变形补码（双符号位）判溢出：**两符号位不同则溢出，01 正溢、10 负溢**；单符号位判溢出：符号位进位与最高数值位进位**异或**
- [ ] 补码加减运算与自动丢弃双符号位进位；补码算术右移**符号位不变**、逻辑右移补 0；**补码左移低位补 0 可能溢出**
- [ ] 原码一位乘（符号位单独异或、绝对值相加移位）与**补码一位乘（Booth 算法）**：附加位 $Y_{n+1}$，按判断位组合决定 +0/[+X]/[−X]，算术右移——会完整手算一道题
- [ ] 除法：原码恢复余数法与**加减交替法**（余数为负加除数、为正减除数，左移一位后上商规则）；补码除法加减交替——理解流程并能手算小规模题
- [ ] IEEE 754：**单精度 1+8+23（偏置 127）、双精度 1+11+52（偏置 1023）**；隐藏最高位 1（规格化数）；阶码全 0（非规格化/±0）、全 1（±∞/NaN）的特殊情形
- [ ] 会做：十进制 ↔ IEEE754 十六进制互转；求给定 float 能表示的最大/最小正规数；判断两个 float 相减的精度损失
- [ ] 浮点加减五步：**对阶（小阶向大阶）→ 尾数加减 → 规格化 → 舍入 → 溢出判断**（阶码溢出才算溢出）；会手算一道完整题
- [ ] C 语言类型转换：int→float 可能丢精度（float 尾数 23 位）、float→int 向零截断；无符号与有符号比较的坑（有符号被转无符号）
- [ ] 加法器：一位全加器、串行进位与**先行进位（CLA）**的思想；ALU 是组合逻辑、为核心部件
- [ ] **标志位的生成（带标志加法器）**：$CF$ 取最高位进位——加法 $CF = C_{out}$、减法 $CF = C_{out} \oplus 1$（不够减产生借位时 $CF=1$）；$OF = C_n \oplus C_{n-1}$（**最高位进位异或次高位进位**，只对带符号数有意义）；$ZF$ = 结果全 0（各位或非）；$SF$ = 结果符号位（只对带符号数有意义）；**减法由补码加法器实现**：$[A-B]_补 = [A]_补 + [-B]_补$，$[-B]_补$ 由 $Sub$ 控制"各位取反 + 末位加 1"
- [ ] **无符号整数的表示与运算**：$n$ 位全部为数值位，范围 $0 \sim 2^n-1$，加减结果按 $2^n$ 取模自动截断；**无符号溢出判据 = 最高位的进位（加法）/ 借位（减法）**，即 $CF=1$；比较用 $CF$、$ZF$（无符号转移 `JA/JAE/JB/JBE`）；位宽提升用**零扩展**
- [ ] **带符号整数的表示与运算**：补码 $n+1$ 位范围 $[-2^n,\ 2^n-1]$，符号位参与运算、最高位进位自动丢弃；**带符号溢出判据 = $OF = C_n \oplus C_{n-1}$**（双符号位 01 正溢、10 负溢）；比较用 $SF$、$OF$、$ZF$（带符号转移 `JG/JGE/JL/JLE`）；位宽提升用**符号扩展**
- [ ] 无符号与带符号的**转换与比较坑**：同宽转换**位串不变、只改变解释方式**（真值可能改变）；C 语言中有符号与无符号混合运算会**隐式转为无符号**（`-1 > 0u` 为真）；判断"谁大、是否溢出"前先看清操作数的符号性
- [ ] 原码一位乘的**硬件电路**：部分积寄存器与乘数寄存器**联合右移**（部分积高位补 0、低位进入乘数寄存器）、一位加法器、由乘数最低位控制"加被乘数 / 加 0"、计数器控制循环次数；共 $n$ 次数值位加法 + $n$ 次**逻辑右移**
- [ ] **阵列乘法器**：$n \times n$ 个**与门**并行产生 $n^2$ 个位积，再用**全加器阵列**按权重逐列压缩求和——**纯组合逻辑、一个时钟周期出结果**（面积换时间），延迟由最长进位链决定，$n$ 位约 $2n-1$ 级全加器
- [ ] 阵列乘法器中的**进位保存加法器（CSA，3-2 压缩器）**：全加器把 3 个输入压缩成"和 + 进位"两个输出，**进位不在本级传播**而是横向送到下一列的高一位，只在最后一级用一次 CLA / 行波加法器（CPA）把和与进位相加
- [ ] 带符号**阵列乘法器**：**算前求补**（补码 → 绝对值）→ 用无符号阵列乘法器相乘 → **算后求补**（结果符号为负时转回补码），符号位由 $X_S \oplus Y_S$ 单独决定
- [ ] **阵列除法器**的思想：用**可控加/减运算单元（CAS）**排成阵列，逐行做"减除数试商"——每行最左单元产生一位商并控制本行是加还是减除数，余数向下传递，纯组合逻辑、不依赖迭代控制

### 2.2 易错点 · 高频陷阱

- 补码表示范围的不对称：$n+1$ 位（含符号）补码没有 $+2^n$，只有 $-2^n$——求"$-(-2^n)$"的补码会出错（结果仍为其自身）。
- 移码 = 补码符号位取反；同一真值移码可直接比大小（用于阶码）——常考"为什么浮点阶码用移码"。
- Booth 算法最后**不移位**；乘积共 $2n+1$ 位（含双符号位）——手算时数错步数是最高频错误。
- 对阶必须**小阶向大阶对齐**（尾数右移），反过来大阶向小阶会丢高位——"为什么"要能答。
- 规格化判断：补码尾数形如 0.1xx…（正）或 1.0xx…（负）；右规最多一次、左规可能多次。
- IEEE754 中 float 的 −0 与 +0 不同位串但值相等；比较阶码用移码可直接比较。
- 海明码校验位放在 2 的幂次位置；纠错时对"出错位置编号=各校验组异或结果"要能推。
- CRC 只能**检错**（配合重传），不能纠错；海明码能纠 1 位错。
- 十六进制中"每 4 位二进制对应 1 位十六进制"，先转二进制再转比直接算快且不易错。
- 阵列乘法器"一个时钟周期完成"说的是**纯组合逻辑**口径；ALU + 移位器的乘法要多周期，软件循环最慢——三种实现的时间排序：软件循环 >（慢于）ALU + 移位器 >（慢于）阵列乘法器。
- 进位保存加法器（CSA）**不在本级传播进位**，单独一级 CSA 得不到最终的和，必须最后接一级 CPA——把"CSA 阵列"当成完整加法器是错的。
- 无符号看 $CF$、带符号看 $OF$，两套判据不能互相替代；减法时 $CF$ 由"借位"定义（$CF = C_{out} \oplus 1$），与加法时"进位"的含义**相反**。
- 同宽的有符号数与无符号数**位串相同、真值不同**：判断大小或溢出前必须先确定类型的符号性，否则 `-1 > 0u` 这类比较会判反。

### 2.3 自测问答

**Q1. 求 −110.101（二进制）的 8 位（含符号）定点小数补码（小数点后 7 位）。**

<details><summary>▶ 展开答案</summary>

原码：1.1101010（符号 1，数值位补足 7 位）。反码：1.0010101，补码 = 反码 +1 = **1.0010110**。
</details>

**Q2. x=−0.1011，y=−0.0111。x·y 应为正还是负？用 Booth 算法时 [y]补 对应的判断位序列是什么？给出 [x·y]补。**

<details><summary>▶ 展开答案</summary>

两负数相乘积为**正**：$x \cdot y = \dfrac{11}{16} \times \dfrac{7}{16} = \dfrac{77}{256} = +0.01001101$，故 [x·y]补 = 00.01001101。
[y]补 = 1.1001，末尾附加 0。判断位（从低位起两两看）：$(y_4y_5)=(1,0) \to +[-x]_补$；$(y_3y_4)=(0,1) \to +[x]_补$；$(y_2y_3)=(0,0) \to +0$；$(y_1y_2)=(1,0) \to +[-x]_补$。
即加法序列 **[−x]补、[x]补、+0、[−x]补**：共 4 次加法、3 次算术右移，**最后一次加完不再移位**；右移时符号位保持（补码算术右移，最高位补符号位）。
</details>

**Q3. 将十进制 −0.75 表示为 IEEE754 单精度（十六进制）。**

<details><summary>▶ 展开答案</summary>

$-0.75 = -0.11_2 = -1.1 \times 2^{-1}$。符号 1；阶码 $= -1 + 127 = 126 = 01111110$；尾数 = 100…0（23 位）。
结果：**1 01111110 10000000000000000000000** = 0xBF400000。
</details>

**Q4. 两浮点数 $x = 2^{01} \times 0.1101$、$y = 2^{00} \times (-0.1010)$（补码尾数，阶码 2 位）求 x+y，写出五步。**

<details><summary>▶ 展开答案</summary>

① 对阶：y 阶小，y 尾数右移 1 位 → $2^{01} \times (-0.0101)$；
② 尾数相加：$0.1101 + [-0.0101]_补(=1.1011) = 10.1000$ → 丢进位得 0.1000；
③ 规格化：已是 0.1xx… 形式，无需规格化，阶码保持 01；
④ 舍入：无舍入；
⑤ 判溢出：阶码 01 在范围内，不溢出。
结果 $= 2^{01} \times 0.1000 = \textbf{1.0}$（验算：$1.625 - 0.625 = 1$ ✓）。
</details>

## 第3章 存储器层次结构

### 3.1 自查清单

- [ ] 存储层次：寄存器—Cache—主存—辅存；"Cache—主存"解决**速度**，"主存—辅存（虚存）"解决**容量**
- [ ] SRAM（触发器、快、贵、功耗大 → Cache）vs DRAM（电容、需**刷新**、集成度高 → 主存）；DRAM 刷新方式：集中/分散/异步，**按行刷新**、刷新以行为单位
- [ ] DRAM 为什么用地址复用（行/列分两次送，省引脚）；SDRAM 与同步、DDR 的上升/下降双沿
- [ ] ROM 家族：MROM/PROM/EPROM/EEPROM/**Flash**（SSD）；Flash 读快写慢、先擦后写
- [ ] 主存与 CPU 的连接：会做**存储扩展**（位扩展/字扩展/字位同时扩展），会算所需芯片数、画出片选译码（线选/译码器 74LS138）
- [ ] 双端口存储器（两套端口，冲突时 busy）与**多体并行**：高位交叉编址（顺序编址，利于扩容）vs **低位交叉编址（各体轮流，流水线存取）**
- [ ] 低位交叉 m 体流水存取：连续访问 m 个字耗时 $T + (m-1)r$（存取周期 $T$、总线传送周期 $r$，条件 $mr \ge T$）；会算带宽提升
- [ ] Cache 工作原理：局部性原理；命中率 $H = \dfrac{N_c}{N_c + N_m}$；**平均访问时间 $t = H \cdot t_c + (1-H) \cdot t_m$**（先 Cache 后主存口径：$t = H t_c + (1-H)(t_c + t_m)$——按教材口径看清题目）
- [ ] 三种映射：**直接映射**（主存块 → 唯一行，$\text{行号} = \text{主存块号} \bmod \text{行数}$；地址划分 tag|行号|块内；无替换问题）、**全相联**（任意放，tag 最长、比较最贵）、**组相联**（组间直接、组内全相联；地址划分 tag|组号|块内）
- [ ] 会做映射计算：给主存地址位分配（如 32 位、Cache 8KB、块 64B、2 路组相联：块内 6 位、组号 6 位、tag 其余）并判断某地址是否命中
- [ ] 替换算法：直接映射无需替换；全相联/组相联组内用 LRU（计数器法）、FIFO、LFU、随机——会推 LRU 计数器变化与命中/替换过程
- [ ] 修改策略：**写直达 write-through**（同时写主存，配写缓冲）vs **写回 write-back**（置换时才写回，需**脏位/修改位**）；写不命中时：写分配法（调块）vs 非写分配
- [ ] Cache 写命中率提升手段（写缓冲）；多级 Cache（L1/L2/L3）中局部/全局命中率的算法
- [ ] 页式虚拟存储器：虚地址→实地址经页表；**TLB（快表）+ Cache + 主存**三级查找的组合情形（TLB 命中→不访问页表；TLB 命中且 Cache 命中→无主存访问取数）；页表基址寄存器 PTBR
- [ ] TLB、Cache 的容量/映射方式设计题（给条件算 TLB tag 位数等）
- [ ] 【22增】**外部存储器 · 磁盘存储器**：盘片（记录面）→ **磁道** → **扇区**（读写最小单位，也称块）；不同记录面上**同号磁道构成柱面**，**磁头数 = 记录面数**；磁盘属**直接存取存储器（DAM）**，须先定位区域再顺序搜索
- [ ] 【22增】磁盘的**寻址与容量**：磁盘地址 = **驱动器号 + 柱面（磁道）号 + 盘面号 + 扇区号**（访问顺序：先驱动器 → 柱面 → 盘面 → 扇区）；容量 = 记录面数 × 每面磁道数 × 每道扇区数 × 扇区大小（格式化容量 < 非格式化容量）
- [ ] 【22增】**平均存取时间 = 寻道时间 + 平均旋转延迟（半圈，$\dfrac{60}{2r}$ 秒，$r$ 为转速 r/min）+ 传输时间 + 控制器延迟**；数据传输率 = 转速(r/s) × 每道扇区数 × 扇区大小——会算给定转速/磁道数/扇区大小的平均存取时间与容量
- [ ] 【22增】**固态硬盘 SSD**：NAND Flash 阵列 + 主控制器 + DRAM 缓存；**FTL（闪存翻译层）**完成主机逻辑块地址 → 闪存物理页的映射与地址转换，磨损均衡也在这一层实现
- [ ] 【22增】SSD 读写特性：**按页读写、按块擦除、写前必须先擦**；改写已写页要整块擦除并搬移有效页（**垃圾回收**）→ **写放大**；**随机读快、随机写慢**，无机械部件所以无寻道与旋转延迟、抗震、低功耗
- [ ] 【22增】**磨损均衡（wear leveling）**：把擦写操作均摊到各块，避免热点块提前失效；**TRIM** 通知 SSD 哪些页已失效可回收；寿命由每块的 **P/E（编程/擦除）次数**决定
- [ ] 【22增】磁盘 vs SSD：SSD 随机访问快、无机械延迟、抗震省电；但**写入寿命有限、单位容量成本高**，磁盘在大容量顺序读写与成本上仍有优势
- [ ] **DRAM 芯片和内存条**：DRAM 芯片地址线**行/列分时复用**（$\overline{RAS}$、$\overline{CAS}$ 分两次选通锁存行地址与列地址），显著减少引脚数、刷新只需行地址；**内存条（DIMM）**把多颗 DRAM 芯片**位扩展**并联成 64 位数据位宽，条上的 **SPD**（小容量 EEPROM）保存容量与时序参数供 BIOS 读取；**DDR** 在时钟双沿各传一次，数据传输率 = 内存时钟频率 × 2
- [ ] **段式与段页式虚拟存储器**：段式按**逻辑功能**分段、段长可变，便于共享与保护（地址 = 段号 + 段内偏移，查段表）；**段页式**先分段再分页（地址 = 段号 + 页号 + 页内偏移，转换需先查段表再查页表），兼有分段便于共享与分页无外部碎片的优点

### 3.2 易错点 · 高频陷阱

- 刷新对 CPU 是**透明**的（CPU 感觉不到）；刷新按**行**、一行一整行（不是按存储单元逐个刷）。
- 低位交叉编址体号在**地址低位**；高位交叉体号在高位——决定"连续地址是否分布在不同存储体"。
- Cache 命中率的两种平均时间口径（并行访问 vs 顺序访问）差别是 $(1-H)t_c$ 一项——看清题目假设。
- 直接映射没有替换算法；写回法必须有脏位，写直达可以没有；**写分配 ↔ 写回**搭配，**非写分配 ↔ 写直达**搭配（教材典型组合）。
- 块大小变化影响命中率：块太小空间局部性利用不足，太大则行数变少冲突上升——论述题要点。
- TLB 中存放的是**页表项的副本**，Cache 存放**主存数据的副本**——两者层次不同、别混。
- 全相联 tag = 主存地址去掉块内偏移的全部位；组相联 tag = 主存地址去掉组号与块内偏移；直接映射 tag 还要去掉行号——三种划分写清楚。
- 存储扩展时芯片的片选逻辑：位扩展共用片选；字扩展用高位地址译码。
- 【22增】平均旋转延迟是**半圈**（$=\dfrac{60}{2r}$ 秒），不是整圈也不是零——算平均存取时间时漏掉它是最常见的错误；传输时间通常远小于寻道与旋转延迟。
- 【22增】SSD **没有寻道与旋转延迟**，不能把磁盘的公式套到 SSD 上；它真正的瓶颈是"**写前必须先擦除**"——改写一页往往要搬移整块的有效页（垃圾回收），由此产生**写放大**，所以随机写比随机读慢得多。
- 磁盘读写的最小单位是**扇区**，但定位时先到**柱面**：同一柱面上各盘面的磁道不用重新寻道，因此"按柱面存放"能减少寻道次数。
- 内存条把多颗 DRAM 芯片**位扩展**成 64 位（DIMM 标准位宽，不是字扩展）：同一 rank 内的芯片共用地址线与片选、各占数据线的一段，不同 rank 由内存控制器分别选通。

### 3.3 自测问答

**Q1. 主存 32 位地址，Cache 数据容量 8KB、块大小 64B、2 路组相联。写出主存地址划分（tag|组号|块内），共多少组？**

<details><summary>▶ 展开答案</summary>

块内偏移 $= \log_2 64 = \textbf{6}$ 位；行数 $= 8\text{KB}/64\text{B} = 128$ 行，每组 2 行 → 组数 $= 64$，组号 = **6 位**；tag $= 32 - 6 - 6 = $ **20 位**。
划分：**tag(20) | 组号(6) | 块内(6)**。
</details>

**Q2. Cache 速度 20ns、命中率 95%；主存 200ns。求平均访问时间（先访 Cache、未命中再访主存口径）。**

<details><summary>▶ 展开答案</summary>

$t = 0.95 \times 20 + 0.05 \times (20+200) = 19 + 11 = \textbf{30ns}$。（若口径为同时访问两级，则 $t = 0.95 \times 20 + 0.05 \times 200 = 29\text{ns}$——答题时说明口径。）
</details>

**Q3. 四体低位交叉编址存储器，存取周期 100ns、总线传送周期 25ns。流水方式连续读取 4 个字需多久？带宽是单体存取的几倍？**

<details><summary>▶ 展开答案</summary>

$T + (m-1)r = 100 + 3 \times 25 = \textbf{175ns}$ 读 4 字；单体读 4 字 = 400ns → 约 **2.3 倍**（极限上界为 m=4 倍）。
</details>

**Q4. 判断：①Cache 对应用程序员和系统程序员都透明；②TLB 全部命中时一次取数最少只需 1 次访存。**

<details><summary>▶ 展开答案</summary>

① 正确——Cache 完全由硬件管理，对所有程序员透明。② 正确——TLB 命中免去页表访存，若 Cache 也命中则取数也在 Cache 完成，无主存访问；关键是**不访问页表**。
</details>

**Q5. 某磁盘有 4 个记录面、每面 1000 条磁道、每道 200 个扇区、每扇区 512B，转速 7200 r/min，平均寻道时间 9ms。求磁盘总容量与读取一个扇区的平均存取时间（不计控制器延迟）。**

<details><summary>▶ 展开答案</summary>

总容量 $= 4 \times 1000 \times 200 \times 512\text{B} = 4.096 \times 10^8\text{B} \approx \textbf{409.6MB}$（按 $1\text{MB}=10^6\text{B}$）。
转速 $7200\text{ r/min} = 120\text{ r/s}$ → 转一圈 $= \dfrac{1}{120}\text{s} = 8.33\text{ms}$，**平均旋转延迟 = 半圈 = 4.17ms**；传输一个扇区 $= \dfrac{8.33\text{ms}}{200} \approx 0.042\text{ms}$。
平均存取时间 $= 9 + 4.17 + 0.042 \approx \textbf{13.2ms}$（题目若给控制器延迟还需加上）。
</details>

- [ ] 条件码 CF/ZF/SF/OF 的含义与适用范围：**OF、SF 对无符号数无意义，CF 对带符号数无意义**；**CMP（行为同 SUB）、TEST（行为同 AND）只设置条件码、不更新目的寄存器**
- [ ] 选择与循环的机器级表示：if-else = CMP + 条件跳转 + JMP 跳过 else 分支；switch = **跳转表**（O(1) 找到入口）；while/for = 条件判断 + 循环体 + JMP 回跳
- [ ] x86-64 寄存器与 64/32/16/8 位对应（RAX/EAX/AX/AL）；RSP 栈指针、RBP 帧指针、RIP 指令指针（= PC）

### 4.2 易错点 · 高频陷阱

- 相对寻址的基准 PC：转移指令**取指完成后**的 PC 值（= 本指令地址 + 指令字长），不是本指令地址——计算偏移必错点。
- 立即寻址最快（A 就是操作数）；间接寻址最慢且需多次访存；寄存器寻址不用访存但要占指令中寄存器编号字段。
- 扩展操作码方案中**短码不能是长码的前缀**；还要检查"每种操作码组合是否够用、有无浪费"——考"是否能成为完整编码方案"。
- 变址寻址适合处理**数组/循环**（IX 自动 +1），基址适合**程序重定位/多道程序**（BR 由 OS 设置）——方向别反。
- RISC 一定采用流水线、指令定长、Load/Store 型——但"RISC 不支持访存指令"错误，是**只有 Load/Store 能访存**。
- 零地址指令在**堆栈计算机**或不需要操作数（如 NOP、停机）两种情形。
- 大端机器存 0x12345678：低地址放 0x12；x86 是小端、网络字节序是大端。
- 看汇编代码先看**格式**：AT&T 与 Intel **操作数顺序相反**（AT&T `mov %eax,(%ebx)` ＝ Intel `mov [ebx],eax`，都是"寄存器 → 内存"）。
- **CALL 入栈的是"下一条指令的地址"**（返回地址），不是本条指令地址；RET 弹出它并转移——`call` 与 `ret` 配对才有"调用—返回"语义。
- 条件转移指令**自身不做运算**：必须跟在 CMP/TEST（或算术指令）之后；`CMP`/`TEST` 只置条件码、**不改结果**，别指望它们改变寄存器。
- 栈帧偏移方向：**局部变量在 `[ebp]−n`（低地址侧）、入口参数在 `[ebp]+n`（高地址侧）**；`[ebp]` 处存的是调用者的 EBP、`[ebp]+4` 才是返回地址。
- **`leave` ＝ `movl %ebp,%esp` ＋ `popl %ebp`**（撤销栈帧并恢复调用者的帧指针），不是空操作。
- `MOV` 有五种操作数组合，但**不能内存 → 内存**、目的操作数不能是立即数；`LEA` 取的是**有效地址**（不访存），别当 MOV 用。
- **NOT（按位翻转）≠ NEG（算术取负）**；`XOR AX,AX` 快速清零、`TEST AX,AX` 判零（配 `JZ`）是固定搭配。
- 一条高级语言语句往往对应**多条**机器指令（for 循环 = 判断 + 条件跳转 + 循环体 + 自增 + JMP 回跳），不是一一对应。

### 4.3 自测问答

**Q1. 某机指令字长 16 位，采用扩展操作码：前 15 条三地址指令（各地址 4 位）。还能安排多少条二地址、一地址指令？给出一种方案。**

<details><summary>▶ 展开答案</summary>

4 位操作码留 1111 做扩展前缀 → 二地址指令可用 1111 + 4 位 = 16 种，同样留一个前缀 11111111 扩展一地址 → 方案：二地址 15 条（1111 0000~1110），一地址 16 条（1111 1111 + 4 位）。需检查"短码非长码前缀、数量够用"。
</details>

**Q2. 转移指令在内存 2000H 处，指令长 2B，目标地址 2010H，相对寻址。求偏移量 A。**

<details><summary>▶ 展开答案</summary>

取指后 PC = 2000H + 2 = 2002H；$A = 2010\text{H} - 2002\text{H} = \textbf{0EH}$（14，补码）。
</details>

**Q3. 判断：①变址寻址中变址寄存器内容由用户设定；②基址寻址有利于多道程序设计。**

<details><summary>▶ 展开答案</summary>

① 正确（IX 由用户程序修改，用于数组遍历）。② 正确（基址寄存器由 OS 管理、存放程序基地址，程序可在内存中浮动，正是多道程序需要的重定位手段）。
</details>

**Q4. 教材 4.6.3 的 caller 里，temp1、temp2、sum 分别放在 `[ebp]−12`、`[ebp]−8`、`[ebp]−4`，为什么偏移都是负数？返回地址和入口参数又在哪里？**

<details><summary>▶ 展开答案</summary>

栈由**高地址向低地址**增长，EBP 指向栈帧起始（栈底），**局部变量在 EBP 之下（低地址侧）**，所以用负偏移；`subl $24,%esp` 预留的 24B 就用于局部变量与即将入栈的实参。`[ebp]` 处是 `pushl %ebp` 压入的**调用者 EBP**，`[ebp]+4` 是 `call` 自动压入的**返回地址**，`[ebp]+8`、`[ebp]+12` 是**入口参数**——进入 `add` 后形参 x、y 正落在这里。
</details>

**Q5. 把 `movl $125, -12(%ebp)` 改写成 Intel 格式，并说明语义。**

<details><summary>▶ 展开答案</summary>

Intel 格式：`mov dword ptr [ebp-12], 125`；语义：M[R[ebp]−12] ← 125，即 temp1 = 125。注意 AT&T **源在前、目的在后**（Intel 相反），AT&T 的 `l` 后缀对应 Intel 的 `dword ptr`（`w`→`word ptr`、`b`→`byte ptr`）。
</details>

**Q6. 教材 4.6.4 的片段 `movl 8(%ebp),%eax` / `movl 12(%ebp),%edx` / `cmpl %edx,%eax` / `jbe .L1`：`cmpl` 比较的是谁减谁？`jbe` 的条件是什么？这里为什么用 `jbe` 而不是 `jle`？**

<details><summary>▶ 展开答案</summary>

AT&T 源在前、目的在后 → `cmpl %edx,%eax` 计算的是 **eax − edx**（即 p1 − p2，只置条件码）；`jbe`（jump if below or equal）按**无符号**比较，条件为 **eax ≤ edx（无符号）** 时跳到 `.L1`。这里比较的是两个**指针**（教材函数 `get_cont(int *p1, int *p2)`），地址是无符号数，故用无符号的 `jbe`；`jle` 用于**带符号**数比较。
</details>

**Q7. 写出 `while(i>0){ sum+=i; i--; }` 的汇编骨架，并说明它与 do-while 的关键区别。**

<details><summary>▶ 展开答案</summary>

骨架：`while_cond: CMP i,0` → `JLE while_end`（条件不成立就退出）→ `ADD sum,i` → `DEC i` → `JMP while_cond` → `while_end:`。**先判断后执行**，循环体可能一次都不执行；do-while 是**先执行后判断**，循环体至少执行一次（GCC 常把 while 翻成"先跳到条件判断 + do-while"的形式）。for 循环同理，只是把"自增"放在循环体之后、回跳之前。
</details>

**Q8. 为什么 switch 用跳转表（jump table）实现是 O(1)？有什么前提？**

<details><summary>▶ 展开答案</summary>

用 `x` 直接索引跳转表取出目标地址（`MOV AX, jmp_table[AX*4]` + `JMP AX`），**与 case 个数无关**，故为 O(1)（若用逐个比较则是 O(n)）。前提：case 值较**密集**（否则表稀疏、浪费空间），且必须先判断 `x` 是否超出表的范围，越界走 default（如 `CMP AX,3` + `JA default_case`）。
</details>

### 5.1 自查清单

- [ ] CPU 四大功能（指令控制/操作控制/时间控制/数据加工）；CPU = 运算器 + 控制器，能列出两部件的主要寄存器
- [ ] 用户可见寄存器（通用寄存器）vs 不可见（PC/IR/MAR/MDR/PSW 对汇编程序员**透明**）；PSW 的作用（OF SF ZF CF 标志位）
- [ ] 取指周期/间址周期/执行周期/中断周期的微操作序列（M(MAR)→MDR→IR、(PC)+1→PC 的位置）；**取指后 PC 自动 +1**
- [ ] 指令执行方案：单周期/多周期/流水线（各指令周期不等长）
- [ ] 数据通路：单总线结构（冲突多、慢）→ 多总线 → 专用通路；内部总线 vs 系统总线
- [ ] 硬布线控制器：微操作控制信号 = 译码输出 & 节拍 & 状态的组合逻辑；RISC 常用、速度快
- [ ] 微程序控制器：**一条机器指令 → 一段微程序 → 若干微指令**；控制存储器 CM（ROM）存微程序；CMAR/μIR/地址转移逻辑；水平型微指令（并行能力强、字长长）vs 垂直型（类似机器指令、需译码）
- [ ] 字段直接编码：互斥微命令分到同字段、**每字段留全 0 表示"无操作"**，$n$ 位字段最多表示 $2^n - 1$ 个微命令；字段间接编码
- [ ] 微指令后继微地址形成：增量计数器法（μPC+1）、断定方式（下址字段+转移条件）
- [ ] 五段流水线：**IF ID EX MEM WB**；时钟周期取决于最慢段
- [ ] 流水线性能计算：$n$ 条指令 $m$ 段流水总时间 $(m + n - 1)\Delta t$；实际吞吐率 $\dfrac{n}{(m+n-1)\Delta t}$、最大吞吐率 $\dfrac{1}{\Delta t}$；加速比 $\dfrac{nm}{m+n-1}$；效率
- [ ] 三类冒险与对策：**结构冒险**（部件冲突，如 IF 与 MEM 同时访存 → 停顿一拍/指令存储器与数据存储器分开）；**数据冒险**（RAW 写后读 → 转发/旁路，load-use 需加气泡 + 编译调度）；**控制冒险**（转移 → 分支预测（静态/动态 BHT）、延迟分支）
- [ ] 会算：含数据冒险/分支的指令序列各需几个周期（"转发后相邻指令无停顿；load-use 插 1 个气泡"）
- [ ] 高级流水线技术：超标量（多条流水线并发、**不改变时钟周期而是每周期发射多条**）、超流水（更细分段、更高主频）、超长指令字 VLIW、多发射与动态调度（乱序执行、按序完成）
- [ ] **异常和中断的基本概念**：异常（Exception）= CPU **内部**、与当前指令**同步**的意外事件；中断（Interrupt）= CPU **外部**（I/O 设备）、**异步**的请求；两者都使 CPU 暂停当前程序、保存现场后转入处理程序，处理完恢复现场返回原程序
- [ ] 异常和中断的**分类**：异常分**故障（fault）**（指令执行前/中检出，纠正后**重执行**当前指令：缺页、除零、非法指令）、**自陷（trap）**（有意触发，处理后**执行下一条**：系统调用、断点）、**终止（abort）**（不可恢复，终止进程：硬件故障、校验错误）；中断分**可屏蔽中断（INTR）**（可由关中断屏蔽，I/O 设备请求）与**不可屏蔽中断（NMI）**（必须立即响应，电源故障、内存校验错）
- [ ] 异常和中断的**检测与响应**：检测时机——异常在**指令执行过程中**由硬件检出（译码/执行/访存阶段），中断在**一条指令执行结束后**的中断检查点检测；**中断隐指令**（硬件自动完成、**不是指令系统中的指令**）做三件事：**关中断、保存断点（PC/PSW 压栈）、引出中断服务程序入口**；随后由服务程序（软件）保护现场 → 设备服务 → 恢复现场 → 开中断 → 返回
- [ ] 中断向量与向量地址：由**中断类型号**查**中断向量表**得到服务程序的**入口地址**（及 PSW）；"向量地址"是表项的地址、"入口地址"才是跳转目标，两者别混；**中断屏蔽字与多重中断**的细节见第7章 7.1 / 7.2
- [ ] 【22增】**多处理器基本概念 · Flynn 分类与向量处理器**：按**指令流 / 数据流**分为 **SISD**（单指令单数据，传统单核冯·诺依曼机）、**SIMD**（单指令多数据：向量处理器、GPU、SSE/AVX，一条指令同时处理多个数据）、**MISD**（理论模型，实际极少）、**MIMD**（多指令多数据：多核、多处理器、集群）；**SPMD（单程序多数据）是 MIMD 的编程模型**，不属于 Flynn 的四种结构；**向量处理器**是 SIMD 的典型实现（Cray-1、现代 GPU），一条向量指令对整组数据运算
- [ ] 【22增】**硬件多线程**：一个物理核维护**多套线程上下文**（寄存器组、PC），用线程切换隐藏访存延迟——**细粒度**（每个时钟周期轮转切换，切换代价最小、隐藏延迟最好，但单线程性能下降）、**粗粒度**（只在**长延迟事件**如 Cache 缺失时才切换，切换代价大）、**同时多线程 SMT**（同一时钟周期内发射多个线程的指令，如 Intel 超线程，要求发射槽有余量、硬件成本最高）
- [ ] 【22增】**多核处理器（multi-core）**：一个芯片上集成多个**独立核心**，**共享最后一级 Cache（L3）、内存控制器与 I/O，各核独立拥有 L1/L2、寄存器组、PC、ALU**；优点是功耗效率高（多个低频核优于一个高频核）；核间通过共享 Cache / 总线通信与同步，编程需处理缓存一致性
- [ ] 【22增】**共享内存多处理器 SMP**：多个**同构**处理器经**总线或交叉开关**共享同一物理主存，由 OS 统一调度（MIMD 的具体实现）；按访存时间分 **UMA**（统一存储访问，访存时间与处理器、被访问的字无关）与 **NUMA**（非统一存储访问，访存时间与之相关）；组织方式分**主/从**（内核固定在主处理器，主失效 → 系统失效）与**对称**（内核可在任意处理器上运行，需复杂同步）
- [ ] 【22增】**Cache 一致性问题与协议（概念级）**：各核 L1 中同一主存块的副本必须保持一致——**监听（snooping）协议**：各 Cache 在总线上"偷听"写操作并作废/更新自身副本（如 MESI 四态，适合总线型 SMP）；**目录（directory）协议**：用目录记录每个块的副本位置，只向持有者发无效化消息（可扩展性好，适合大规模 NUMA）；同步靠**原子指令**（Test-and-Set、LL/SC）+ 锁 + 屏障

### 5.2 易错点 · 高频陷阱

- PC、IR、MAR、MDR、PSW 都是**用户不可见**寄存器；通用寄存器可见——判断"汇编程序员能否访问"就用这条。
- 微程序控制器里**每条机器指令对应一段微程序**；取指周期的微程序是公用的。
- 水平型微指令一条可定义多个并行微命令（指令字长但快）；垂直型一条只控制一个基本操作——两者性能对比方向别背反。
- 字段直接编码的 $2^n - 1$：全 0 已被"无操作"占用——数微命令数时记得减。
- load-use 冒险**即使有转发也不能完全消除**（生产者 WB 在消费者 EX 之后），必须停 1 拍——高频考点。
- 超标量 ≠ 超流水：前者横向多发射、后者纵向细分段提高频率。
- 中断周期在"执行周期之后"响应（一条指令执行完），断点入栈/存指定单元。
- 转移指令在流水线中：分支预测错误要**清除已取的后续指令**（冲刷流水线），代价 = 惩罚周期。
- 异常是**同步**的（与当前指令相关、CPU 内部），中断是**异步**的（与当前指令无关、CPU 外部）——判断某事件属于哪一类就看这两条：除零、缺页是异常，键盘请求、磁盘传送完成是中断。
- 自陷（trap）是**有意**触发的（系统调用指令），处理完**执行下一条**；故障（fault）是**无意**发生的（缺页），处理完**重执行当前指令**——"缺页重执行、系统调用下一条"是经典对比。
- 中断隐指令由**硬件**完成关中断、保存断点、引出入口三件事，**不属于指令系统**；保存通用寄存器（保护现场）由**服务程序（软件）**完成。
- 【22增】Flynn 分类的判据是**指令流与数据流**，不是"处理器个数"：SIMD 的典型代表是**向量处理器 / GPU**，多核 CPU 属于 **MIMD**；SPMD 是 MIMD 的**编程模型**，别当成第五种结构。
- 【22增】多线程切换代价别弄反：**细粒度**切换最频繁（每周期轮转）、单线程性能损失最大，但隐藏延迟最好；**粗粒度**只在长延迟事件（Cache 缺失）时切换、切换开销大；**SMT** 是在**同一时钟周期内**发射多个线程的指令（超线程），不是简单的时间轮转。
- 【22增】UMA / NUMA 是**按访存时间**对共享内存多处理器的划分（与"处理器个数"无关）；**Cache 一致性**（同一数据的多个副本如何保持一致）与**内存一致性**（多核看到的访存顺序）是两个不同问题，别混。

### 5.3 自测问答

**Q1. 某流水线 5 段、每段 1ns。执行 20 条指令的总时间、加速比、实际吞吐率。**

<details><summary>▶ 展开答案</summary>

总时间 $= (5+20-1) \times 1 = \textbf{24ns}$；串行 = $20 \times 5 = 100\text{ns}$ → 加速比 $= \dfrac{100}{24} \approx \textbf{4.17}$；吞吐率 $= \dfrac{20}{24\text{ns}} \approx \textbf{0.83}$ 条/ns（极限 1 条/ns）。
</details>

**Q2. 序列 `I1: lw R1, 0(R2)`；`I2: add R3, R1, R4`；`I3: sub R5, R3, R6`。五段流水线（EX 前可转发）需要几个周期（含气泡）？**

<details><summary>▶ 展开答案</summary>

I1 与 I2 是 **load-use**：转发也不够（数据 EX 后才产生），I2 需停 1 拍；I2→I3 是 ALU→ALU 相关，靠**转发**解决无停顿。共需 $5 + (4-1) + 1 = \textbf{8}$ 个周期（含 1 个气泡）。
</details>

**Q3. 某字段直接编码：字段 A 3 位、字段 B 4 位、字段 C 5 位，每字段留全 0 表示无操作。这些字段最多能表示多少个互斥微命令？**

<details><summary>▶ 展开答案</summary>

$(2^3-1) + (2^4-1) + (2^5-1) = 7 + 15 + 31 = \textbf{53}$ 个。
</details>

**Q4. 判断并说明理由：①SIMD 的典型代表是多核 CPU；②细粒度多线程的线程切换开销最大；③SMP 中各处理器共享同一物理主存，因此不存在缓存一致性问题。**

<details><summary>▶ 展开答案</summary>

① 错误——SIMD（单指令多数据）的典型代表是**向量处理器与 GPU**（一条指令同时处理多个数据）；多核 CPU 属于 **MIMD**（多指令多数据）。
② 错误——**细粒度**多线程每个时钟周期就轮转切换，**切换开销最小**，代价是单线程性能被拉低；**粗粒度**只在 Cache 缺失等长延迟事件时才切换，保存/恢复上下文的开销**较大**。
③ 错误——每个核都有自己的 L1/L2 副本，同一主存块可能同时存在于多个 Cache 中；某核写入后其他核的副本就过时了，必须用**监听协议**（总线广播无效化，如 MESI）或**目录协议**（按目录记录副本位置、定向发无效化消息）维护**缓存一致性**。
</details>

## 第6章 总线系统

### 6.1 自查清单

- [ ] 总线的概念与分类：片内/系统总线（数据、地址、控制）/通信总线；**数据总线双向、地址总线单向（CPU→外）**
- [ ] 总线性能：总线宽度（位数）、**总线带宽 = 工作频率 × 每次传送的字节数**——会算（如 32 位、100MHz、每周期传 1 次 → 400MB/s；DDR 双沿 ×2）
- [ ] 总线仲裁：**集中式三种**——链式查询（BG 串行，离控制器近优先级高、对故障敏感、线少）、计数器定时查询（设备地址计数、优先级可改）、独立请求（每设备独立 BR/BG，并行响应快、灵活可编程、线最多）；分布式仲裁（自举式，竞争时仲裁号）
- [ ] 总线定时（传输方式）：**同步通信**（统一时钟、速度快、须迁就最慢设备/强制同步）、**异步通信**（应答：不互锁/半互锁/全互锁，慢但可靠灵活）、半同步通信（加 WAIT 应答）、分离式通信（总线周期拆分，总线利用率最高）
- [ ] 一次数据传输的四个阶段：申请分配→寻址→传输→结束
- [ ] 常见总线标准：ISA/EISA/PCI/PCIe/USB/AGP 的大致定位（PCI 并行、PCIe 串行点对点、USB 通用串行、支持热插拔）

### 6.2 易错点 · 高频陷阱

- 链式查询的优先级**固定**（物理位置决定）；计数器查询可循环改变；独立请求可用编程改变——"优先级灵活"对应独立请求。
- 地址线是单向的，**数据线是双向的**；总线带宽计算时数据线位数决定每周期字节数。
- 带宽公式 $\text{带宽} = \text{工作频率} \times \dfrac{\text{宽度}}{8}$ 里若每周期传两次（DDR）要 ×2；给出时钟与传送周期不同的（如每 4 个时钟传 1 次）要按传送周期算。
- 异步全互锁最可靠但最慢；不互锁速度快可靠性差——排序题：不互锁 < 半互锁 < 全互锁（速度依次变慢）。
- 分离式通信把从设备准备数据的时间让出总线给其他主设备用——它提高的是**总线利用率**而非单次传输速度。

### 6.3 自测问答

**Q1. 同步总线：时钟 200MHz，每个时钟周期传送 64 位数据。总线带宽是多少？若改为每 2 个时钟周期传送一次呢？**

<details><summary>▶ 展开答案</summary>

每周期 $64\text{bit} = 8\text{B}$，$8\text{B} \times 200\text{MHz} = \textbf{1.6GB/s}$；若 2 周期传一次：**800MB/s**。
</details>

**Q2. 判断：①链式查询方式对电路故障很敏感；②独立请求方式所需控制线最少。**

<details><summary>▶ 展开答案</summary>

① 正确——BG 链上任一接口故障会阻断后面所有设备。
② 错误——独立请求需要每设备一对 BRi/BGi，**控制线最多**；链式查询仅 BR、BG、BS 三根，线最少。
</details>

## 第7章 输入输出系统

### 7.1 自查清单

- [ ] I/O 接口的功能与基本结构（数据缓冲寄存器 DBR、状态/控制寄存器、端口地址译码）；接口 vs 端口 vs 设备的关系
- [ ] I/O 端口编址：统一编址（占内存空间、可用访存指令但译码慢）vs 独立编址（专用 I/O 指令、地址空间独立、需控制线区分）
- [ ] 程序查询方式：CPU 轮询忙等、**CPU 与设备完全串行**、接口简单；会算查询方式 CPU 利用率
- [ ] 中断方式（重点）：中断请求→**中断判优**→响应条件（CPU 允许中断、有请求、一条指令执行完）→中断隐指令（关中断、保存断点、引出入口）→服务程序（保护现场→设备服务→恢复现场→开中断→返回）
- [ ] 单重中断 vs 多重中断（服务中开中断才可实现嵌套）；中断判优：硬件排队器/软件查询
- [ ] **响应优先级（硬件排队，不可变）vs 处理优先级（屏蔽字，可变）**；会按处理优先级设计屏蔽字（1=屏蔽，自身恒 1）
- [ ] 中断向量：向量地址 vs 中断服务程序入口地址；向量中断（中断向量表/中断类型号）的思想
- [ ] DMA 方式（重点）：数据块为单位、**主存与设备直接通路、不经过 CPU**、CPU 仅在预处理/后处理介入；DMA 控制器组成（主存地址计数器、传送长度计数器、数据缓冲、中断逻辑、控制/状态逻辑）
- [ ] DMA 传送方法：**周期挪用（周期窃取）**、停止 CPU 访存、交替访存——各自对 CPU 的影响对比
- [ ] DMA 与程序中断的对比（数据通路、响应时机：**DMA 在存取周期结束、中断在指令周期结束**；优先级：DMA 高于中断——不丢失数据；CPU 开销；适用对象）
- [ ] DMA 的三个阶段：预处理（初始化 MAR/字计数器/启动）→ 数据传送（硬件完成）→ 后处理（校验、以中断方式报告 CPU）
- [ ] 通道方式（概念级）：通道程序、字节多路/数组选择/数组多路通道的适用对象

### 7.2 易错点 · 高频陷阱

- 中断隐指令**由硬件自动执行，不是指令系统里的指令**；它做三件事：关中断、保存断点、引出服务程序入口。保存通用寄存器（现场）由**服务程序（软件）**完成。
- 屏蔽字设计：处理优先级高的中断要屏蔽**所有低于等于自己**的；最高优先级的屏蔽字全 1——给出新优先级重新设计屏蔽字是高频计算题。
- "CPU 响应中断一定在一条指令执行结束时"对程序中断成立；**DMA 请求可在存取周期结束时响应**（不必等指令结束）——两者响应时机的区别是经典考点。
- DMA 数据**不经过 CPU**（不经 CPU 寄存器），中断方式数据经过 CPU（累加器/寄存器中转）。
- 周期挪用时若 CPU 与 DMA 同时要访存，**DMA 优先**（不挪用会丢数据）。
- 统一编址下"访问 I/O 的指令"就是普通访存指令，无专用 I/O 指令；独立编址必须专用指令、且需指明是 I/O 访问。
- 程序查询方式的 CPU 效率最低但硬件最少；中断方式提高了 CPU 利用率但仍按字传送（适合低速设备）；DMA 适合高速块设备。

### 7.3 自测问答

**Q1. 设备 B、C、D 处理优先级要求为 C > B > D，响应优先级为 D > C > B。写出 B、C、D 的屏蔽字（顺序 B C D，1=屏蔽）。**

<details><summary>▶ 展开答案</summary>

屏蔽所有"处理优先级 ≤ 自身"的：
B：屏蔽 B、D，开放 C → **1 0 1**；C：全 1 → **1 1 1**；D：全 1 → **1 1 1**。
（最高处理优先级 C 的屏蔽字必全 1；D 只比自身高，也全 1。）
</details>

**Q2. 判断：①DMA 方式中 CPU 完全不参与数据传送；②中断方式下数据传送经过 CPU。**

<details><summary>▶ 展开答案</summary>

① 正确（传送阶段完全由 DMA 控制器硬件完成；CPU 只做预处理和后处理）。
② 正确（中断方式每字都要 CPU 执行服务程序从接口取走/写入——数据流经 CPU）。
</details>

**Q3. 比较程序查询、程序中断、DMA 三种 I/O 方式的 CPU 介入程度与适用设备类型。**

<details><summary>▶ 展开答案</summary>

程序查询：CPU 全程忙等，与设备串行，适合速度慢、任务简单的场合（CPU 利用率最低）；程序中断：CPU 仅在每字传输完成时短暂介入（执行服务程序），CPU 与设备并行、适合中低速设备；DMA：以数据块为单位，CPU 仅在块前后介入，主存与设备直传，适合磁盘等高速块设备，CPU 开销最小。
</details>
