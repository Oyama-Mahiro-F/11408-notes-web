# 搜索功能设计文档

**日期：** 2026-07-23  
**状态：** 已确认  
**范围：** 在考研笔记静态站点中新增全站搜索功能

---

## 1. 概述

在现有的静态 HTML 考研笔记网站（GitHub Pages 部署）中添加客户端搜索功能。支持搜索页面标题和正文内容，bigram 中文分词，分科索引按需加载。

## 2. 架构

```
push.py 流程（构建时）
  └─ add_nav.py
       ├─ 现有：导航栏/侧边栏/目录生成
       └─ 新增：build_search_index()
            ├─ 扫描 site/ 下所有 .html
            ├─ 提取纯文本（去标签、脚本、样式）
            ├─ bigram 切分 → 倒排索引
            └─ 输出 site/search/{408,数学,英语,政治}.json

运行时（客户端）
  ├─ search.js（全局引入，每个页面加载）
  │    ├─ 导航栏搜索图标/框 → 下拉面板
  │    ├─ 首页大搜索框 → 下拉面板
  │    ├─ 按需 fetch 索引（sessionStorage 缓存）
  │    ├─ bigram 匹配 + 排名
  │    └─ "查看全部" → 跳转 search-results.html?q=xxx
  └─ search-results.html（独立搜索结果页）
       └─ 完整结果列表，带摘要和高亮
```

## 3. 搜索入口

### 3.1 导航栏搜索（所有页面）

- 位置：顶部 nav-header 右侧，现有标签（首页/408/数学/英语/政治）之后
- 默认显示 🔍 搜索图标
- 点击图标或按 `Ctrl+K` → 展开为搜索输入框（宽度过渡动画），自动聚焦
- 输入时实时弹出下拉面板（300ms debounce）
- 点击外部或按 `Esc` 关闭面板并收起输入框
- 搜索范围：全站（所有科目）

### 3.2 首页搜索框（index.html）

- 位置：倒计时和科目卡片之间
- 较大的搜索框，placeholder："搜索笔记关键词..."
- 同样弹出下拉面板
- 搜索范围：全站

### 3.3 下拉面板

- 默认显示前 6 条结果
- 每条结果：标题（可点击跳转）、面包屑路径、正文摘要片段（关键词高亮）
- 超过 6 条时底部显示 "查看全部 N 条结果 →"，跳转 search-results.html
- 无结果时显示 "未找到匹配的笔记"
- 最大高度约 400px，超出滚动

### 3.4 搜索结果页（search-results.html）

- 顶部保留导航栏
- 搜索框可继续输入搜索
- 显示结果总数
- 每条结果：标题（可点击跳转）、面包屑路径、正文摘要（关键词高亮）、科目标签
- 结果之间分隔线

## 4. 索引结构

### 4.1 文件位置

`site/search/{subject}.json`，每个科目一个索引文件。

### 4.2 JSON 格式

```json
{
  "pages": [
    {
      "id": 0,
      "title": "进程同步与互斥",
      "path": "408/操作系统/进程同步与互斥.html",
      "text": "进程同步是指协调多个进程在访问共享资源时...",
      "subject": "408"
    }
  ],
  "index": {
    "进程": [0, 3, 7],
    "同步": [0, 5],
    "互斥": [0, 4]
  }
}
```

- `pages[i].text`：正文前 500 字符摘要，用于搜索匹配和结果展示
- `index`：bigram → page id 数组的倒排索引
- 每个 .html 文件对应一个 page entry

### 4.3 Bigram 切分规则

- 中文：连续两个字符组成一个 bigram（如 "操作系统" → `["操作", "系统"]`）
- 英文/数字：按词边界切分（空格、标点分隔），保留原词
- 构建索引时对文本做 bigram 切分并去重
- 搜索时对 query 同样做 bigram 切分

## 5. 搜索 & 匹配逻辑

### 5.1 匹配流程

1. 用户输入 query
2. 对 query 做 bigram 切分
3. 对每个 bigram 查倒排索引，取对应的 page id 集合
4. 取交集（AND 语义）：所有 bigram 都必须命中
5. 如果交集为空，降级为取并集（OR 语义），按命中 bigram 数量排名

### 5.2 排名规则

- 标题匹配：每命中一个 bigram +3 分
- 正文匹配：每命中一个 bigram +1 分
- 按总分降序排列

### 5.3 特殊字符处理

- 搜索前对 regex 特殊字符（`+?*.[](){}^$|\`）进行转义
- 输入为空/纯空格时不执行搜索

## 6. 索引加载策略

- 首页（index.html）：页面加载时预加载全部 4 个科目索引
- 子页面：按需加载（用户首次打开搜索时 fetch，搜索期间显示 loading 状态）
- 所有索引加载后缓存到 `sessionStorage`，同 session 不重复请求
- 索引加载失败时：搜索框置灰，placeholder 改为 "搜索不可用"

## 7. UI 样式

- 复用现有 CSS 变量：`--accent: #3f51b5`，`--accent-light: #e8eaf6`
- 下拉面板：白色背景、圆角、阴影，与现有卡片风格统一
- 关键词高亮：使用 `<mark>` 标签，背景色 `var(--accent-light)`
- 移动端：下拉面板宽度不超过 90vw

## 8. 构建集成

在 `add_nav.py` 中新增函数 `build_search_index(site_dir)`，在现有导航生成流程之后调用。`push.py` 自动继承此步骤，无需额外配置。

## 9. 文件清单

| 文件 | 说明 | 操作 |
|------|------|------|
| `add_nav.py` | 新增 `build_search_index()` 函数 | 修改 |
| `site/search.js` | 搜索核心逻辑 + UI 交互 | 新建 |
| `site/search-results.html` | 搜索结果页 | 新建 |
| `site/search/*.json` | 分科搜索索引 | 构建时生成 |
| `site/index.html` | 首页：添加搜索框 HTML + 引入 search.js | 修改（构建时注入） |
| `push.py` | 可能需要 minor 调整 | 视情况修改 |

## 10. 边界情况

| 场景 | 处理 |
|------|------|
| 索引 fetch 失败 | 搜索框置灰，placeholder 改为 "搜索不可用" |
| 输入为空/纯空格 | 不显示下拉面板 |
| 输入 1 个字 | 正常搜索，结果按分数排序 |
| 无匹配结果 | 下拉显示 "未找到匹配的笔记" |
| 特殊字符 | 搜索前转义，当作普通字符 |
| 构建时 HTML 解析失败 | 跳过该文件，打印 warning |
| 科目目录不存在 | 跳过该科目索引生成 |
